## P-001：changelog 需要实时时间戳（2026.06.09 18:52）

**需求**：每次更新 `public/changelog-9.txt` 时，`Date:` 行必须是实际时间，精确到分钟（HH:mm）。

**实现方式**：
- 更新 changelog 前，执行 `Get-Date -Format "yyyy.MM.dd HH:mm"` 获取当前时间
- 写入格式：`Date: 2026.06.09 18:47`

**已确认**：此规则适用于所有后续 changelog 更新。

## P-002：changelog 最新记录必须在文件开头（2026.06.09）

**需求**：最新的版本记录写在 changelog 文件的最前面，旧记录依次后移。

**原因**：方便打开文件时直接看到最新变更。

**已确认**：此规则适用于所有后续 changelog 更新。

**已确认**。

## P-004：重构策略 —— 分层递进（2026.06.09）

**需求**：
1. 先清空所有不符合规范的代码
2. 在文件中注释声明要实现什么、规范化要求
3. 搭建主体框架（最内层基础 → 向外层）
4. 每层验证通过后再下一层
5. 优先实现可拓展的主体框架，防止"项目长歪"

**已确认**。

---

## P-005：严格遵守规范，禁止逾越（2026.06.09）

**需求**：完全严格按照项目规范（mod-specification.md / code-rules.md / AGENTS.md）来，禁止有任何代码超出规则限制。

**含义**：
- 不修改 core/foundation 层的现有设计
- 不跨 MOD 访问内部文件
- 不擅自添加用户未要求的功能
- 不确定时先问用户

**例外（P-005-EX1，2026.06.09）**：
当技能规范（mod-specification.md）与 core/foundation 层的实际代码不一致时，以技能规范为准修正代码。
这种情况仅限"代码实现偏离了规范"的场景，不包括"规范之外的自主修改"。

**已确认**。
