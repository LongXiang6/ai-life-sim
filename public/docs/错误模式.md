## E-001：ESLint unused 变量时走极端（2026.06.09 18:47）

**触发条件**：ESLint 报告 `'SYSTEM_PROMPT' is defined but never used`

**AI 的错误操作**：
1. 第一步：将 `SYSTEM_PROMPT` 改名为 `_SYSTEM_PROMPT`（用下划线前缀静默警告）→ 错了
2. 第二步：改回 `SYSTEM_PROMPT` 并从 `index.ts` 中 `export { SYSTEM_PROMPT }` 导出 → 正确

**根因**：AI 第一反应的"改前缀"是一种偷懒行为——前提假设该常量确实只是注释/文档用途不需要导出。但实际上 `SYSTEM_PROMPT` 是需要导出供调用方传递给 `callAI(systemPrompt, ...)` 的。

**正确流程**：
1. 遇到 unused 警告时，先检查该变量是否应该被外部使用
2. 如果是 → 从 index.ts 导出（消除警告的同时完成正确架构）
3. 如果否 → 确认是注释/文档后，再用 `_` 前缀或删除
4. **不要默认走"静默"路径**

**状态**：已修复，记录防止复发。

## E-002：TS 类型 Import 删除后导致编译失败（2026.06.09 18:47）

**触发条件**：ESLint 报告 `'SimulationStatus' is imported but never used`（在 orchestrator-system.ts）

**AI 的操作**：
1. 直接删除 `SimulationStatus` 从 import 中 → 发现 tsc 通过
2. 但同时也删了 `RoundResult` → tsc 报错（RoundResult 被 `step()` 和 `handleNarrativeResponse` 使用）
3. 重新加回 `RoundResult`

**根因**：批量修改 import 时没有二次确认每个类型是否真的在两个文件版本中都不被使用。

**正确流程**：删除 import 前，对该行做一次 grep 确认该标识符在整个文件中没有其他引用。

**状态**：已修复，记录防止复发。
