# AI 人生模拟器测试

## 目标

解决或准确诊断用户报告的行为，并以真实运行路径、状态契约和可复现证据支持所要求的完成结果。

## 适用范围

- 用户报告的问题、复现、聚焦回归、浏览器路径和交付验证。
- 读取问题所属的活动权威章节和实时源；修改或交付应用文件时追加 [开发检查](../ai-life-sim/references/development-checks.md)。
- 仅在用户明确报告问题、要求诊断，或所属流程已列明验证步骤时执行测试；无关基线失败单独报告。

## 执行契约

### 根因修复流程

| 阶段 | 必须动作 | 结束条件 |
|---|---|---|
| `prepare` | 固定并复现原始路径，记录预期与实际结果、关联标识、时间线、首个可观察异常和已有基线；把报错、超时、卡住或错误终态视为症状，不预设为根因。 | 症状可稳定定位到具体执行实例、节点、所有者和状态。 |
| `ready` | 从异常节点列出输入、依赖、等待边、状态写入、资源、重试和调用方，建立“症状 -> 直接失效机制 -> 失效前置条件 -> 前置条件为何失效 -> 现有校验为何未阻止或发现”的候选因果链，并为候选项声明可区分的证据。 | 证据计划足以区分主要候选原因，不靠猜测选修复点。 |
| `execute` | 沿调用、依赖和状态来源反向追到最早出现的无效状态或错误设计，继续检查它的创建、配置、注册、顺序、输入校验、生命周期、持久化、资源与失败反馈，直到找到有证据、归属明确且能解释完整故障链的根因。 | 根因能够解释症状如何形成、为何此前未被阻止，以及哪些同源路径可能受影响。 |
| `transition` | 在根因所有者处同时修复直接缺陷、缺陷形成机制和防复发机制。实现遗漏应把不变式变成 Schema、注册/启动校验、原子提交、测试、门禁或可观测指标；设计缺陷应修正所有权、边界、依赖、数据契约或执行图，并删除被取代路径。 | 最早无效状态已不可进入，或能在业务执行前以明确状态失败并反馈给正确所有者。 |
| `finalize` | 重跑原始路径、同根调用点、故障注入和范围匹配门禁，确认没有延长等待、额外重试、吞错、降级、备用实现或页面遮罩掩盖故障，并移除临时诊断。 | 因果链已在根因处断开，公开结果、状态、诊断和持久化一致。 |

- 根因不是“最先看到的问题”，而是当前证据能支持的最早可修复原因。只要仍存在尚未检查的“为什么这个前置条件会失败”或“为什么系统允许它进入运行态”，就不能宣告根因闭环。
- 遇到超时时，量化时间消耗并确认节点实际状态，至少区分未启动、依赖未收敛、死锁或等待环、队列/资源耗尽、外部服务变慢、无界输入或循环、计算退化、终态缺失、通道关闭和时限契约错误。不得仅增加等待时间、重试次数或超时阈值；只有证据证明正常合法工作量超过已声明预算且不存在上游异常时，才调整时限并同步更新预算、指标和回归。
- 证据不足以确定根因时，返回已确认的故障链、尚未区分的候选原因和取得决定性证据所需的最小观测；不得猜测成功、以症状补丁代替根因修复或声称问题已解决。

- 涉及系统运行图或 MOD 生命周期时，回归必须确认统一五阶段 `prepare -> ready -> execute -> transition -> finalize`、唯一 owner、显式依赖、状态码和故障反馈链，不能只验证局部返回值。
- 处理实体引用目录缺失、同回合依赖未登记或结算语义冲突时，恢复、生成、提交三个入口共用同一前置检查；同包创建操作必须先于关系、目标、行为和记忆引用。
- 生产部署验证只读取 [生产部署](../ai-life-sim/references/production-deployment.md) 返回的构建与 PM2 重启终态，不追加未授权的专项操作。
- 标识、文件、格式、写法和排序按 [项目标准化契约](../ai-life-sim/references/standardization.md) 执行。

## 权威与实时源

- 实体目录、上下文、存档恢复和回合提交：读取问题所属的系统树、核心模拟和逻辑树目标章节。
- 执行流门禁：`src/core/execution/execution-flow-registry.ts`、`npm run check:execution`。
- 根因链与观测证据契约：`scripts/check/rules/execution-system-review.json`、`scripts/check/fixtures/execution-incidents.json`、`npm run check:execution`。
- 事故样本：`scripts/check/fixtures/execution-incidents.json`。
- 复盘与废弃机制：`scripts/check/rules/execution-system-review.json`。
- 诊断与指标：开发诊断 JSONL、数据查看器和所属 owning system 的公开结果。

## 边界

- 不宣称超出已有证据的结果，不把局部测试通过描述为完整链路通过。
- 不用页面、聚合器或测试夹具拥有业务状态；测试只通过公开契约观察结果。
- 不以静默跳过、猜测成功、广播求援、备用实现或兼容路径掩盖失败；真实终止性故障必须返回唯一失败终态。
- 生产、账号、凭据和部署操作遵循对应 reference，不在测试 Skill 复制操作细节。

## 验收

- 先运行与问题直接相关的聚焦回归，再按风险运行 `npm run check:execution`、`npm run check:structural`、`npm run check:mod` 或浏览器路径。
- 任何项目文件交付前运行 `npm run check:standardization`；跨领域、持久化或发布前交付追加 `npm run gate-check`。
- 结果必须记录状态、失败类别、关联标识和未验证边界；真实事故至少交付一条回归样本、契约断言或可观测指标，并补齐根因链与观测证据；涉及执行流时由 `npm run check:execution` 校验根因契约，超时类修复禁止只调整等待时间、超时阈值或重试次数。
