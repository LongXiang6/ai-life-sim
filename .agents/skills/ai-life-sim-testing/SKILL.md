# AI 人生模拟器测试

## 目标

[核心原则] 用真实运行路径、状态契约和可复现证据证明用户要求的行为结果。

## 适用范围

[核心原则] 问题复现、根因诊断、聚焦回归、浏览器路径和交付验证由本 Skill 负责。

[次要规则] 问题所属活动权威、实时源和 [开发检查](../ai-life-sim/references/development-checks.md) 提供验证范围。

## 执行契约

[核心原则] 固定原始路径、预期结果、实际结果、执行标识、时间线和首个可观察异常。

[核心原则] 从异常节点反向追踪输入、依赖、状态写入、资源、调用方和已有校验。

[核心原则] 用可区分证据定位最早出现的无效状态或错误设计。

[核心原则] 在根因所有者处修复直接缺陷、形成机制和同源路径。

[核心原则] 复跑原始路径、同根调用点、故障路径和范围匹配门禁。

[核心原则] 公开结果、运行状态、诊断记录和持久化结果保持一致。

[核心原则] 核心模拟先验证必须功能：故事 AI 必须返回可用正文且不得提前结局；连续性提取必须返回准确时间、事件和权重。分支判定、应结局而漏结局、未来事件、天赋成长与状态分析按当前用户要求作为非硬验收，不以边缘命中率阻塞基础功能交付。

[核心原则] 记忆压缩失败路径必须验证正文已经提交、失败来源回合被保留，并在最近详细故事窗口内获得至少两次后续重试机会；不把一次压缩失败扩大为整轮失败。

[绝对红线] 解析器回归必须优先证明最大兼容、智能识别、乱序识别、智能补全和逐项降级：单条坏消息、坏字段、坏数组项或坏未来事件不得抛弃同一响应中的其他可用结果。除非最低可用产品完全不存在，不得以严格 Schema 或整包判定阻断真实调用。

[次要规则] 局部稳定问题采用复现、定位、修复、聚焦回归的紧凑路径。

[次要规则] 跨系统、异步、持久化、生产、重复或难观测问题采用完整根因链。

[次要规则] 超时诊断区分启动、依赖、等待环、资源、外部服务、输入规模、计算、终态和时限契约。

[次要规则] 执行流回归覆盖阶段、所有者、依赖、状态码、独立发布边界和故障反馈链。

## 权威与实时源

[核心原则] 实体目录、上下文、存档恢复和回合提交读取所属系统树、核心模拟和机制权威。

[核心原则] 执行流读取 `src/core/execution/execution-flow-registry.ts` 与 `npm run check:execution`。

[次要规则] 根因链与观测证据读取 `scripts/check/rules/execution-system-review.json`。

[次要规则] 事故样本读取 `scripts/check/fixtures/execution-incidents.json`。

## 边界

[核心原则] 测试通过公开契约观察业务结果，业务状态保留在所属系统。

[核心原则] 结论范围与现有证据范围一致。

[次要规则] 生产、账号、凭据和部署操作使用对应 reference 的既定入口。

[辅助说明] 证据仍有分叉时，记录已确认链路、候选原因和取得决定性证据的最小观测。

## 验收

[核心原则] 先运行直接相关聚焦回归，再按风险运行结构、执行、MOD、UI 或浏览器检查。

[次要规则] 项目文件交付运行 `npm run check:standardization`。

[次要规则] 跨领域、持久化或发布前交付按本次执行范围运行 `npm run gate-check`。

[辅助说明] 结果记录状态、失败类别、验证证据和剩余边界。
