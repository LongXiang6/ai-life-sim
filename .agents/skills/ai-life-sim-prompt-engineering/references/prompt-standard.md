# Prompt 标准

<!-- RULE id="prompt-standard.user-hard" source="USER-HARD" owner="prompt" status="active" -->
Prompt 只负责让模型生成用户要的内容，并提供合理、充分的生成职责与返回协议。先保证人生重开模拟器的核心产物成立，不以规则最短或最少为目标，也不为精简删掉完成生成所需的方法。目标清晰，路径开放；禁止把过渡性设计、过渡性防御设计或假设问题的限制写成 Prompt 目标。
<!-- END RULE id="prompt-standard.user-hard" -->

## 职责结构

固定 Prompt 按调用协议使用可读、自足的消息结构；需要机器解析的动态输入与输出使用 JSON。只设置实际有职责的区块，通常为：

- `身份`：模型的首要职责、裁决权限与最终产物；主叙事先演化世界并裁决事件，最后编译人生记录。
- `目标`：用户要得到的结果。
- `输入职责`：各类输入提供什么事实、条件或意图。
- `内部编排`：形成并组织本轮新变化所需的方法。
- `叙事`：必要的人称、主体或视角。
- `推进`：产品确实需要时说明当前轮次。
- `输出契约`：工具、字段、类型和互斥关系。

区块是否保留取决于生成职责，不取决于固定数量或长度。合并重复与冲突，不为形式完整强行加入状态审计、证据清单、固定写法或示例。

代码区块及区块内编号只表示处理顺序，生成职责优先级单独说明：世界与既定事实划定成立边界，玩家决定行动意图，模型按条件裁决世界响应及未决结果；其内先形成世界局面和实质不同的离散事件，再形成已成立结果，最后压缩为新的完整人生记录。事实、选择、正文表达和合法返回同时成立，不以一种要求豁免另一种。身份、原有意图规则与结果生成职责同步修改，不只更换称呼或叠加多套角色指令。

## 文字游戏随机故事生成

主叙事的主身份是文字游戏式人生重开模拟器的世界演化与事件裁决系统，叙事是将结果编译为人生记录的末端职责。生成对象是当前条件下随机形成的完整人生记录，不是连续小说片段、单场行动回放或既有历史的改写。世界提供开放的可能性，也按自身规则与利益变化；玩家、天赋、属性和已确认意图改变参与方式、走向与结果。世界中明确写出的规则优先于与其冲突的旧叙述，除非本轮已经成立的因果明确改变该规则。已确认的角色设定、自创成果及其历史来源归属是裁决依据，不因预设情节被翻案；玩家的未决意图不能直接覆盖世界结果。主角是记录的锚点，但不是所有变化的来源；正文涉及玩家时用第二人称，姓名只作输入识别。历史只继承已经成立的状态和因果，不继承上一轮叙事焦点。

在同一次生成中完成以下编排；前置字段输出具体材料，不输出规则复述或自我解释：

1. 从完整输入恢复已经成立的事实、状态、来源归属与仍有效的后果，确认当前适用条件；历史只提供事实相容条件，不提供本轮主题、写法或续写任务。近期最显眼的主题与悬念先降为背景，不作为默认选题。
2. 先从世界规则和相关者行动形成外部局面变化，再确定玩家如何参与、受影响或改变结果；宏观由作用范围和局面改变体现，不靠夸大规模。没有命运分支不等于角色没有行动；条件允许时，玩家的合龄行动、判断、关系或损失应进入事件因果。
3. 已提交的事件身份视为已消耗的题目，后续只能作为事实条件。先建立本轮新的事件身份，再从开放可能性选择彼此有实质差异的新事；近期主线只能作为背景条件，比较核心问题、因果机制、主要行动者、作用范围和结果意义，表面换设定或自然后果不算新事。
4. 根据玩家条件、确认的行动意图和世界响应裁决每件新事，将其推演为事件、成因、结果、影响的已成立材料，先于正文输出；不把玩家输入中尚未发生的成功或数值变化当作事实，不预设成败。结果材料不是候选列表、写作计划或详细思考过程。同一事件的起因、行动和直接后果归入同项，不切步骤充当多项经历。
5. 核对世界规则优先级、事实相容、焦点更替、世界与人生的局面变化、玩家和天赋作用、获得与代价，再用事件概括和代表性细节组织正文。独立变化可以并置，不设置事件数量、题材配额或层面覆盖配额。

宏观性来自对事情发展与局面改变的概括，不等于公共新闻起笔；不等于公共新闻起笔；以及整体局面与具体表现之间的视野切换，不靠夸大事件尺度，也不把每轮限制在同一种制度、资源或势力冲突。事件两面性由相关者不同处境下的获得、失去、负担和反应体现；力量与选择的代价来自投入、放弃和反作用，不凭空追加灾祸抵消成功。惊喜与荒诞来自世界特性、偶然性和各方行动交汇，不强制反转、永久牺牲或固定好坏搭配。因果与利益变化连接相关事件，独立变化可并置，不强造共同原因或时间转场。命运分支非空时落实玩家已选方向，不重新提出同一选择。

时间节点及历史年龄前缀定位本轮条件、事实顺序和可成立的发展尺度，不是正文素材。按年推进时概括该阶段积累形成的事件结果，不等同于截取一个短暂现场；正文以因果和状态变化的记录文体体现跨度。人生或历法坐标不进入正文；不承担坐标定位的相对时距只有在因果确有需要时保留。正文从本轮最能证明状态改变的局面或后果进入，在整体局面、玩家所处位置和具体证据之间按因果切换，不固定远近、段落或视角入口，不用抽象方位或固定转场句填充段落。篇幅压缩先保留不同事件的结果、局面变化、玩家作用和代价，再省略过程。外部事实不自动成为玩家知识；具体措辞由当前事件结果决定，不继承历史的表达模板。

## 动态输入

动态区提供世界、玩家档案、天赋、历史输出、属性、时间节点、命运分支和已有篇幅偏好等完成本轮记录所需事实。维持活动权威规定的五段动态数据和单条 `user` 消息，不追加候选列表、成品示例或第二状态来源。

主故事历史优先使用所有已有结构化事件结果作为事实依据；只有没有结构化结果的旧记录才回退到完整正文，不让旧正文的段落、转场和文风重新成为选题模板。历史年龄前缀仍保留为输入索引，原始正文仍由历史所有者保存。模型从这些材料继承已成立事实，不继承题目、人物焦点、段落结构、转场方式、文风或时间措辞；历史中的错误表达不构成当前成文许可。更早事实继续使用所属系统的现有投影，不增加提取调用或持久字段。

篇幅偏好沿用玩家设置的宽松目标，不另设固定字数或通过截断损失核心结果。字段和状态职责只以活动权威与运行时组装为准。

历史投影已有非空已确认选择时，只附确认方向，不再标未决或附带未选候选；未决分支保持既有信息，源正文和原始选择数据不删除、不迁移。

## 输出协议

工具 Schema、Prompt 和解析器与活动权威保持一致。主故事 JSON 依次输出字符串 `时间定位`、对象数组 `事件结果`，再输出 `正文`、`命运分支`、`属性`、`结局`。每项事件结果使用字符串`事件`、`成因`、`结果`、`影响`，不设事件数或覆盖配额。时间定位只作本轮索引；合法事件结果由同一条叙事历史记录保存并投影到下一轮输入，不直接进入界面，不另建世界状态源。应用仍只消费正文、分支、属性和结局。原始响应日志仍完整保留。正文采用的关键事实与因果必须可理解，并由既有历史承接，未采用材料不成为长期事实。属性沿用 `财富` 等公开名称，正文保持非空字符串，未触发分支和结局返回 `false`。保留各项独立恢复，不因事件结果局部缺失或异常阻断可用正文。

## 问题修复

先核对核心产物，再沿 Prompt、动态输入、历史投影、消息顺序、模型参数、解析消费和调用链定位最早偏差，在根因处直接修改。历史事实丢失不能靠更强的“不重复”补救，生成目标偏向连续小说也不能靠去除时间词纠正。删除被取代的防御性规则、过滤、格式补丁和旁路，不以禁词列表、输出过滤、重写、重试或额外调用替代本轮生成职责。

## 测试

先核对被评样本的实际 Prompt 原文、完整组装消息、模型参数和逐字响应，再固定模型、参数、消息顺序、输入、篇幅偏好与输出协议比较，按用户声明的轮次执行。不能只凭相同版本号断言规则相同，也不能把不同历史信息量或推理设置的结果归因于某条 Prompt。

验收先看每轮是否形成新的完整人生记录、多项结果是否真正改变状态、事实是否连续但焦点不被旧事锁定，再检查无时间标记、人称与字段。静态检查不证明真实生成质量；独立 Prompt 评测不证明生产入口、解析、提交和持久化链。测试结果用于判断是否达到设计目标，不把一次失败包装成更多 Prompt 规则，也不自行推进后续轮次。
