# Prompt 标准

## 目标

让每个官方 API 调用获得自足、最小、稳定且可校验的中文 Prompt，不依赖模型预先知道项目、系统或调用链背景。

## 任务身份与目标

1. 系统 Prompt 的前两个键固定为 `身份` 和 `目标`。
2. `身份` 只说明本次调用承担的任务角色，例如故事生成器、记忆压缩器、路线生成器、分析器或提取器；不把项目名、内部架构、MOD、状态所有者或调用顺序当作模型已知背景。
3. 身份名称优先使用直接描述产物且能自足说明任务边界的角色。只有真实测试证明更稳定时才使用“文字世界运行核心”“小说作者”等强化文体联想的名称；无论名称为何，都按模型未知项目、架构和调用链处理。
4. `目标` 用一句话声明唯一功能、直接产品和必要终态，不重复执行规则或输出模板。
5. 身份和目标作为隔离变量验证：其余系统 Prompt、动态输入、消息顺序、模型参数和输出协议不变，只比较目标模型的结构通过率与内容验收。
6. 非格式、Schema、字段、解析、互斥关系和终态形状等结构性契约的 Prompt 文案使用正向目标、事实边界和优先级表达；避免使用“必须、一定、只能、不得、禁止、务必”等强制限定词，把相同意图改写为可执行的结果描述。结构性契约为保障可解析性而保留形式化措辞时，不扩散到剧情、文风、能力或内容创作规则。

## 叙事输入去重

1. 历史记忆和最近两轮正文用于消歧、衔接和识别已完成上下文，不承担下一轮新事件的创作模板职责。
2. 当前回合引导与当前回合事实承担新目标、新阻力、新关系变化和新结果；连续性描述优先指出变化方向，不要求复述上一轮场景。
3. 当近期正文反复使用同一地点、关系或动作时，Prompt 通过切换叙事重心、外部回应或目标变化保持推进；这类语义使用正向结果描述，避免把“不要重复”扩写成新的重复模板。

## 中文代码式 JSON

1. 固定系统 Prompt 使用一个可由 `JSON.parse` 直接解析的中文 JSON 对象，不添加 Markdown、注释或对象外说明。
2. 推荐键顺序为 `身份`、`目标`、`输入映射`、任务执行规则、必要条件决策、`输出契约`；没有实际职责的键省略。
3. `输入映射` 只解释动态输入名称及其业务含义，不复制动态值。
4. 同类顺序动作写入字符串数组，每个数组项只承担一个职责，并按实际依赖排列。
5. 互斥结果使用对象数组表达 `如果`、`则`、`否则如果`、`否则`；模型先选择唯一模式，再生成该模式要求的内容。
6. `输出契约` 只声明媒介、形状、字段类型、互斥关系和结束条件，并且只声明一次。
7. Prompt 使用 JSON 组织不代表所有项目调用使用同一输出媒介；一个调用包含多个需要拆分校验的直接结果区时，统一输出一个严格 JSON 对象，不混用 JSON 与裸行文本。
8. `response_format` 是 Provider 请求参数，不是 Prompt 完整性的替代品。只有目标协议、解析器和真实回归共同证明需要时才启用。

## 最小充分设计

1. 先确定唯一功能，再反推必要判断、最小输入和最小输出。
2. 每个输入、规则和输出字段应能回答：删除后哪个必要结果无法产生；没有具体答案时删除。
3. AI 只接收完成业务判断所需的事实；编号、路由、去重、数值计算、钳制、状态写入和持久化由本地所有者处理。
4. 下游 AI 不重新判断上游已经成立的结果；正文与压缩记忆足以维持的剧情事实不建立重复字段或独立调用。
5. 每个调用和字段都会增加 Token、成本、等待时间与失败概率，只有不可替代的必要结果能够证明其保留价值。
6. 合并调用同时满足同一触发点、共享主要事实、能够形成一个严格结果包且不产生前后依赖；只共享少量字段或只有名称相近不足以证明合并。

## 问题修复

剧情质量问题先沿固定 Prompt、动态组装、输入映射、消息顺序、模型参数、解析消费和调用链反向核对，定位最早改变结果的偏差及其唯一根因所有者。根因属于已有规则、输入或职责时，修改或合并原内容，并删除被取代的同义文案、后置过滤和格式补丁；只有职责确实缺失或用户明确提出时才新增提示词、字段、调用或规则。

## 规则新增判定

1. 新增第五条或后续同类规则前执行 Conflict、Coverage、Complexity 检查。
2. 与现有规则的职责、条件或结果重叠超过 30% 时合并，不新增同义规则。
3. 现有规则已覆盖 95% 以上结果，而新增规则只处理剩余边缘情况时，并入最接近的规则或输出不变量。
4. 只有需要独立输入、判断或输出职责时才新增 JSON 键；一句话能够完整表达时并入现有数组。
5. 默认使用正向结果描述；真实复测稳定出现某个错误时，允许在所属规则中加入一条直接指向该错误的短负向边界。

## 输入与缓存

1. 固定身份、目标、规则和协议排列在消息前部。
2. 主故事固定使用三条可由 `JSON.parse` 直接解析的完整动态消息，对象外不加 `⟦…⟧` 标签：稳定世界事实，历史记忆与最近两轮详细剧情后接角色当前叙事语义，以及白话本轮引导。
3. 主故事的世界消息不发送文明阶段、当前区域、难度枚举、历法名称、系统配置、基础值、修正值、当前数值、天赋等级或词条来源；本轮引导只发送当前时间、玩家行动、挑战与失败取向、文风和篇幅的完整句子。存在已到期且仍可用事项时，第三条消息增加可选的 `当前到期事件`，只发送时间、标题和事实，不发送候选编号、审计状态或其他内部投影。文风古典但略微白话、直接易读，字数使用“约 N 字”目标值。角色对象使用 `天赋` 键，每项只发送名称和效果。
4. 故事 AI 的历史记忆使用有效 JSON 字符串数组，同日连续事实合并为一项，不发送权重、来源 ID、层级、衰减或计算字段。02 保留自身必要的记忆权重职责；03 保留等级与属性创作边界。
5. 结构化 JSON 的键和值保留标准双引号和标准转义；只能删除不承担结构、语义或示范作用的强调引号。缓存命中依赖精确且稳定的消息前缀，不会因删除双引号自动提高。
6. 同一调用保持固定键顺序、数组顺序和序列化方式一致。
7. 每个调用在本地使用稳定且隔离的调用标识；调用标识不进入 AI 可见消息或输出。

## 正常建局与连续样品

1. 声称模拟正常流程的样品先建立共享创建基线，覆盖世界名称与描述、空间形态、世界观本质、力量体系与边界、历法和叙事风格，角色姓名、性别、种族、背景、起始年龄、寿命，基础值、修正值、当前值，以及已选普通命格和轮回天赋。
2. 共享基线用于证明信息来源完整，不代表每次调用都发送整份内容；01 接收故事成立所需的世界与角色事实，02 接收时间轴事实，03 接收成长候选与本级证据。
3. 连续测试把已经验收的记忆、未来事件和玩家选定成长路线应用到下一轮；原始故事、原始 AI 输出和每次状态快照完整保留。
4. 02 以三条标准 JSON 用户消息依次接收历史记忆、最近两轮正文和当前回合。输出近期完整正文退出上下文后仍需成立的连续性事实；先保留最终状态、持续关系、关键发现、承诺和未解决结果，再移除被后续结果完整覆盖且没有独立影响的中间动作与阶段结果。本轮记忆每项输出时间、事实和必要权重；未来事件使用无权重的 `时间：事实` JSON 字符串数组。本轮记忆投影给后续故事 AI 时移除权重，转为同日合并的 `时间：事实` 字符串。
5. 02 的未来事件只接受具体日期、明确历法周期或可由当前绝对时间唯一换算的相对时间；没有排期的条件、触发关系和“下次”事项保留在连续性事实中，不推定为当前回合之后的时间。
6. 03 的候选至少包含命格血脉编号、当前版本、类别、当前名称、当前等级、当前详细介绍、当前效果、当前完整属性加成、目标等级和允许属性；候选不含极性。系统 Prompt 只声明一次六级通用能力边界，并说明体魄、心智、悟性、魅力、气运的用途与点数语义。
7. 03 的动态组装紧接系统消息先提供历史记忆和最近两轮详细正文，再提供仍有严格下一等级的已选普通命格；本地不以关键词、时间数量或故事阶段代替 AI 的语义成长判断。
8. 03 的 AI 按 `SELECT 候选 -> FILTER 必要触发条件 AND 核心能力实际表现 -> RETURN` 执行；有条件的当前效果只有在已成立事实明确写出全部必要触发条件，并且核心能力实际表现出结果时才能计入。需要使用“未直接触发”“类似环境”“能力延伸”“可以视为”或同义解释才能关联时同样无效。成长依据只概括已经成立的必要事实，不补写动作、环境或结果。三条路线固定为深度强化、广度强化、转变强化，分别表示同路更深、同路更宽和作用方式发生根本变化，名称和效果保持实质不同并处于同一目标等级。转变强化只改变作用方式，不额外扩大影响总量。描述使用叙事逻辑说明能力会给剧情带来什么变化，不使用成功率、判定值、触发率、冷却或其他系统化措辞。属性加成表示成长后的完整词条，不是本轮增量。等级与属性预算读取当前活动权威；负属性可以抵扣正属性，但只有真实牺牲时使用；本地校验沿所属权威执行。
9. 命格名称为二至六个汉字，优先四字；可有古朴神话感，但强度严格对齐目标等级。详细介绍和效果描述先直接说明能力，再写条件、代价或限制；保留古典用词质感并保持易读，避免堆砌意象、典故、倒装或玄虚套话，比喻最多一处且不能替代具体机制。

## 输出协议

1. Schema、Prompt、解析器、校验器和状态应用共同使用同一字段契约。
2. 输出只包含调用的直接产品；标题、解释、依据、标签、来源和重复摘要只有在唯一功能直接需要时保留。
3. JSON 输出声明完整顶层形状、必要键、可空值、互斥关系和未知字段边界。
4. 纯 JSON 响应的第一个字符为 `{` 或 `[`，最后一个字符为对应的 `}` 或 `]`；对象或数组外不输出代码围栏、语言标题、解释或其他字符。
5. 裸行输出声明单行形状、行首行尾、空结果和值域，不额外添加 JSON、项目符号、代码围栏或说明。
6. 格式占位只使用中性键名、类型和关系，不提供人物、世界、事件、路线、能力、属性或成品内容示例；详细样品只能留在离线审查文档，不进入正式 Prompt。
7. 响应终态验收覆盖完整响应、截断、空字段、未知字段、重复字段、互斥冲突和状态应用结果。
8. JSON 字符串中的段落换行使用 `\n` 转义，引号、反斜线和控制字符遵守标准 JSON 转义；不得在字符串内部输出未经转义的真实换行。
9. 01 故事正文使用一个非空 JSON 字符串；全部段落保持在同一字符串内，需要换行时只使用 `\n` 转义，不把段落拆成相邻字符串、数组元素或额外字段。
10. 解析器先尝试标准 JSON，再宽容识别成对围栏、对象外说明、旧标签和普通正文。主故事正文字符串遗漏关闭引号时，只在后续合法顶层字段边界可唯一确定时补全引号并转义字符串内裸换行；字段顺序不作为前提。不唯一、缺少括号、多个对象或空响应不补写。
11. 解析器默认采用最大兼容和逐项恢复：标准 Schema 不是整包拒绝门禁；字段别名、乱序、字符串数字、布尔变体、局部补全和多候选响应先尝试恢复。单个坏字段、坏数组项或坏未来事件单独放弃，其余内容继续消费；只有最低可用产品完全不存在时才失败。除非绝对必要，禁止严格性判定、格式修复请求、重试或备用模型。

## 样品与验收

1. 01 至 03 样品使用同一中文代码式 JSON 系统 Prompt 结构；01 生成故事，02 提取时间轴连续性，03 判断天赋成长并生成路线。最终样品架构固定为前置 01、后置 02/03；04 状态变化样品不保留。
2. 样品通过用户审查和真实请求验证后才能进入运行时资产。
3. 身份或目标变化按隔离测试处理，其他系统 Prompt、动态输入、模型参数和请求顺序保持不变。
4. 机器格式检查与人工语义验收分别记录；关键词检查不能替代时间、事实、行动与终态判断。
5. 逐项核对身份自足、目标唯一、JSON 可解析、字段无重复、条件唯一、输出媒介匹配、稳定前缀、动态后缀和调用隔离。
6. 故事正文和不提前结局属于硬验收；分支准确判定、应结局而漏结局和天赋成长属于非硬验收。压缩的时间、事件和权重属于硬验收，未来事件属于非硬验收；压缩失败应验证不阻塞正文并可在详细窗口内重试。
7. 后续正式替换必须删除 04 的调用、Prompt、Schema、缓存、状态应用和测试引用，不得从其他输入或调用恢复同类 AI 状态分析职责。
