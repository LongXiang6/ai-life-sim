# Prompt 标准

<!-- RULE id="prompt-standard.user-hard" source="USER-HARD" owner="prompt" status="active" -->
Prompt 只负责让模型生成用户要的内容，并提供完成生成所必需的最少说明和返回协议。目标清晰，路径开放；禁止把过渡性设计、过渡性防御设计或假设问题的限制写成 Prompt 目标。
<!-- END RULE id="prompt-standard.user-hard" -->

## 最小结构

固定 Prompt 使用可由 `JSON.parse` 直接解析的中文 JSON。只设置实际有职责的键，通常为：

- `身份`：模型负责生成的产物。
- `目标`：用户要得到的结果。
- `叙事`：必要的人称、主体或视角。
- `推进`：产品确实需要时说明当前轮次。
- `输出契约`：工具、字段、类型和互斥关系。

不为形式完整强行加入输入映射、边界分类、状态审计、证据清单、固定写法或示例。

## 人生模拟器

生成对象是玩家接下来要经历的人生故事，不是润色、总结、结算报告或行动日志。玩家选择推动剧情，既有剧情、玩家角色和世界环境对选择产生回应；结果应让玩家感到人生在变化，并保留继续经历和选择的空间。

玩家角色需要第二人称时，用一句话说明即可。宏观或微观时间、体例、视角距离、节奏、段落和具体表达交给模型根据剧情自然决定，不把任何一种实现写成固定模板。

## 动态输入

动态区提供世界、玩家档案、历史剧情、属性、当前剧情和玩家选择等完成本轮创作所需事实。历史用于连续性，不作为成品样例；不为弥补 Prompt 缺陷新增额外调用或额外结算层。

## 输出协议

工具 Schema、Prompt 和解析器使用同一字段契约。只声明产品真正需要的字段、类型和互斥关系；正文保持非空字符串，未使用的可选字段按既有契约返回字符串 `"null"`。

## 问题修复

沿 Prompt、动态输入、消息顺序、模型参数、解析消费和调用链定位最早偏差，在根因处直接修改；删除被取代的防御性规则、过滤、格式补丁和旁路，不用过渡性设计替代用户目标。

## 测试

测试固定模型、参数、消息顺序、输入和工具协议，按用户声明的轮次执行。测试结果用于判断是否达到设计目标，不把一次失败包装成更多 Prompt 规则，也不自行推进后续轮次。
