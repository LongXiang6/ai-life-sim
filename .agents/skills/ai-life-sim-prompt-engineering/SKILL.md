# AI 人生模拟器提示词工程

## 目标

[核心原则] 让固定 Prompt、动态组装、结构化输出、解析、校验、缓存与状态应用形成单一可追踪契约。

## 适用范围

[核心原则] 提示词、Skill 指令、结构化输出、解析器、叙事组装、Provider 参数、Token、缓存池和调用标识由本 Skill 负责。

[次要规则] DeepSeek 生命周期、`finish_reason`、保活、超时、限速、`user_id` 和 KVCache 同时读取系统树 AI 服务章节与 `PD-039`、`PD-040`。

## 执行契约

[核心原则] Prompt 创建、审查或样品制作先读取 [Prompt 标准](references/prompt-standard.md)。

[核心原则] 活动权威先声明调用应达到的结果，Prompt 与组装器再实现该结果。

[核心原则] 官方 API 模型只知道当前请求；固定 Prompt 先用任务型身份和一句唯一目标建立完整上下文，不假设模型知道项目、MOD、状态所有者或调用链。

[核心原则] 固定 Prompt 使用可直接解析的中文 JSON 对象，按 `身份`、`目标`、`输入映射`、执行或条件规则、`输出契约` 排列；没有实际职责的键省略。

[核心原则] 互斥结果使用明确的 `如果`、`则`、`否则如果`、`否则` 决策，输出媒介、形状、类型、互斥关系和结束条件只声明一次。

[核心原则] 每个调用先用一句话确定唯一功能，再按“必要判断、最小输入、最小输出”反推协议；删除后不影响必要结果的字段不进入 Prompt。

<!-- RULE id="prompt.root-cause" source="USER-HARD" owner="prompt" status="active" -->
[核心原则] 剧情质量问题按 [Prompt 标准](references/prompt-standard.md) 的“问题修复”段落执行：沿 Prompt、动态输入、调用链和解析消费定位首个偏差，在根因所有者处修复或合并原有内容。
<!-- END RULE id="prompt.root-cause" -->

[核心原则] 新增第 5 条或后续同类规则前执行 3C：Conflict 超过 30% 重叠时合并，Coverage 只覆盖剩余 5% 边缘情况时并入最近规则，Complexity 只有形成独立输入、判断或输出职责时才新增 JSON 键。

[核心原则] 工程编号、路由、去重、计算、钳制、状态写入和上游已经完成的判断由本地所有者处理，仅将 AI 直接需要选择或生成的业务信息发送给 AI。

[核心原则] 新增调用或字段应产生不可由现有故事、压缩记忆、上游结果或本地程序替代的结果；Token、等待时间、成本和失败概率计入负面设计成本。

[核心原则] 合并调用只在职责拥有同一触发点、共享主要事实、可以组成一个严格结构化结果包且不形成前后依赖时成立；合并后的各结果区仍由本地所属系统分别校验和消费。

[核心原则] 固定资产承载长期稳定规则，动态区承载本轮事实、条件和玩家原始意图。

[核心原则] 占位符、Schema、解析、校验和应用共同描述一个字段契约。

[核心原则] 所属系统负责业务状态写入，Prompt 负责生成所需信息。

[核心原则] 每个调用在本地使用稳定且隔离的调用标识并映射到所属缓存池，调用标识不进入 AI 可见消息或输出。

[核心原则] 主故事消息编排、动态输入边界、样品基线和成长投影读取 [Prompt 标准](references/prompt-standard.md) 的“输入与缓存”和“正常建局与连续样品”段落；具体字段、数值和当前结果由活动权威维护。

[核心原则] 解析兼容、Schema 归一化、逐项恢复和最低可用终态读取 [Prompt 标准](references/prompt-standard.md) 的“输出协议”段落；入口不复制解析规则。

[次要规则] 样品生成、隔离测试、用户审查和运行时替换读取 [Prompt 标准](references/prompt-standard.md) 的“样品与验收”段落。

## 权威与实时源

[核心原则] 当前回合结果读取 `docs/authority/core-simulation.md` 及 `docs/authority/mechanisms/core-round/`。

[核心原则] Prompt 与缓存结果读取 `docs/authority/mechanisms/prompt-and-cache.md` 和 `cache-isolation.md`。

[核心原则] Prompt 资产、动态组装、Schema、解析器和状态应用以权威点名的实时源为准。

[次要规则] Provider 传输与参数读取 `src/core/ai-service/` 和 `src/app/api/proxy/`。

## 边界

[核心原则] AI 调用数量、字段、Provider 策略、重试、回落和内容门禁以当前用户要求和最新编号目标为准。

[核心原则] 固定规则进入固定资产后，动态区保留本轮事实和字段值。

[核心原则] 下游 AI 不重新解释上游已经成立的业务结果；只为叙事连续性服务的事实优先由故事正文与压缩记忆承载。

[核心原则] 故事 AI 的硬产品是可用正文且不得提前结局；分支判定、应结局而漏结局和天赋成长结果是非硬要求。压缩 AI 的硬产品是准确时间、事件和权重，未来事件为非硬要求；压缩失败不阻塞正文，并在详细窗口内后续重试。

[次要规则] AI 失败通过所属调用的明确失败状态返回流程所有者。

[次要规则] 本地校验聚焦字段、类型、结构、证据引用和终态完整性。

## 验收

[核心原则] 运行直接相关 Prompt、协议、解析、缓存和 AI 服务回归。

[次要规则] 结构化写入或回合推进变化运行 `npm run check:execution`。

[次要规则] Skill、Prompt 文件、格式和命名变化运行 `npm run check:standardization`。

[次要规则] 纯 Prompt 结构化输出按目标模型、温度、消息顺序和 Token 上限执行重复真实请求；代码围栏、未转义控制字符、字段遗漏或截断任一偶发复现时，样品不得标记为可直接替换运行时。

[辅助说明] 核对旧协议入口、重复 Schema、旁路状态写入和未声明字段已经完成收口。
