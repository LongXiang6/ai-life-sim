# AI 人生模拟器 Prompt 工程

## 目标

<!-- RULE id="prompt.goal.user-hard" source="USER-HARD" owner="prompt" status="active" -->
Prompt 的唯一产品目标是生成符合人生重开模拟器要求的 AI 内容：根据世界、玩家、天赋、已结算现实、当前时间节点和玩家意图，随机形成新的、完整的广角人生记录，让多项已经落地、各自有事实与结果的变化共同把人生或世界带到新的位置。先保证这一核心产物成立，再处理表达与协议细节，不能用无时间词、格式正确或文字流畅代替核心质量。
<!-- END RULE id="prompt.goal.user-hard" -->

<!-- RULE id="prompt.neutral-compact-rules" source="USER-HARD" owner="prompt" status="active" -->
编写固定 Prompt 时，把被调用模型视为没有调用外上下文或全局信息的独立执行者；模型只能依据当前组装消息理解世界、历史、当前状态与本轮职责，消息必须自足且不能要求模型记住未提供的信息。规则以合理、充分地完成核心目标为准，不以最短或最少为优化目标；保留确有生成职责的说明，合并冲突和重复，不为精简删除恢复事实、形成新变化、比较状态差与组织结果所需的指引。使用客观、中性、适配不同世界观的原则，不用正面或负面枚举堆叠题材、事件、写法或禁词。输入中的年龄、纪元、事件进度等时间信息属于定位本轮条件的索引，不是正文素材；正文应把索引转译为人物、局势、行动、因果和结果，不把时间索引或时间经过写成叙述语言、标题、转场或收尾。
<!-- END RULE id="prompt.neutral-compact-rules" -->

## 适用范围

处理固定 Prompt、动态输入、结构化 AI 输出、解析和真实请求验收。生成质量优先检查事件新意、叙事重心、代表性具体表现和玩家因果位置，不把宏观误写成公共政策报告。主叙事模型以世界演化与事件裁决为首要职责，最后把已成立结果编译为人生记录；不把身份名称本身当作真实质量改善的证据。

## 执行契约

- 先按活动权威确认核心产物、输入职责和验收依据，再判断现有规则能否充分完成目标。不能只修时间词、格式或单个失败片段，却保留把本轮写成连续小说的生成目标。
- 按[Prompt 标准](references/prompt-standard.md)组织生成职责：开头定义世界演化与事件裁决身份、权限边界和离散人生记录产物，再以只读数据恢复事实，先形成外部世界局面，选择与近期历史核心问题有实质差异的新事，裁决玩家参与并统一形成已成立事件结果，最后压缩为广角正文并结算。身份变化应同步原有生成顺序、意图落实和事实边界，不另叠同义角色清单。区分编号顺序与职责优先级：事实划定成立边界，已选意图落实为行动与世界响应，未决结果依条件裁决；篇幅和表达服务事件结果。时间定位只作本轮索引；事件结果由同一条叙事历史记录保存并投影到后续输入，不成为平行世界状态；不增加调用或程序事件库。
- 世界先形成局面变化，玩家是人生记录的参与者或受影响者而不是所有变化的来源。新事件按事件身份、核心问题、因果机制、主要行动者、作用范围和结果意义与近期历史比较，不能用换人物、地点、物件或措辞代替新事。玩家背景、天赋、属性和已确认意图改变参与方式、走向与结果，姓名只作识别；正文涉及玩家时使用第二人称，不用姓名或第三人称替代。命运分支非空时落实确认的行动或发展方向，不把其中未发生的成功或数值结论登记为事实，也不预设失败；新选项同样表达方向而非保证结果。已确认的角色设定与自创成果是裁决依据，不为戏剧需要改写历史来源和归属。变化依据自身因果产生收益、损失、负担或反作用，不把宏观性误解为强制宏大事件。
- 历史只继承已经成立的事实、状态与因果，不继承上一轮主题。已确定的来源、归属、关系和身份持续有效，除非本轮新的因果明确改变；已完成事项不能换一种说法重新发生。恢复事实后，近期主题、冲突和最显眼的未解决问题只作为背景条件，不能成为本轮默认选题。先从世界规则、外部势力和开放人生可能性建立新事件身份，再以事件核心问题与结果意义理解新旧经历的差别，不以表面设定变化重复同一问题和应对过程。既有后果作为新事件条件，不自动决定本轮题目。
- 事件结果是正文唯一的前置事实材料：先确定发生、成因、已成立结果和影响，再组织正文。从最能证明本轮状态改变的事实进入，在整体局面、玩家位置与具体证据之间按因果切换，不固定远景开头或段落转场，也不回放现场动作链。不同变化可以并置，同一冲突的步骤不充当多项新经历。两面性与意外从事件因果中形成，不采用固定惩罚、永久牺牲或反转模板。正文涉及玩家时使用第二人称，借因果与状态变化的记录文体表达跨度；玩家姓名只用于识别。
- Prompt 保留目标、输入职责、必要生成方法、表达边界和返回协议，不规定固定事件数、覆盖配额、段数、字数、标题、三幕、拍数、镜头、意象、对白、钩子或详细示例；既有玩家篇幅偏好仍由动态输入提供。用能够覆盖同类问题的原则修复职责，不为单个词语、题材或失败样例追加独立规则。

固定 Prompt 使用可读、自足的消息结构；需要机器解析的动态输入与输出使用 JSON。区块由实际生成职责决定，不为形式完整强行加入审计字段或证据清单。

动态输入承载本次调用需要的世界、玩家、天赋、历史输出、当前属性、时间节点、命运分支与已有篇幅偏好。所有未压缩的历史轮次优先使用同轮已保存的结构化事件结果作为已成立事实；只有缺少结构化结果时才使用完整正文作为回退，不取末句或用结局评语代替整轮事实。原始正文仍由历史所有者完整保存，不建立第二状态来源。历史投影区分已确认选择与未决分支，不把已选记录附上未选候选或继续标成未决；只修派生输入，不删除源记录。历史材料的主题、文风、结构和时间措辞都不是本轮模板。世界明确规则不能由与之冲突的旧叙述自行推翻，旧事件身份仅作已成立事实条件。时间节点及历史年龄前缀保留在输入，用于定位适用条件和事实顺序；正文不用人生或历法坐标定位，因果确实需要时可保留不承担坐标定位的相对时距。

## 权威与实时源

主叙事结果读取[核心模拟](../../../docs/authority/core-simulation.md)与[主叙事输入区](../../../docs/authority/mechanisms/core-round/prompt-input.md)；固定规则以 `D:/AI/docs/prompt.txt` 为接入基线，动态字段、调用消息与输出契约核对运行时组装和解析。Prompt 结构与生成编排方法见[Prompt 标准](references/prompt-standard.md)。

## 边界

<!-- RULE id="prompt.no-transitional-design" source="USER-HARD" owner="prompt" status="active" -->
禁止过渡性设计、过渡性防御设计和替用户预设目标。不得为了防止假想问题增加新的调用、状态、过滤、负面清单、兼容路径或写作限制。模型出现偏差时先定位最早改变结果的规则或数据，再修改原所有者并合并被取代内容，不把每个症状逐条改写成新规则。只有用户明确要求或实际产品契约确实缺失时，才增加对应内容。
<!-- END RULE id="prompt.no-transitional-design" -->

不修改应用运行代码、公共契约、持久化 Schema、Provider 凭据或部署配置，除非用户明确要求。Skill 和 Prompt 变更完成后，只运行与当前目标直接相关的检查；不自行开启新一轮测试或连续推进剧情。

## 验收

工具调用时，Prompt 与工具 Schema 使用同一字段契约。验证直接产品需要的字段、类型和唯一终态；不通过后置过滤、重写或额外模型调用弥补 Prompt 问题。

纯 Prompt 测试固定模型、消息顺序、动态输入、参数和工具协议，按用户声明的轮次执行。测试用于判断故事是否达到设计目标，不把测试指标升级为新的 Prompt 限制。

纯 Prompt 测试必须明确标记为独立评测，不得声称覆盖实际运行流程；实际入口、运行时资产、解析、状态提交和持久化链的保真验证由 `$ai-life-sim-testing` 负责。

验收先检查真实结果是否形成新的广角人生记录、多项变化是否各自落地、历史是否只约束事实且焦点能够更替，再检查时间表达、人称与协议。静态检查只能证明资产、接线和契约一致，不能据此宣称生成质量合格。

<!-- RULE id="prompt.root-cause" source="USER-HARD" owner="prompt" status="active" -->
剧情质量问题沿 Prompt、动态输入、历史投影、消息顺序、模型参数、解析消费和状态提交追踪到最早偏差，在唯一根因处直接修复。先判断生成目标是否仍是人生重开模拟器的完整人生记录、历史事实是否充分可见但不继承焦点、单轮是否由多项有效状态变化形成新结果，再处理表达细节；删除被取代的提示、过滤、格式补丁和旁路，不用过渡性防御设计掩盖根因。
<!-- END RULE id="prompt.root-cause" -->
