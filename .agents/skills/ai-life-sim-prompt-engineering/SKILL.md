# AI 人生模拟器 Prompt 工程

<!-- RULE id="prompt.goal.user-hard" source="USER-HARD" owner="prompt" status="active" -->
Prompt 的唯一产品目标是：根据剧情、玩家角色、玩家选择和世界环境，继续生成可玩的、有人生变化和命运牵引的故事内容，让玩家想继续经历下一段人生。
<!-- END RULE id="prompt.goal.user-hard" -->

<!-- RULE id="prompt.no-transitional-design" source="USER-HARD" owner="prompt" status="active" -->
禁止过渡性设计、过渡性防御设计和替用户预设目标。不得为了防止假想的越权、失控、风格偏差或未来问题，额外增加调用、结算层、状态、过滤、负面清单、兼容路径、严格格式或写作限制。只有用户明确要求或实际产品契约确实缺失时，才增加对应内容。
<!-- END RULE id="prompt.no-transitional-design" -->

## 适用范围

处理固定 Prompt、动态输入、结构化 AI 输出、解析和真实请求验收。Prompt 是剧情生成器，不是润色器、审计器、结算报告器或后置过滤器。

## 核心方法

- 先确定唯一生成目标，再保留完成目标所必需的最少规则。
- 玩家是剧情主体，玩家选择推动故事，既有剧情和世界环境产生回应。
- 人生模拟器的内容应有因果、变化、关系和未来牵引；具体体例、时间尺度、节奏、镜头和表达方式交给模型根据输入选择。
- Prompt 只规定目标、必要边界和返回协议，不规定固定段数、字数、标题、三幕、拍数、镜头、意象、对白、钩子或详细示例。
- 规则越少越好；删除一条规则后目标仍能实现，就删除或合并它。

## 标准结构

固定 Prompt 使用可直接解析的中文 JSON。只在有实际职责时设置键，通常包括：

- `身份`：模型在本次调用中负责生成什么。
- `目标`：要让玩家获得什么故事体验。
- `叙事`：必要的人称或玩家角色视角，例如“使用第二人称”。
- `推进`：仅在产品需要时说明当前轮次或推进边界。
- `输出契约`：工具、字段、类型和互斥关系。

不要为了形式完整强行加入输入映射、边界分类、证据层、状态维度或审计字段。

## 动态输入

动态输入承载世界、玩家档案、历史剧情、当前属性、玩家选择和本轮所需事实。历史用于连续性，剧情用于继续创作；不要把历史范文或详细样例放入固定 Prompt 诱导模型照抄。

## 输出与验证

工具调用时，Prompt 与工具 Schema 使用同一字段契约。验证直接产品需要的字段、类型和唯一终态；不通过后置过滤、重写或额外模型调用弥补 Prompt 问题。

纯 Prompt 测试固定模型、消息顺序、动态输入、参数和工具协议，按用户声明的轮次执行。测试用于判断故事是否达到设计目标，不把测试指标升级为新的 Prompt 限制。

## 根因修复

<!-- RULE id="prompt.root-cause" source="USER-HARD" owner="prompt" status="active" -->
剧情质量问题沿 Prompt、动态输入、消息顺序、模型参数、解析消费和调用链追踪到最早偏差，在唯一根因处直接修复；删除被取代的提示、过滤、格式补丁和旁路，不用过渡性防御设计掩盖根因。
<!-- END RULE id="prompt.root-cause" -->

## 变更边界

不修改应用运行代码、公共契约、持久化 Schema、Provider 凭据或部署配置，除非用户明确要求。Skill 和 Prompt 变更完成后，只运行与当前目标直接相关的检查；不自行开启新一轮测试或连续推进剧情。
