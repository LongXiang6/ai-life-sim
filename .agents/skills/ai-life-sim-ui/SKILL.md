# AI 人生模拟器界面

## 目标

[核心原则] 实现用户指定的页面、状态、交互、导航和响应式结果，并保持低信息压力与稳定视觉层级。

## 适用范围

[核心原则] 页面、原型目标、布局、交互、文案、动画、导航和响应式变化由本 Skill 负责。

[次要规则] 状态所有权变化同时读取系统树，跨界面流程变化同时读取逻辑树与机制权威。

## 执行契约

[核心原则] 先读取第一层界面树，再读取目标页面的第二层权威和其导航的深层机制权威。

[核心原则] 页面消费 MOD 或引擎公开投影，业务状态由所属系统维护。

<!-- RULE id="ui.root-cause" source="USER-HARD" owner="ui" status="active" -->
[核心原则] UI 问题先沿公开状态投影、组件契约、事件路径、布局约束和响应式状态定位首个偏差，在唯一所有者处修正。只有确认缺少组件、状态或约束时才新增；额外 CSS 覆盖、页面特判、重复控件和局部状态补丁不替代根因修复。
<!-- END RULE id="ui.root-cause" -->

[核心原则] 同一功能在多页面、多状态和多入口复用同一公共组件与样式契约。

[核心原则] 标题、正文、辅助信息和操作控件维持清晰稳定的视觉层级。

[次要规则] 图标、按钮、返回、确认、导航和反馈控件沿用项目现有组件契约。

[次要规则] 响应式布局维持内容可读、控件可达和状态可辨识。

[次要规则] 标识、文件、格式和命名按 [项目标准化契约](../ai-life-sim/references/standardization.md) 执行。

## 权威与实时源

[核心原则] 第一层玩家流程读取 `docs/authority/interface-tree.md`。

[核心原则] 第二层页面结果读取 `docs/authority/pages/` 的目标文件。

[核心原则] 第三层与第四层机制结果读取目标页面导航的 `docs/authority/mechanisms/`。

[次要规则] 具体组件、样式和公开 API 以目标权威点名的实时源为准。

## 边界

[核心原则] 页面负责展示、输入和导航，业务计算、持久化和跨系统写入由所属公共契约完成。

[核心原则] 原型评审控件只服务原型评审，运行时功能以活动权威为准。

[次要规则] 失败状态在对应操作位置清晰呈现，并保持成功状态语义准确。

## 验收

[核心原则] 运行目标页面或流程回归及 `npm run check:ui`。

[次要规则] 项目文件变化运行 `npm run check:standardization`。

[次要规则] 状态所有权、跨系统流程或持久化变化运行 `npm run check:structural`、`npm run check:execution` 或本次范围内的 `npm run gate-check`。
