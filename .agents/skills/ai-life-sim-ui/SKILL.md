# AI 人生模拟器界面

## 目标

准确实现用户指定的页面、状态、交互、导航和响应式运行目标，让界面消费公开系统投影并保持低信息压力与稳定视觉层级。

## 适用范围

- 页面、原型目标、布局、交互、文案、动画和响应式变更。
- 读取界面树目标章节；状态所有权变化时追加系统树，端到端流程变化时追加逻辑树。
- 用户指定页面或明确选定原型时，以该页面或原型为目标；原型评审控件不是运行时功能。

## 执行契约

- 页面只使用 MOD 或引擎公共 API，不拥有引擎状态；同一功能在不同页面、状态或入口复用同一个公共组件和样式契约。
- 标题在视觉层级上大于所属正文，保持稳定字号、字重和行高；响应式调整不得让正文反超标题或混淆层级。
- 图标能增强理解时使用图标；按钮、返回、确认、导航和反馈控件遵循项目既有组件与样式契约。
- 标识、文件、格式、写法和排序按 [项目标准化契约](../ai-life-sim/references/standardization.md) 执行；页面不建立第二套状态或文案真源。

## 权威与实时源

- 页面与交互机制：`ai-life-sim/docs/authority/interface-tree.md`。
- 跨系统流程：`ai-life-sim/docs/authority/logic-tree.md`。
- 状态所有权和公共 API：`ai-life-sim/docs/authority/system-tree.md`。
- 具体页面、组件和样式以被目标章节点名的实时源为准。

## 边界

- 不把原型评审控件、页面局部 Store、聚合器或文案副本当成业务状态所有者。
- 除非存在明确平台差异，不为同一交互建立多个外观、键名、状态码或旁路入口。
- 页面只消费所属系统公开结果；跨系统写入必须经公共契约，失败状态必须可见且不能伪装为成功。

## 验收

- 运行对应页面或流程回归及 `npm run check:ui`。
- 修改项目文件后运行 `npm run check:standardization`，确认页面文件、组件命名、文档格式、生成标记和唯一归属符合项目契约。
- 涉及状态所有权、跨系统流程或持久化时追加 `npm run check:structural`、`npm run check:execution` 或 `npm run gate-check`。
