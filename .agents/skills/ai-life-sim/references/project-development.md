# 项目开发契约

仅在任务涉及架构、所有权、系统演进、执行顺序、状态衔接、标识或数值边界时读取；当前运行机制仍以活动权威和实时源为准。

## 架构与所有权

- 时间是统一模拟源和核心运行轴；剧情推进及其他时间相关系统从 `TimeSystem` 派生，具体机制读取系统树、核心模拟和逻辑树的目标章节。
- 所属系统自行完成内部计算、校验、写入、持久化和自动接线；页面及其他调用方只通过公共 API 提供输入并消费结果。
- 代码、文档、日志和目录归入界面树、系统树或逻辑树；核心模拟单列，不建立并行真源。
- 项目运行按公司式金字塔分层：核心模拟回合是总指挥，MOD 是部门，子系统是课/团队，组件是执行个体；上层下达目标并汇总状态，下层拥有业务实现和状态写入权。
- 自动化只承担加载、注册、接线、排队、校验、状态流转、快照和诊断等机械职责；业务判断、业务状态和业务结果仍由所属系统唯一负责。
- 能够稳定描述的节点、所有者、阶段、依赖、顺序、状态码、输入输出和验收条件统一进入公共执行契约；局部差异留在所属活动权威，不复制第二套体系。
- 流程级 `flowId/owner/failureTarget/department/subsystem` 只在 `src/core/execution/execution-flow-registry.ts` 登记；共享执行器负责运行时验证，结构门禁负责发布前验证，二者不另建流程清单。
- 执行诊断的层级读模型由原始事件派生为部门/MOD → 子系统/团队 → 组件节点 → 五阶段；该读模型不拥有业务状态，事故类别、耗时和失败数只能作为诊断指标。

## 执行顺序规则归属

- 多步骤任务、Skill 流程、系统和功能组件的阶段、排序、状态码、故障反馈与结束条件，只以 `D:\AI\AGENTS.md` 的“全局核心理念：显式按序执行”为唯一全局规则，本文件不复制或改写该规则。
- AI 人生模拟器只在所属活动权威和实时源中补充具体流程的节点、业务状态码、依赖、输入输出与所有者；当前共享执行器使用 `prepare -> ready -> execute -> transition -> finalize`，不得改变全局阶段屏障、确定性排序、故障收束或唯一终态要求。

## 迭代与系统演进

- 唯一真源、权责、公共契约、状态模型和生命周期不变时，质量、性能、体验、实现或参数改善属于迭代。
- 改变唯一真源、系统边界、状态模型、公共契约、生命周期、跨系统协作或核心运行轴时属于系统演进；同一任务内明确新所有者和最终稳定态，完成接线、状态收口、旧机制清理与端到端验证。
- 代码项目使用“系统演进”；游戏内角色、世界或社会变化使用“世界演化”。

## 标识与命名

- 详细格式、命名空间和唯一范围只以系统树“标识与命名”为权威。
- 注册、路由、事件、存储、公共契约和持久数据使用机器标识；显示名称可以重复但不能作为机器主键。
- 新建跨系统机器标识先确定所有者和唯一范围；同范围必须唯一，跨范围同名通过命名空间区分，机器标识默认使用 ASCII。
- 生成、注册或启动发现冲突时必须报错，不得静默覆盖、保留首项或无说明去重；现有局部 ID 不因风格统一批量改名。
- 公共或持久标识重命名属于契约或数据变更，只有用户明确要求时执行，不保留旧别名或兼容路径。

## 数值边界

- 除非业务明确需要连续量、比例或概率精度，提交到业务状态、存档、AI 协议或界面的计算结果在所属系统边界四舍五入取整。
- 中间计算保留必要精度；`floor`、`ceil` 或 `trunc` 只按明确业务语义使用，必须保留小数的字段在所属契约中声明精度和显示规则。
