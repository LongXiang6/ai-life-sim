# 数据完整性与禁止截断

任何数据的存储、选择、压缩、传递、容量或限长处理都必须读取。

## 禁止事项

- 禁止任何会减少、丢弃、覆盖或不可恢复改变原始内容的数据截断，包括按字符、字节、Token、固定条数、数组位置、时间窗口、容量或先进先出规则裁剪数据。
- 禁止使用切片、取首尾 N 项、固定最大长度、溢出丢弃、部分保存、部分传输、摘要覆盖源、日志覆盖或清空等方式规避上下文、接口、存储、性能或展示限制。
- 禁止静默省略字段、正文、历史、日志、错误、状态或结构化变更；结构化变更包必须在首次写入前整体校验，不得丢弃无效部分后提交其余部分。
- 压缩、摘要、索引、筛选、分页和窗口只可作为派生视图；源数据必须完整保存、可检索，全部分页或分段必须能够按稳定顺序完整还原。
- 默认只实现当前存档和数据契约；不做向前或向后兼容、旧格式迁移、双读双写、兼容层或未来格式预留，除非用户明确要求。

## 无损处理

- 容量或接口不足时，自动采用分段、分页、流式传输、无损文件轮转、扩大存储或完整归档，不得截断。
- 下游暂时无法接收完整数据时，保留原始数据且不提交不完整结果；没有无损路径时明确报告真实阻塞，不得把截断结果记录为成功。
- 压缩、转换、校验或传输为空、不完整或失败时保留源数据以供重试，不得覆盖完整源。

## 验证

- 检查正常路径及回退路径是否存在用于缩减数据的切片、固定首尾 N 项、最大长度、容量淘汰、过期删除、日志覆盖、清空或部分提交。
- 验证存储、恢复、分页、分段和传输可以保留并重建完整原始内容。
- 路径承载剧情语义时继续运行：

```powershell
node scripts/check/domains/narrative/no-hard-truncation-audit.mjs
```

只追加变更所有者直接需要的检查。
