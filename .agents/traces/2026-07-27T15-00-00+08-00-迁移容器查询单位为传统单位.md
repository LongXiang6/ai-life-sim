# 2026-07-27T15:00:00+08:00 迁移容器查询单位为传统单位

- 触发原因：`文件变更`
- 开始时间：`2026-07-27T15:00:00+08:00`
- 完成时间：`2026-07-27T15:30:00+08:00`
- 任务状态：`完成`
- 用户目标：将所有 CSS 中的容器查询单位（cqw/cqh）替换为传统单位（vw/vh/px/%），消除容器上下文依赖导致的 UI 尺寸不稳定问题

## 根因分析

`cqw/cqh` 相对于最近的 `container-type` 祖先容器计算；MOD 动态页面存在多层容器时，尺寸所有者不直观且容易漂移，因此本任务移除该依赖。

2026-07-27 复核确认，`final-flow` 同时存在两种有效尺寸来源：移动端画布铺满真实视口，桌面端由 `FinalFlowScaleRuntime` 保持固定设计像素后整体缩放。直接把所有 `cqw/cqh` 替换成 `vw/vh` 只适用于移动端，会使桌面内容按浏览器视口放大并脱离设计画布；现已改为由共享画布提供统一横纵尺寸单位。

## 改造策略

- 保留 CSS Modules 和排行榜/邮箱的独立页面样式文件。
- 删除运行时源码中的全部 `container-type`、`cqw` 和 `cqh`。
- `final-flow-design-canvas` 统一拥有 `--final-flow-inline-unit` 与 `--final-flow-block-unit`：桌面端分别映射到四种设计画布的固定像素，移动端通过同优先级媒体覆盖映射为 `1vw/1vh`。
- 保留 `FinalFlowScaleRuntime` 的桌面数值缩放和移动端全屏机制，不再让页面模块直接选择尺寸来源。
