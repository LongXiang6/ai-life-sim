## 根因分析

**问题 1：移动端软键盘吞点击（主要原因）**

- 用户在 textarea 输入文字后，移动端软键盘保持打开状态
- 点击预设选项或确认按钮时，第一次触摸事件被浏览器用于收起键盘，实际 click 事件不触发
- textarea 为空时键盘已收起，点击正常 → 完全吻合用户描述的"有字点不动，没字就能点"

**问题 2：confirmingBranchRef 卡死（次因）**

- `useSimulationBranch.ts` 原始代码中 `confirmingBranchRef` 无超时保护
- 如果 `advanceRound()` 挂起不返回（网络延迟、AI 生成超时等），ref 永远为 `true`
- 后续所有确认点击被 `if (confirmingBranchRef.current) return` 直接拦截
- 无 UI 反馈，用户看到的就是"点不动"

## 变更详情

### 1. NarrativeTimeline.tsx（mod-ui）

- 新增 `branchTextareaRef` 引用 textarea 元素
- 新增 `handleBranchOptionSelect`：点击预设选项前先 `blur()` textarea 收起软键盘
- 新增 `handleBranchConfirmClick`：点击确认按钮前先 `blur()` textarea 收起软键盘
- 预设选项 `<label>` 和 `<input>` 的 onClick/onChange 改为 `handleBranchOptionSelect`
- 确认按钮 onClick 改为 `handleBranchConfirmClick`

### 2. NarrativeTimeline.module.css（mod-ui）

- `.branchCustomInput` 的 `resize: vertical` 改为 `resize: none` — 移除移动端拖拽手柄避免触摸冲突
- 添加 `touch-action: manipulation` — 禁用移动端双击缩放，减少触摸延迟

### 3. useSimulationBranch.ts（mod-pages）

- 新增 `confirmTimerRef` 超时引用
- 新增 `useEffect` 监听 `unresolvedBranchIndex` 变化时重置 `confirmingBranchRef` — 防止上次失败后锁死
- `handleBranchConfirm` 返回类型改为 `Promise<{ ok: boolean; error?: string }>`
- 添加 10 秒安全超时：`advanceRound` 挂起时自动解锁
- 所有失败路径返回具体错误信息（替代原 `console.warn`）
- `advanceRound` 抛异常时 catch 并返回错误信息

### 4. page.tsx（mod-pages）

- 新增 `handleBranchConfirmWithFeedback`：调用 `handleBranchConfirm`，失败时通过 `addToast('warning', ...)` 显示错误
- `onBranchConfirm` prop 改为 `handleBranchConfirmWithFeedback`
