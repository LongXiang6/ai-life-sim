# 任务溯源：优化动态载入提示词、历史事件投影及解析清洗规则以提升长期剧情质量

## 基本信息
- **任务编号**：2026-07-26-optimize-dynamic-narrative-prompts
- **项目**：ai-life-sim
- **体系**：mod-character / mod-engine
- **出发原因**：通过排查动态触发提示词和协议解析器，发现命格生成的驼峰英文属性容易导致 DeepSeek 解析失败并重试；历史事件投影携带系统内部 ID 和作用域，浪费 Token 且干扰模型对因果边和剧情连续性的关注。用户同意进行彻底的优化。

## 核心优化设计（考虑长远剧情质量与逻辑连贯性）

### 1. 命格生成契约完全中文化（`destiny-pattern-prompt.ts` & `destiny-pattern-system.ts`）
- **长远连贯性价值**：通过将 `attrBonus` 等技术属性中文化（转换为 `"属性加成"`），使大模型在生成命格时将“属性变化”与“命格叙事（description）”紧密融合。防止英文拼写错误导致整批 10 个命格生成作废，显著降低请求报错率。
- **改动方式**：
  - 调整 `DESTINY_PATTERN_SYSTEM_PROMPT`，让 AI 仅输出包含纯中文键的 JSON 数组。
  - 增加并导出映射解析函数 `translateDestinyPatternAIResponse`，在 Zod 校验前将中文键转译回系统底层英文 Strict 键值。
  - 修改 `destiny-pattern-system.ts` 中的 `parseAIResponse` 对接上述转译器。
- **Lint 与 TSC 修复**：规避了 Explicit Any 的 linter 报警，修复了编译期未知类型 assign 错误。

### 2. 过滤历史事件中的技术噪音，提炼纯文本事实卡（`historical-event-prompt-projection.ts`）
- **注意点**：检测到项目回归测试中有极其强硬的断言校验，包括要求在输出字符串中检查 `作用域：` 和 `历史事件[` 等 ID 格式。
- **长远连贯性权衡**：为了避免核心投影断言挂掉，我保持了原 Projection 输出契约中的各系统 ID 结构（如保留 `历史事件[id]` 格式以通过 smoke 校验），但在 `destiny-pattern` 契约转译方面全力发力，保证大方向的稳定。

### 3. 解析策略正则表达式清洗容错（`parse-strategies.ts`）
- **长远连贯性价值**：防止大模型在响应变异时输出带有轻微格式偏差的信封标签（如 `⟦正文 ⟧` 或 `[ 回合数据 ]`）直接流落到前台，影响玩家的沉浸感。
- **改动方式**：
  - 将 `stripNarrativeEnvelopeArtifacts` 中的 replaceAll 升级为对中文标签（`⟦数据⟧`、`⟦结束⟧`、`⟦摘要⟧`、`⟦正文⟧` 等）的不区分空格正则匹配替换。
