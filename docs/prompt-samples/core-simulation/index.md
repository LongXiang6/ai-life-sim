# 核心模拟 Prompt 样品索引

## 样品范围

[核心原则1] 每个样品只描述一个 AI 调用的唯一功能、必要输入和必要输出。

[核心原则2] 样品是正式 Prompt 与调用职责的审查基线；运行时只保留与该基线一致的活动职责。

[核心原则3] 01 是故事前调用；03 在正文验收后按现行条件触发，02 只在近期完整正文超过十轮且到达五轮间隔时触发。后调用之间不存在 AI 调用 AI 的依赖。

[核心原则3.5] 开启批量生成时，01 一次最多返回十轮完整故事；遇到命运分支、结局或人生阶段结束即在该轮停止，该轮为本批最后一项，不足十轮是正常结果。调用时限随目标轮数放大；传输被截断时只回收完整前项。玩家每次推进仍只发布并结算一轮。

[核心原则4] 01 的固定规则与动态数据由服务端合成一条 `user` 消息，顺序为角色/输入/写法/输出规则在前、五段数据在后；当前资产版本为 `10.0.0`；主故事资产不携带故事示例矩阵；动态数据层使用可由 `JSON.parse` 解析的五元素数组；02 与 03 的固定 Prompt 与直接产品继续使用各自声明的 JSON 协议。

[核心原则4.5] 控制平面只投影事件卡池的卡名；主故事在 `事件卡消费` 中列出本轮实际采用并写入正文的卡名，未消费卡留在池中，引擎按名扣卡。卡池不设空手概率，也不由本地抽固定张数。

[核心原则5] 01 不设置默认字数、事件数量、重大变化、阶段推进或宏观编年配额。正文按本次信息.篇幅偏好写，允许概括、跳跃和留白；正文像人生小说的一章，不是因果报告、提纲、规则解释或事件清单。01 的受保护固定资产不携带九个示例或其他故事示例；02 与 03 也不带这些示例。已有保存的有效正文篇幅偏好保持不变。

## 正常建局共享基线

[核心原则1] 四份样品使用同一局已经完成世界选择、世界配置、角色创建、四槽命格选择、属性分配和命运预览的事实；共享基线证明上游信息完整，每个调用仍只接收完成自身职责所需的投影。

| 来源步骤 | 已确认信息 | 本组样品值 |
|---|---|---|
| 世界选择与配置 | 名称、描述、空间形态、世界观本质、力量体系、力量边界、文明阶段、挑战取向、节庆范围 | 雾潮群岛；位面；唯物修仙；潮汐劲有限体系；海贸城邦；合理挑战、行动可因条件不足失败；中国节庆 |
| 世界初始化 | 历法、当前区域、世界规则、气候、主要资源、力量进度、世界阶位、瓶颈、训练天赋 | 潮历；赤潮矿寨；湿冷多雾；赤铁砂与盐晶；潮汐劲进度 22；凡俗二阶；瓶颈 40；潮息训练 |
| 角色创建 | 姓名、性别、种族、种族规则、背景、起始年龄、当前年龄、预期寿命 | 岑澜；女；潮裔；18 岁开始；当前 19 岁；预期寿命 150 年；矿寨测潮学徒兼浅海潜水员 |
| 属性分配与修正 | 四项基础值、命格与种族修正、当前有效值、气运 | 基础值体魄 4、心智 4、悟性 4、魅力 3；修正后当前值 6、6、5、4；气运 4 |
| 四个携带槽 | 普通命格与轮回天赋的类型、类别、资质阶位、开发阶段、当前效果和完整属性加成 | 听潮辨隙、耐压持息、守约成章、轮回天赋灰烬回响 |
| 模拟设置 | 叙事风格、时间步长、正文篇幅、模型条件 | 写实冒险；按轮次切换日/月/季度/年；正文目标随跨度变化；DeepSeek v4 flash、关闭 thinking、非流式 |

[主要规则1] 01 最终只接收一条 `user` 消息，固定规则由服务端受保护资产 `src/mods/mod-engine/server/narrative-system-prompt.ts` 维护，动态数据依次为 `世界`、`玩家信息`、`历史输出`、`玩家本次点属性`、`本次信息`；模型在当前时间跨度内自主安排故事节奏和经历数量，输出正文、属性、命运分支、结局、角色死亡，可选事件卡消费和天赋表现线索，应用只消费正文、分支、属性和结局。事件卡消费只用于本地扣卡，未消费卡留在池中。天赋表现线索只含引用和可观察结果，`来源回合` 由引擎按本轮记录，不由模型输出。02 依次接收 `历史剧情`、`待压缩五轮正文` 和 `压缩范围` 三条标准 JSON，输出带来源回合的 `本轮剧情` 与 `未来事件`；03 先由程序筛年龄、证据窗口、冷却、开发阶段和次数，再接收可推进开发阶段的天赋候选及现有历史记忆、最近两轮详细记忆、角色上下文、世界上下文和成长历史。

[主要规则2] 长轮次测试从该基线开始，每轮执行 01，并按条件执行 02/03；02 每次把连续五轮形成的剧情与未来事件交给各自所有者，03 中玩家选定的合法成长路线按所属系统进入后续输入。测试写入独立产物目录，不接入正式运行状态。

## 最小充分原则

[核心原则1] 先用一句话写清调用的唯一功能，再从该功能反推必要输入和必要输出。

[核心原则2] 每个字段必须能够回答：删除它后，哪个必要结果将无法产生；无法回答时删除该字段。

[核心原则3] AI 只接收业务事实；上下文编号、目标编号、路由、状态写入、数值钳制、去重和其他本地可计算内容由本地程序负责。

[核心原则4] 只有同一触发点、共享主要事实、可以组成一个严格结果包且不形成前后依赖的职责才合并为一次调用。

[核心原则5] 已发布正文是两个后调用共同的事实来源；02 一次读取连续五轮完整正文并输出带来源回合的长期剧情与未来事件，03 保留现有成长字段并读取其证据窗口。

[核心原则6] 02 的本轮剧情与未来事件分别表示已经发生和尚未发生的时间轴事实；03 不改变资质，只推进开发阶段，保留属性、证据窗口、角色/世界上下文、输出、解析和本地成长字段。角色数值分析、道德字段与其他重复状态 AI 不进入后调用。

[核心原则6a] 02 与 03 的正式 Prompt 只保留抽象字段、规则和输出形状；本组样品的动态消息使用同一局离线审查数据，不把样品人物、日期、剧情、路线、能力、属性或成品结果写入固定资产。

[核心原则7] 动态剧情阶段及剧情引导 AI 已从样品集合移除；故事 AI 根据世界、玩家信息、历史输出、玩家本次点属性与本次信息生成新的人生事件，并在同次响应中输出正文、属性、命运分支和结局。

## 统一固定 Prompt 结构

[核心原则1] API 模型只接收当前请求；每个固定 Prompt 资产先声明本次调用的任务身份和一句唯一目标，不假设模型知道项目、MOD 或调用链。01 由服务端合成单条 `user` 消息，其他调用按各自协议使用固定资产。

[核心原则2] 固定键按 `身份`、`目标`、`输入映射`、执行或条件规则、`输出契约` 排列，没有实际职责的键省略。

[核心原则3] 互斥结果使用 `如果`、`则`、`否则如果`、`否则`；输出媒介、形状、字段和互斥关系只声明一次。

[核心原则4] 身份名称直接描述产物且能自足说明任务边界；即使使用“小说模拟器”等文体取向身份，也必须同步写清场景、人物行动、因果和事实边界，不能假定身份名称单独就能带来目标文风，也不能假定模型知道项目、架构或调用链。

[核心原则5] JSON 结构中的键和值保持标准双引号和标准转义；只有不承担结构或示范作用的正文强调引号可以删除。缓存命中依赖稳定消息前缀，不因删除双引号自动提高。

## 合并边界

[主要规则1] 故事压缩与未来事件提取都从待压缩的连续五轮正文形成时间轴事实，合并为故事连续性提取；历史内容只用于连续性确认，待压缩五轮是唯一新输出来源。

[主要规则2] 天赋成长包含长期证据判断和三个候选方向生成，继续独立；它不从其他后调用接收成长信号，也不阻塞其他后调用开始。

[次要规则1] 技能、能力、知识技术、文化、经济、人口和一般世界变化由正文与连续记忆维持，不为它们建立重复状态结果。

[次要规则2] 独立调用增加的 Token、失败概率和等待时间必须由不可替代的结果证明；合并也必须保持唯一目标、严格输出和本地所有权边界。
