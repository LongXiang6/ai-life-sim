# 故事 AI Prompt 样品

## 样品范围

[核心原则1] 浏览器只发送动态数据；服务端受保护资产 `src/mods/mod-engine/server/narrative-system-prompt.ts` 把固定规则与动态数据合成为模型实际接收的一条 `user` 消息。当前资产版本为 `10.0.0`。

[核心原则2] 动态数据严格使用五元素数组，字段依次为 `世界`、`玩家信息`、`历史输出`、`玩家本次点属性`、`本次信息`；实际时间窗口、称呼、文风和控制平面放在现有 `本次信息` 内，不增加顶层元素。

[核心原则3] 固定消息顺序为：`# 角色`、`# 输入`、`# 写法`、`# 输出`，随后是五段只读数据。主故事资产不携带故事示例矩阵，也不在数据之后追加规则。

[核心原则4] `历史输出.事件`来自既有历史投影；所有未压缩轮次直接投影该轮完整正文与发生年龄，不拆分或优先投影结构化事件结果，也不用末句或结局评语替代整轮记录。压缩轮次沿用记忆所有者的事实投影，不新增第二世界状态源。模型只继承人物、关系、资源、身份和未解决方向，不继承旧正文的焦点、结构或措辞。

[核心原则5] 模型输出最小 JSON：`正文`、`属性`、`命运分支`、`结局`、`角色死亡`，可选 `事件卡消费`、`天赋表现线索`，不强制工具调用；应用只消费正文、命运分支、属性和结局。`事件卡消费`只列本轮实际采用并写入正文的卡名；`天赋表现线索`只含不透明天赋引用和 `可观察结果`，来源回合由引擎记录。

[核心原则6] 主身份是人生模拟器。正文写这一段时间里真正发生在角色身上的事：日常、关系、选择、代价、变化。角色是中心：他是谁、此刻想要什么、怕失去什么、与谁有关系、手上有什么。允许概括、跳跃、留白；正文像人生小说的一章，不是因果报告、提纲、规则解释或事件清单。玩家计划与自定义输入是 Attempt，主叙事自然回应但不保证成功。难度只以隐藏命运指引及事件卡相对权重影响故事倾向，不作为角色属性或世界中的真实力量。世界规则、既定事实、玩家能力及行动因果共同约束裁决。

## 时间跨度与正文篇幅

不设置默认字数、事件数量、重大变化、阶段推进或宏观编年配额。模型按本次信息.篇幅偏好写正文；日、月、季、一年或更长跨度都由角色处境自然决定节奏。需要压缩跨度时用转场、概述和留白，不逐日列清单，也不把单一现场强行扩写成整年。篇幅偏好是宽松参考，不是精确截断线。

## 发送顺序

模型只接收一条由服务端受保护主故事资产组装的 `user` 消息，不接收独立主故事 `system` 消息。固定规则在前，五段只读数据在后；模型在一次调用内读取世界、历史、角色和本次条件，写出正文并返回最小协议对象。

## 标准输出

```json
{
  "正文": "你在潮湿的春末接下外海航线图。议会给的条件不算宽厚：三个月内测出可用的避礁水道，否则领航资格收回。你沿着旧码头走访老船主，把听来的潮声一段段记在木板上。第一次出航遇到逆风，船队被迫在无名礁湾停了两日；你没有硬闯，而是趁退潮重新测深浅，找出了一条更窄却稳定的水道。回港时，议会没有立刻兑现全部报酬，只先恢复你的勘定权。你把那块写满潮声的木板上交，心里明白这条航线还没有真正属于你。",
  "属性": {
    "心智": 4,
    "财富": 3
  },
  "命运分支": [
    "接受议会的长期勘定契约",
    "把航线图卖给商会，换一笔现钱",
    "暂时离开港城，沿外海继续寻找更安全的航道"
  ],
  "结局": false,
  "角色死亡": false,
  "事件卡消费": ["风口失约"],
  "天赋表现线索": [
    {
      "引用": "命格-1",
      "可观察结果": "你在无名礁湾听出退潮时的异常回响，避开了暗礁。"
    }
  ]
}
```

`属性`只写发生持续变化的项，填结算后的当前值；未变化项可省略。人生尚未形成分支时，`"命运分支": false`；人生未结束时 `"结局": false`。`命运分支`非空时为 2 至 4 个字符串；`结局`为恰好四个汉字；`角色死亡`为 false 或 `{死因类型, 死因}`，明确死亡必须同时有结局且没有命运分支。`事件卡消费`只列本轮实际采用并写入正文的卡名；未消费卡留在卡池中，由引擎按名扣卡。`天赋表现线索`只记录玩家实际使用命格后留下的可观察结果；来源回合由引擎按本轮记录，不由模型输出。

## 批量输出

批量时顶层返回 `故事批次` 数组，一次最多返回 10 轮；遇到命运分支、结局或人生阶段结束时停止，该轮即本批最后一项。每项都是完整故事对象，不写摘要；不足 10 轮是正常结果。
