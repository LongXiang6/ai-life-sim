# 第一层：玩家表层

## 产品主线

玩家从欢迎界面进入一段新人生，依次选择或创作世界、建立角色、选择命格、分配属性、确认命运，然后在核心故事界面推进人生，最终进入结算并开始下一世。

1. **欢迎界面**：展示产品主体入口，提供开始新人生、继续已有进度以及设置、说明、排行榜、邮箱等附属入口。
2. **世界选择界面**：让玩家从已有世界中选择，或填写自定义世界名称与描述；确认后直接建立本局本地世界并进入角色创建。
3. **角色创建界面**：让玩家定义角色姓名、身份、背景、起始年龄和寿命范围等角色开局选项。
4. **命格界面**：让玩家从候选命格中完成选择，并区分本局普通命格与跨局轮回天赋。
5. **属性分配界面**：让玩家确认本局起始基础属性。
6. **命运预览界面**：汇总已经确认的世界、角色、命格与属性，作为进入模拟前的最后确认。
7. **核心故事界面**：展示已经生成的故事、时间、角色状态、分支选择与推进操作。正文收到并通过协议后立即进入阅读区，后续分析继续完成本轮附加结果。
8. **人生结算界面**：展示人生评分、评语、诗句、重要经历、轮回结果和下一段人生入口。

## 附属界面

- **设置**调整阅读、叙事和玩家自有模型配置。
- **说明**介绍游戏流程、更新记录和关联项目。
- **排行榜**展示符合条件的优秀人生记录。
- **邮箱**承载站内消息与可转移轮回天赋。
- **账号**管理可选登录、云端数据和账号内容。
- **存档管理**保存、读取和管理本地人生。
- **反馈**提交问题并提供可关联诊断编号。

## 统一布局

- 所有稳定玩家界面使用同一个共享主体宽度，不按页面建立不同的桌面宽度特例。
- 桌面视口中的主体使用统一的 `74rem` 宽度上限，视口两侧各保留 `20px` 外边距；宽度由共享外壳一次计算，嵌套内容不重复扣减边距。移动视口占满可用宽度。
- 统一的是页面主体板块，按钮、表单、卡片、提示框和对话框继续按各自内容与交互需要保持合理宽度。
- 主流程页面共享章节化阅读骨架：顶部保留品牌与当前步骤，正文使用连续纸页式内容区，底部保留当前步骤的主操作和返回操作；附属页面沿用同一骨架，但不伪造主流程进度。
- 创建步骤分别展示世界、角色、抽取、选择、属性、命运与故事七步，与既有页面阶段一致；步骤仅指示当前进度，不增加跳转入口。
- 页面信息按“当前上下文 → 核心内容 → 次级细节 → 当前可执行操作”排序；状态、错误和等待信息就地展示，不以装饰性面板遮挡主要内容。
- 桌面端允许主流程使用目录或辅助信息栏提升扫描效率，移动端自动收束为单列阅读；所有固定操作区必须为滚动正文预留可达空间。
- 页面文字与交互控件保持可持续阅读的层级：正文和主要控件不因视口缩小而降到不可辨认的字号，辅助信息仍须可读；键盘焦点覆盖当前页面的所有现有操作，独立页面不套用弹窗的模态焦点边界。
- 主题只改变色彩语义，不降低文字、选中态、禁用态和焦点态的可辨认性；设置页面按外观、叙事、模型与数据任务组织，数据危险操作与即时生效状态就地说明。

## 统一配色

- 阅读主题保持低饱和淡黄色底色；多彩主题以纯白为整体背景，并提供鲜艳、明亮且对比鲜明的赤橙黄绿青蓝紫可选强调色，暗夜主题使用低亮度深色层次，白色主题以中性白色为主体并使用低饱和雾青强调色。多彩主题的高饱和色可按界面需要用于主要操作、选中态、分类面和必要的语义背景，不要求全部同时出现，仍须保持文字对比、层级清晰和正文可读，不用渐变铺满正文底色。
- 辅助边框只负责区分层次，使用低对比度暖灰；辅助文字和图标使用中性暖灰，不以深黄作为常规说明色。
- 主要操作、错误、成功、警告、稀有度和分类可以使用必要语义色；阅读主题提供克制的辅助色，多彩主题提供赤橙黄绿青蓝紫七组鲜艳可选辅助色。多彩辅助色允许形成清晰可辨的色块与边界，但不能用强渐变覆盖正文或牺牲文字对比。
- 页面视觉基线采用样例中的纸页、细线、章节索引和少量语义色，但不复制样例的独立状态机、数据模型或业务判断；各页面继续消费所属系统提供的公开状态和动作。
