# 调用隔离与缓存

## 目标

调用隔离让不同职责的 AI 请求保持独立上下文归属，同时让同一职责的稳定前缀持续复用。

## 结果

- 主叙事、故事连续性提取、天赋成长和条件式事件卡池各自拥有独立调用池。
- 同一可信主体与同一调用池形成稳定上游身份。
- 不同调用池形成不同上游身份。
- 批量故事复用主叙事调用池和同一次请求，不创建独立调用或预生成路径。开启时请求最多十轮有序完整结果，遇命运分支、结局或阶段结束即停；当前项立即发布，后续项由引擎状态持久保存并在每次玩家推进时消费一轮。
- 批次队列与所属人生的故事历史、时间、模型和叙事设置一起保存；新人生或会改变后续结果的玩家输入、步长、模型/叙事设置变化及分支或结局会清除队列。读取存档时只恢复该存档携带的批次，不从当前另一局继承队列。
- 缓存命中影响等待和费用，不改变故事或业务结果。
- 主故事由服务端受保护资产 `src/mods/mod-engine/server/narrative-system-prompt.ts` 把固定规则与五段动态数据合成为一条 `user` 消息，不发送独立 `system` 消息；批量请求与普通请求都使用同一最终消息契约。
- 连续性提取固定按历史剧情、当前来源回合之前最多四轮的近期正文、当前回合发送三条 JSON 用户消息，合计形成五轮详细窗口；天赋成长固定按历史记忆、最近两轮详细记忆、程序筛选后的玩家已选天赋发送三条 JSON 用户消息，第三条可包含成长历史、角色上下文和世界上下文。
- 标准 JSON 的双引号是格式契约的一部分；删除非结构性强调引号可以减少少量冷输入 Token，但不会单独提高缓存命中。

## 最大边界

缓存归属来自主叙事、故事连续性、天赋成长和条件式事件卡池四个已登记调用职责。批量故事是主叙事的一次有序结果，不建立新的调用池；条件式事件卡池只按世界、人生阶段和玩家意图缓存整池卡名（名称、正负、权重），不缓存玩家已发生事实。旧世界数值模拟不恢复为缓存状态源。会话编号、回合编号和随机值不改变长期调用池身份。
