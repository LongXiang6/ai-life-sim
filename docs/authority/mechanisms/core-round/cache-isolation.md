# 调用隔离与缓存

## 目标

调用隔离让不同职责的 AI 请求保持独立上下文归属，同时让同一职责的稳定前缀持续复用。

## 结果

- 主叙事、故事连续性提取和天赋成长各自拥有独立调用池。
- 同一可信主体与同一调用池形成稳定上游身份。
- 不同调用池形成不同上游身份。
- 主叙事正式调用与下一轮正文预生成共享主叙事调用池及稳定前缀，但分别标记为正式执行和预览执行；预览调用计入真实费用，不进入正式回合正文归档或等待统计。
- 下一轮正文只保存在 `mod-engine` 的瞬态单槽。真实下一轮主故事请求的完整指纹与预生成请求完全一致时消费一次；任何输入差异都使该结果失效并回到正式调用。
- 缓存命中影响等待和费用，不改变故事或业务结果。
- 主故事固定系统 Prompt 后只发送一条四元素数据层用户消息：世界、玩家信息、剧情和同时包含玩家属性与当前信息的末项。
- 连续性提取固定按历史剧情、当前来源回合之前最多四轮的近期正文、当前回合发送三条 JSON 用户消息，合计形成五轮详细窗口；天赋成长固定按历史记忆、最近两轮详细记忆、程序筛选后的玩家已选天赋发送三条 JSON 用户消息，第三条可包含成长历史、角色上下文和世界上下文。
- 标准 JSON 的双引号是格式契约的一部分；删除非结构性强调引号可以减少少量冷输入 Token，但不会单独提高缓存命中。

## 最大边界

缓存归属来自三个已登记调用职责。下一轮预生成不是第四种业务职责，只是主叙事的提前执行，不建立新的调用池或持久化结果源；旧世界模拟、事件库、事件生命周期注入和候选投递均不保留缓存别名、汇总归属或兼容映射。会话编号、回合编号和随机值不改变长期调用池身份。
