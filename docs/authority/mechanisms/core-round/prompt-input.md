# 主叙事输入区

## 职责边界

故事 AI 使用指定的单时间节点叙事系统 Prompt，根据世界、玩家、历史事件上下文、本节点属性和当前时间节点生成一条世界内事件叙事。固定 Prompt 只生成当前节点，不跨时间、不总结一生、不输出多条；历史事件上下文是按时间升序排列的只读节点事件序列，用于前情和防重复；当前节点不得以任何形式重复历史内容，可以承接历史因果或生成新触发事件；事件必须局部因果闭合并依赖全局上下文，不包含时间锚点，且体现宏观跨度或为全新的离散化独立事件。世界观与题材是只读全局约束；玩家信息提供角色身份、天赋技能和当前属性。固定 Prompt 不拥有世界、角色、记忆、属性或回合状态；动态数据只由各所属系统做只读投影。

主故事不再强制工具调用或 JSON 输出。模型按固定 Prompt 返回人生重开文本：状态行、`正文`、`命运分支`、`结局`。正文按开篇事件定论、中间承接回响和结尾收束余波组织。状态行只包含年龄、心智、体魄、魅力和家境；结局对象包含四字评语与最终总结。本地解析器从同一次响应中识别可用正文以及可选分支、结局和状态行；显式 `正文` 字段只发布字符串值本体，不包含 JSON 引号、字段间逗号或其他协议标点。正文存在时，不因未使用字段写成 `false`、字段标点差异、固定 Prompt 中的简写对象语法或缺少正文字段标签而丢弃正文，缺少标签时只在状态行后的正文及结束边界能够唯一识别的情况下恢复。响应以完整状态行开头时，状态行只作为协议元数据，不进入玩家正文；其后的带引号或不带引号正文均可恢复，后续可选分支或结局沿用既有解析。

## 固定顺序

1. 服务端注入 `D:/AI/docs/系统prompt.txt` 对应的固定系统 Prompt。
2. 浏览器发送一条可由 `JSON.parse` 直接解析的用户消息。

用户消息是一个 JSON 对象，顶层字段顺序固定为：

1. `世界`
2. `玩家信息`
3. `历史事件上下文`
4. `玩家本节点属性`
5. `本节点信息`

对象外不添加标签、说明或第二条动态消息。

## 数据层

- `世界` 只含 `名称`、`描述`。
- `玩家信息` 只含 `姓名`、`性别`、`种族`、`背景`、`天赋技能`；天赋技能按“名称：效果”字符串数组投影。
- `历史事件上下文` 只含 `节点事件`，按时间顺序合并故事连续性已经压缩的事实字符串与仍处于近期窗口的完整正文。
- `玩家本节点属性` 只含 `心智`、`体魄`、`魅力`、`家境`，值均为整数字符串，顺序固定。四项都来自角色基础属性所有者的当前值只读投影。
- `本节点信息` 只含 `时间节点`、`命运抉择`。时间节点同时表达当前年龄和当前历法标签；命运抉择只写本轮玩家已确认行动，没有明确行动时为空字符串，不追加系统引导、时间参考、世界事实、事件候选、到期事项或任何兜底语义。

示例中的具体世界、角色、历史和选择只说明字段形状，不进入固定 Prompt，也不写入运行状态。

## 记忆边界

故事连续性调用一次处理连续五轮完整正文。近期正文超过十轮且到达五轮调用间隔时，最早五轮形成长期记忆投影；原始正文仍完整保存，失败时不删除来源正文。主故事只消费当前长期记忆投影与仍处于近期窗口的完整正文，不接收重复的阶段、伏笔、因果或分析副本。

## 输出边界

每次主故事调用必须提供可用正文。命运分支与结局互斥：仅在命运级事件中给出三个具体、互斥且符合世界观的字符串选项，上一节点已选命运作为输入上下文，本次输出不得复述旧选择；固定 Prompt 的判定规则要求未触发分支时输出 `null`，输出示例仍保留 `false`，本地解析器按现有宽松协议消费两者；结局使用包含四字评语和最终总结的对象。状态行中的心智、体魄、魅力和家境是 AI 报告的本轮结果值，本地只把能够相对当前角色数值换算且符合单轮变化范围的差值交给 `character-base` 校验、钳制和持久化；年龄不建立新的 AI 状态所有权。

## 最大边界

主故事只拥有玩家可见正文、可选命运分支、可选结局和本轮属性结果声明，不拥有状态写入。页面消费解析后的公开结果，不自行解析 AI 原文。属性、年龄、历史、未来事件和记忆压缩仍由原所属系统管理。
