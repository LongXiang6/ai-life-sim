# 主叙事输入区

## 职责边界

故事 AI 使用指定的离散化人生事件模拟系统 Prompt，根据世界观、玩家状态、历史记忆、本节点属性和当前节点，重新采样本节点最值得记录的一件重要事件及其结果。程序确定时间节点，AI 只处理当前节点；状态连续而事件离散，每个节点都是新的事件单元。历史只保持状态一致性，不受上一事件剧情方向支配；已有事实和真实后果可以延续，但不得拆分同一事件、延续同一场景或逐步推进同一行动。世界独立运行，事件只保留具有实际意义的变化，忽略无意义日常与自然成长，也不得为了填充节点制造轻微变化。世界观与题材是只读全局约束；玩家信息提供角色身份、天赋技能和当前属性。固定 Prompt 不拥有世界、角色、记忆、属性或回合状态；动态数据只由各所属系统做只读投影。

主故事不强制工具调用，模型按固定 Prompt 返回标准 JSON 对象，顶层依次包含年龄、心智、体魄、魅力、家境、`正文`、`命运分支`、`结局`。正文以事件事实和结果为中心，少写过程、对白、心理和无意义场景细节，并避免即时场景推进和明确时间锚点。年龄与四项属性为字符串；命运分支为 `null` 或三个字符串数组，结局为 `null` 或 `[四字评语, 最终总结]`，分支和结局互斥。本地解析器从同一次响应中识别正文以及可选分支、结局和顶层属性；显式 `正文` 字段只发布字符串值本体，不包含 JSON 引号、字段间逗号或其他协议标点。正文存在时，不因未触发字段写法、字段标点差异或对象外层包装而丢弃正文。

## 固定顺序

1. 服务端注入 `D:/AI/docs/系统prompt.txt` 对应的固定系统 Prompt。
2. 浏览器发送一条可由 `JSON.parse` 直接解析的用户消息。

用户消息是一个 JSON 对象，顶层字段顺序固定为：

1. `世界`
2. `玩家信息`
3. `历史事件上下文`
4. `玩家本节点属性`
5. `本节点信息`

对象外不添加标签、说明或第二条动态消息。

## 数据层

- `世界` 只含 `名称`、`描述`。
- `玩家信息` 只含 `姓名`、`性别`、`种族`、`背景`、`天赋技能`；天赋技能按“名称：效果”字符串数组投影。
- `历史事件上下文` 只含 `节点事件`，按时间顺序合并故事连续性已经压缩的事实字符串与仍处于近期窗口的完整正文。
- `玩家本节点属性` 只含 `心智`、`体魄`、`魅力`、`家境`，值均为整数字符串，顺序固定。四项都来自角色基础属性所有者的当前值只读投影。
- `本节点信息` 只含 `时间节点`、`当前状态`。时间节点同时表达当前年龄和当前历法标签，按 `年龄·历法` 连接；当前状态只写现有唯一玩家确认行动投影，没有明确行动时为空字符串，不追加系统引导、时间参考、世界事实、事件候选、到期事项或任何兜底语义。

示例中的具体世界、角色、历史和选择只说明字段形状，不进入固定 Prompt，也不写入运行状态。

## 记忆边界

故事连续性调用一次处理连续五轮完整正文。近期正文超过十轮且到达五轮调用间隔时，最早五轮形成长期记忆投影；原始正文仍完整保存，失败时不删除来源正文。主故事只消费当前长期记忆投影与仍处于近期窗口的完整正文，不接收重复的阶段、伏笔、因果或分析副本。

## 输出边界

每次主故事调用必须提供可用正文。命运分支与结局互斥：仅在命运级事件中给出三个具体、互斥且符合世界观的字符串选项，上一节点已选命运作为输入上下文，本次输出不得复述旧选择；未触发分支或结局时均输出 `null`，本地解析器继续把历史 `[false]` 与 `null` 都消费为未触发；结局触发时为 `[四字评语, 最终总结]`。JSON 顶层的心智、体魄、魅力和家境是 AI 报告的本轮结果值，本地只把能够相对当前角色数值换算且符合单轮变化范围的差值交给 `character-base` 校验、钳制和持久化；年龄不建立新的 AI 状态所有权。

## 最大边界

主故事只拥有玩家可见正文、可选命运分支、可选结局和本轮属性结果声明，不拥有状态写入。页面消费解析后的公开结果，不自行解析 AI 原文。属性、年龄、历史、未来事件和记忆压缩仍由原所属系统管理。
