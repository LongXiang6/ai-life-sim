# 事件轮次时间机制

## 目标

时间机制以自然年为基础，把一年抽象为 1000 个基础时间点；玩家每次推进消费一个故事事件轮次，事件数量决定本轮消费的点数。日、月、季不再是玩家可选的微观推进单位。

## 结果

- 新人生与引擎重置的默认推进步长为 `year:1`（一年）；这是 `mod-engine` 的默认配置，不改变事件模式的年度预算 `DEFAULT_ANNUAL_EVENT_COUNT=12`。用户手动选择的步长和存档中已保存的显式步长继续按原值恢复。
- 每个自然年冻结一个事件预算 `N`（`1 ≤ N ≤ 1000`）；第 `k` 个事件轮次的本轮基础点由相邻累计边界取整之差确定：`floor(k×1000/N)-floor((k-1)×1000/N)`，全年严格合计 1000 点，单轮允许 ±1 的分配差异。
- 事件轮次由本地推进计数决定，不由 AI 正文或状态提取输出的事件条数决定。
- 年度节点位置、剩余节点和基础点增量作为本轮事实投影给故事 AI；日期只作为派生显示或期限校验。
- 业务系统统一消费 `basePointsPassed` / `totalBasePoints`；`totalDays` 仅作为由基础点派生的日历兼容字段。
- 世界事件候选在事件轮次推进后由本地事件库按分类、条件、强度和冷却选择；故事 AI 只决定如何合理采用并叙述，不直接写入状态。

## 最大边界

事件预算决定时间分配，不预先决定具体剧情。`year:Y` 作为宏观快进时一次推进 `Y×1000` 基础点并生成一轮概览故事；不展开为 `Y×N` 次 AI 调用。旧存档迁移保留原 `totalDays` 快照，并按新基准重建基础点，不把天数直接改名为事件轮次。
