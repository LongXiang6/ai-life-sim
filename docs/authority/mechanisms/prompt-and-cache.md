# Prompt 与缓存机制

## 目标

Prompt 机制把固定职责、慢变事实、故事历史和本轮条件组成稳定、可理解的 AI 输入。

## 结果

- 主故事固定资产逐字采用 `D:/AI/docs/prompt.txt` 的规则与顺序，当前资产版本为 `9.15.0`。代码区块先定义世界演化与事件裁决身份及核心产物，中段集中提供五段只读数据，后段按事实恢复、世界局面、离散事件、玩家参与与结果裁决、正文压缩、结算和 JSON 顺序执行。身份与意图权限遵循[主叙事输入区](core-round/prompt-input.md)，不新增独立状态或调用。服务端合成唯一一条 `user` 消息；主故事不发送独立 `system` 消息。每次请求都是独立调用，模型只能依据这条组装消息生成结果，不拥有调用外上下文或全局信息。
- 浏览器只发送动态数据与受保护资产编号，固定规则不下发客户端；故事连续性与天赋成长调用保持各自现有消息角色和资产职责。
- 主故事动态数据使用可由 `JSON.parse` 直接解析的五元素数组；服务端把各元素填入固定规则的对应位置，运行时不追加示例人物、世界、历史或成品正文。
- 固定 Prompt 与需要机器识别的动态 JSON 保持标准双引号和标准转义；只删除不承担结构、语义或输出示范职责的强调引号。缓存命中取决于消息与字节前缀稳定，不因删除双引号自动提高。
- 条件结果使用明确的“如果、则、否则如果、否则”关系；输出形状、字段类型和互斥关系只声明一次。
- 主故事输出使用固定 Prompt 声明的完整 JSON 对象，依次为时间定位、事件结果、正文、命运分支、属性和结局，不强制工具调用。时间定位只作本轮索引；事件结果的`事件`保存本轮事件身份，`成因`、`结果`、`影响`保存已成立事实，提交后由同一条叙事历史记录保存并投影到下一轮输入，不直接展示、不成为持久世界状态。应用仍只消费正文、分支、属性和结局；日志仍完整保留原始响应。随机故事生成、正文表达与事件结果生命周期遵循[核心模拟](../core-simulation.md)及[主叙事输入区](core-round/prompt-input.md)的唯一结果契约。
- 主故事解析先识别正文，再独立识别财富等属性、分支与结局；属性当前值相对输入换算后由既有状态所有者处理。正文存在时，坏的其他字段、字段写法或协议标点差异不得牵连同一响应中的可用正文；只有最低可用正文完全不存在时才失败，不从解析恢复中生成故事事实。
- 故事正文以单个 JSON 字符串承载；全部段落保持在同一字符串内，需要换行时使用标准 `\n` 转义，不把段落拆成相邻字符串或额外字段。正文是当前现实条件下重新选题并推演结果的广角人生记录；世界与个人生活都可发起事件，历史约束事实，玩家条件改变参与方式和结果。正文涉及玩家时使用第二人称，姓名只作输入标识；坐标时间只作内部定位，相对时距可在因果确有需要时出现。
- 正文段落按模型返回的换行保留，不由渲染器改造成固定行数或固定换行节奏；故事生成、结果结算、表达和时间结构要求只以固定 Prompt 原文为准。
- 核心模拟的单个正式回合固定消费一个主故事结果。天赋成长按现行条件执行；故事连续性只在近期完整正文超过十轮且到达五轮间隔时调用，一次压缩最早连续五轮。开启下一轮预生成时，只等待本轮实际启动的后调用完成，不提前执行下一回合的后调用。
- 正式替换前的共享审查基线沿正常创建流程包含世界名称与描述、历法与叙事风格，主角姓名、性别、种族、背景、起始年龄、寿命，心智、体魄、魅力、财富四项基础值、修正值与当前值，以及四个携带槽中的普通命格和轮回天赋；每个调用只接收完成自身职责所需的投影，不重复发送整份基线。
- 连续审查把已确认的本轮剧情、未来事件、结构化事件结果和玩家选定成长路线投影应用到下一轮输入，用同一角色和世界验证长期连续性；测试数据不写入正式运行状态。
- 连续性提取先保留近期完整正文退出其自身处理窗口后仍需成立的最终状态、持续关系、关键发现、承诺和未解决结果；同一回合中已经被后续最终结果完整覆盖且没有独立影响的中间动作、复测和阶段结果不再保留，同一因果阶段合并表达，不设置固定条数上限。该提取结果不再进入主故事输入。
- 连续性提取一次输出五轮批次中各来源回合的时间、剧情和权重，权重只服务于 02 的记忆职责。主故事 `历史输出.事件`由叙事历史所有者优先投影所有已有结构化事件结果；只有没有结构化结果的旧记录才回退到完整正文，不让旧正文的段落、转场和文风重新成为选题模板。不新增第二个历史状态源或额外提取调用。原始正文与事件结果仍由历史所有者完整保存，历史年龄索引不进入新正文。历史使本轮变化与既定事实相容，本轮焦点由世界可能性、当前条件和随机性重新形成，旧主题只作为背景事实而非续写入口。
- 未来事件只接收正文已经给出具体日期、明确历法周期或可从当前绝对时间唯一计算的事项；“某事发生前后”“下次处理时”等没有排期的条件继续作为连续性事实，不伪造为当前回合结束之后的绝对时间。未来事件逐条识别、逐条去重和逐条登记，单条无法换算时放弃该条，其余合法事项继续使用；本轮剧情不因未来事件异常而丢弃。
- 解析器红线：除非最低可用产品绝对不存在，不得使用严格 Schema、未知字段、字段顺序或整包严格判定阻断响应；不得增加格式修复请求、重试、备用模型或旁路兼容层。
- 命格抽取的五类首批调用分别只接收行动、认知、表达、经营或杂类一个方向，每次目标四条普通命格；五类调用完成后才发布选择页。选择页发布后按分类继续补充至每类十二条，候选逐条合并并由命格池缓存按世界与 Prompt 版本增量保存。
- 命格页只从同一世界与当前 Prompt 版本的缓存恢复并重新建立五类计数；命格缓存所有者在读取或枚举时自动删除所有非当前版本候选池，不读取、不迁移、不兼容。失去当前版本候选池支撑的 AI 抽取页状态由其所有者同步删除。只有五类都至少有四条可用普通候选才恢复首批完成状态并在首次渲染直接进入选择页，不展示抽取页或封印回放。缺少任一分类或任一分类不足四条的缓存不直接进入选择交接。进入选择页后按实际分类缺口补充，达到每类十二条后停止该类后续调用；补充失败由命格池保留并反馈给页面，再次进入选择页时按仍然存在的缺口继续补充。最后一个完整响应中已经识别出的有效条目继续保留，不为凑固定总数丢弃。
- 命格解析支持围栏、对象外说明、顶层多候选、字段乱序、字段别名、中文或英文分类名、字符串数字和文本属性加成；属性字段或单个命格无法恢复时只放弃对应局部结果，不能牵连同一响应中的其他有效命格。传输 Schema 只做宽容观测，不作为整包运行阻断。
- 命格分类由每次调用的分类系统 Prompt 唯一承载；用户消息不重复发送 `generationTask`。`existingNames` 表示全池已被占用的名称，新命格不得与其重复；每次补充调用还必须接收目标类别已有候选的名称、设定描述和效果摘要，并不得以同义词、改名或换写效果重复已有能力方向。内部 ID、lineageId 和调用编号不发送给 AI。未使用的固定分类模板不作为第二真源保留。
- 基础抽取 Prompt 只生成普通等级；普通候选只能表达局部、有限、非决定性的优势，并以输入世界中普通个体与常规水平的凡俗尺度为基准。每条候选必须有实际正向收益；带有负面效果时必须同时给出明确、可兑现的额外补偿，禁止只有损失、限制、惩罚或负属性的纯负面候选。分类按主要作用机制判断，不按场景、题材、角色身份或种族判断；题材只改变机制形式与尺度，种族、身份和背景只限定实际可用的行动、感知、表达和资源通道。杂类只在行动、认知、表达、经营无法承载主要机制时使用，不得直接生成灵体、长生、不灭、预知、必然逢凶化吉、因果操控、言出法随、全知全能或万法通晓等高阶结果，高阶方向由独立成长调用决定。运行时不以关键词黑名单、名称、相似度或换写效果判断丢弃可解析候选；重复与强度偏移必须回到 Prompt、分类输入和现有候选摘要修复。
- 命格候选只在最低字段无法恢复、类别无法归一化、属性不是有限整数、普通级明确数值预算越界或身份 ID 重复时放弃对应局部项；这些完整性边界不得扩展为内容过滤。首批响应中已经解析出的额外候选继续保留，不按四条目标截断。
- 天赋成长的动态组装先完成可确定的机械筛选：证据窗口固定为来源故事回合，同一故事回合经连续性提取形成的多条记忆、多个事实日期或重复正文只合并为一个窗口；再按候选本级生效时间标明窗口可用于哪些候选，剔除成长选择等结果记录，并移除可用窗口数量尚未达到目标等级最低门槛、单条天赋已进阶 2 次、全局已进阶 6 次、距上次确认不足 20 轮或模拟时间未严格超过 20 年的候选。本地不判断事实是否真正体现天赋。全部候选被程序过滤时不调用成长 AI。AI 只在剩余候选及其可用窗口中判断核心能力、结果强度与成长路线；有条件的当前效果必须在同一窗口中同时满足必要触发条件和核心能力实际表现，且成长必须同时具备反复训练或使用形成的长期积累、窗口之间真实经过的时间沉淀和至少一个明确契机（机缘、奇遇、顿悟、重大变故、情绪冲击或同等具体事件），任一缺失都不构成成长证据。路线说明先直述能力，只有真实存在条件、限制或属性牺牲时才补充，不强制能力+代价模板。属性上限为普通 2、精良 4、稀有 6、史诗 8、传说 10、神话 12；每条路线的负属性绝对值总和与净分配都不得超过目标等级上限，不要求用满或高等级实际点数超过低等级。名称为二至六字并优先四字，使用叙事逻辑说明剧情变化，不使用成功率、判定值、触发率、冷却等系统化措辞，最多使用一处点睛比喻，不复制长篇输入或逐字叠加旧效果。
- 轮回升阶的 `attrBonus` 是最终属性加成的稀疏表示：只输出非零项，零值省略；没有数值加成时允许 `{}`。Schema 要求属性对象存在，但不要求五个键全部出现。
- Prompt 使用中性字段与类型占位，不提供人物、世界、事件或成品正文示范。
- 主故事只发送一条 `user` 消息，顺序与 `D:/AI/docs/prompt.txt` 完全一致；动态字段固定为 `世界`、`玩家信息`、`历史输出`、`玩家本次点属性`、`本次信息`，其中 `本次信息`包含时间节点、命运分支和现有篇幅偏好。
- 主故事、故事连续性和天赋成长三个逻辑调用各自拥有独立缓存归属，同一主体同一调用保持稳定；已删除的 04 事件库不保留缓存池或兼容映射。

## 最大边界

Prompt 提供事实和职责，不拥有业务状态，也不替代本地协议校验。指定系统 Prompt、数据层示例、02 与 03 样品分别是主故事固定规则、动态字段、连续性压缩和天赋成长的接入基线；不在对应样品中的 AI 可见字段不接入，也不从其他来源补回。旧 04 世界模拟和后续事件库的调用、Prompt、Schema、缓存、动态组装、概况/状态应用、活动阶段、瞬态结果和测试引用全部删除，不保留兼容入口或旁路。
