# Prompt 与缓存机制

## 目标

Prompt 机制把固定职责、慢变事实、故事历史和本轮条件组成稳定、可理解的 AI 输入。

## 结果

- 主故事动态输入提供当前年龄、出生后至起始年龄的介入前史和当前自然寿命参考年龄。自然寿命参考年龄只作衰老背景，不是死亡线，也不由主故事逐轮调整；只有明确死亡结果才能提交死亡状态并绑定历史事实，普通结局不推断为死亡。
- 主故事固定资产采用受保护规则与五元素只读数据，当前资产版本为 `10.0.0`；消息顺序为角色/输入/写法/输出规则→五段数据。模型在一次调用内读取世界、历史、角色和本次条件，按角色处境写出这一段时间里真正发生的事；不设置事件数量、重大变化、阶段推进或默认字数配额，允许概括、跳跃和留白。正文像人生小说的一章，不是因果报告、提纲、规则解释或事件清单；玩家行动是 Attempt，不是剧情命令或成功事实。历史只承接已发生事实与来源，不提供本轮主题或续写顺序；事件卡池为软提示且只投影卡名数组，主故事可创作本时间段的新剧情，但不得倒填为过去事实。正负、权重与指纹只由本地校验与消费扣除使用，不进入数据层。叙事称呼与文风偏好只影响表达，不覆盖世界、事实、因果和协议；五元素数据顺序与事件卡池整池投影仍按主叙事资产执行。
- 浏览器只发送动态数据与受保护资产编号，固定规则不下发客户端；故事连续性与天赋成长调用保持各自现有消息角色和资产职责。
- 主故事动态数据使用可由 `JSON.parse` 直接解析的五元素数组；服务端把各元素填入固定规则的对应位置，动态层不追加示例人物、世界、历史或成品正文。主故事固定资产不携带故事示例矩阵；故事连续性和天赋成长资产也不加载示例。时间投影明确提供当前年龄和内部阶段索引，但只供人物处境与能力判断；不把年龄标签、具体日期、季节和推进数值作为正文素材暴露给模型。
- 固定 Prompt 与需要机器识别的动态 JSON 保持标准双引号和标准转义；只删除不承担结构、语义或输出示范职责的强调引号。缓存命中取决于消息与字节前缀稳定，不因删除双引号自动提高。
- 条件结果使用明确的“如果、则、否则如果、否则”关系；输出形状、字段类型和互斥关系只声明一次。
- 主故事输出使用固定 Prompt 声明的最小 JSON 对象：`正文`、`属性`、`命运分支`、`结局`、`角色死亡`，并可选 `事件卡消费`、`天赋表现线索`；不强制工具调用。属性只写发生持续变化的项；命运分支非空时为 2 至 4 个字符串；结局为恰好四个汉字。事件卡消费只列本轮实际采用并写入正文的卡名。应用仍只消费正文、分支、属性和结局；日志仍完整保留原始响应。随机故事生成、正文表达与历史承接规则遵循[核心模拟](../core-simulation.md)及[主叙事输入区](core-round/prompt-input.md)的唯一结果契约。
- 主故事解析先识别正文，再独立识别财富等属性、分支与结局；属性当前值相对输入换算后由既有状态所有者处理。正文存在时，坏的其他字段、字段写法或协议标点差异不得牵连同一响应中的可用正文；只有最低可用正文完全不存在时才失败，不从解析恢复中生成故事事实。
- 故事正文以单个 JSON 字符串承载；全部段落保持在同一字符串内，需要换行时使用标准 `\n` 转义，不把段落拆成相邻字符串或额外字段。正文是当前现实条件下重新选题、推演结果并以小说场景呈现的人生故事；世界与个人生活都可发起事件，历史约束事实，玩家条件改变参与方式和结果。正文涉及玩家时按程序解析后的 `本次信息.叙事称呼` 使用第二人称、第一人称或角色姓名；姓名只作输入标识；坐标时间只供内部定位，不机械转写为正文结构，符合本轮因果的相对时距可自然出现。
- 正文段落按模型返回的换行保留，不由渲染器改造成固定行数或固定换行节奏；故事生成、结果结算、表达和时间结构要求只以固定 Prompt 原文为准。
- 核心模拟的单个正式回合固定消费一个主故事结果。开启批量故事时，主故事调用一次最多返回十轮完整故事；遇到命运分支、结局或人生阶段结束时，该轮即本批最后一项，不足十轮是正常结果。调用时限随目标轮数放大；传输被截断时只回收最后一个完整项及其之前的完整前项，半截 JSON 不算一轮。后续项进入引擎持久状态，由玩家后续每次推进逐轮消费并走完正式回合提交。存在待消费批次时不整体替换事件池，批次结束后下一轮再补。队列为空或批量开关关闭时不请求批次。天赋成长按现行条件执行；故事连续性只在近期完整正文超过十轮且到达五轮间隔时调用，一次压缩最早连续五轮。
- 正式替换前的共享审查基线沿正常创建流程包含世界名称与描述、历法与叙事风格，主角姓名、性别、种族、背景、起始年龄、寿命，心智、体魄、魅力、财富四项基础值、修正值与当前值，以及四个携带槽中的普通命格和轮回天赋；每个调用只接收完成自身职责所需的投影，不重复发送整份基线。
- 连续审查把已确认的本轮剧情、未来事件和玩家选定成长路线投影应用到下一轮输入，用同一角色和世界验证长期连续性；主故事不再提供结构化事件结果，历史以正文为事实底稿。测试数据不写入正式运行状态。
- 连续性提取先保留近期完整正文退出其自身处理窗口后仍需成立的最终状态、持续关系、关键发现、承诺和未解决结果；同一回合中已经被后续最终结果完整覆盖且没有独立影响的中间动作、复测和阶段结果不再保留，同一因果阶段合并表达，不设置固定条数上限。该提取结果不再进入主故事输入。
- 连续性提取一次输出五轮批次中各来源回合的时间、剧情和权重，权重只服务于 02 的记忆职责。主故事 `历史输出.事件`由叙事历史所有者直接投影完整正文与发生年龄，不拆分或优先投影结构化事件结果；完整正文仍由历史所有者保存，历史年龄索引不进入新正文。历史使本轮变化与既定事实相容，本轮焦点由世界可能性、当前条件和随机性重新形成，旧主题只作为背景事实而非续写入口。
- 未来事件只接收正文已经给出具体日期、明确历法周期或可从当前绝对时间唯一计算的事项；“某事发生前后”“下次处理时”等没有排期的条件继续作为连续性事实，不伪造为当前回合结束之后的绝对时间。未来事件逐条识别、逐条去重和逐条登记，单条无法换算时放弃该条，其余合法事项继续使用；本轮剧情不因未来事件异常而丢弃。
- 解析器红线：除非最低可用产品绝对不存在，不得使用严格 Schema、未知字段、字段顺序或整包严格判定阻断响应；不得增加格式修复请求、重试、备用模型或旁路兼容层。
- 命格抽取的五类首批调用分别只接收灵躯蜕变、万象听令、洞察天机、万灵随行或造化成形一个主机制族，每次目标四条普通命格；五类调用完成后才发布选择页。选择页发布后按分类继续补充至每类十二条，候选逐条合并并由命格池缓存按世界与 Prompt 版本增量保存。
- 命格页只从同一世界与当前 Prompt 版本的缓存恢复并重新建立五类计数；命格缓存所有者在读取或枚举时自动删除所有非当前版本候选池，不读取、不迁移、不兼容。失去当前版本候选池支撑的 AI 抽取页状态由其所有者同步删除。只有五类都至少有四条可用普通候选才恢复首批完成状态并在首次渲染直接进入选择页，不展示抽取页或封印回放。缺少任一分类或任一分类不足四条的缓存不直接进入选择交接。进入选择页后按实际分类缺口补充，达到每类十二条后停止该类后续调用；补充失败由命格池保留并反馈给页面，再次进入选择页时按仍然存在的缺口继续补充。最后一个完整响应中已经识别出的有效条目继续保留，不为凑固定总数丢弃。
- 命格解析支持围栏、对象外说明、顶层多候选和字段乱序；仅接受当前双轴字段、五个规范分类 ID 和有限整数属性，不读取旧形状、旧等级、类别别名或字符串数字。单个命格无效时只放弃该条，不能牵连同一响应中的其他有效命格。传输 Schema 只做宽容观测，不作为整包运行阻断。
- 命格分类由每次调用的分类系统 Prompt 唯一承载；用户消息不重复发送 `generationTask`。`existingNames` 表示全池已被占用的名称，新命格不得与其重复；每次补充调用还必须接收目标类别已有候选的名称、设定描述和效果摘要，并不得以同义词、改名或换写效果重复已有能力方向。五类主机制族以灵躯蜕变、万象听令、洞察天机、万灵随行、造化成形呈现，只用于候选编排，不是能力类型白名单；内部 ID、lineageId 和调用编号不发送给 AI。未使用的固定分类模板不作为第二真源保留。
- 基础抽取 Prompt 只生成资质1至3阶、开发阶段初醒的候选，资质由AI按机制复杂度评定，不设概率或配额。候选是玩家的觉醒能力与外挂金手指，能力类型与世界适配遵循[命格界面](../pages/talent-draw.md)的唯一结果契约。简介以约30至45字的动作、画面或异常现象呈现能力与可见结果，完整触发、机制、边界及真实代价保存在效果字段。多样性来自机制差异，而不是同一能力换名；不把世界改为全民觉醒制度。每条候选须有实际正向收益；带负面效果时须给出可兑现的补偿。文风偏好不做运行时过滤，不增加评审或重试调用。
- 命格候选只在当前协议最低字段无效、分类不是规范ID、属性不是有限整数、资质或开发阶段越界、资质对应属性预算越界或身份重复时放弃对应局部项；这些完整性边界不得扩展为内容过滤。首批响应中已经解析出的额外候选继续保留，不按四条目标截断。
- 天赋成长的动态组装先读取命格系统已经保存的天赋表现线索：线索必须来自玩家实际使用命格后留下的可观察结果，来源回合由引擎按本轮记录，并以来源故事回合合并为证据窗口；同一故事回合的多条线索、连续性记忆或重复正文只构成一个窗口。线索只携带命格引用与可观察结果，不要求主故事输出“突破契机”。程序先按年龄、阶段、窗口数量、证据水位、冷却和次数筛选候选，再按本轮存档种子做一次确定性机缘判定；未命中不调用成长 AI，命中后只把该天赋、机缘类型和窗口送入 03。路线说明先直述能力，只有真实存在条件、限制或属性牺牲时才补充，不强制能力+代价模板。属性正向净加成与负值绝对值总和分别不得超过当前资质阶位乘以2，至高上限18，不要求用满。名称为二至六字并优先四字，使用叙事逻辑说明剧情变化，不使用成功率、判定值、触发率、冷却等系统化措辞，最多使用一处点睛比喻，不复制长篇输入或逐字叠加旧效果。
- 成长只推进开发阶段，不改变资质。深度、广度基于当前已确认能力，转变根据本局历史与机缘气质重塑机制组合；三条路线均不得删除或削弱已经成立的核心能力。新效果完整替换旧版本，不默认叠加历代能力。初醒到掌握至少2个窗口，掌握到圆满至少3个窗口。属性净加成与负值绝对值总和分别不得超过资质阶位乘以2，不要求用满。该变化沿用现有调用和玩家确认路径，不增加额外 AI 调用。
- 轮回升阶的 `attrBonus` 是最终属性加成的稀疏表示：只输出非零项，零值省略；没有数值加成时允许 `{}`。Schema 要求属性对象存在，但不要求五个键全部出现。
- 主故事固定资产不携带故事示例；其余 Prompt 也使用中性字段与类型占位，不提供人物、世界、事件或成品正文示范。
- 主故事只发送一条 `user` 消息，由服务端受保护资产 `src/mods/mod-engine/server/narrative-system-prompt.ts` 维护固定规则并合成五段动态数据；动态字段固定为 `世界`、`玩家信息`、`历史输出`、`玩家本次点属性`、`本次信息`，其中 `本次信息`含时间节点、时间窗口、可选自然寿命参考年龄、可选批量输出、命运分支、篇幅偏好、叙事称呼、文风偏好和可选控制平面。控制平面含出生背景、人生规划、事件卡池、命运转折调性、难度指引和到期世界事实；人生规划包含阶段标识、当前阶段、阶段目标与下一阶段入口，列表字段允许字符串或对象，由程序展开为可读文本；正负、权重与来源指纹不进入数据层。主故事的 `事件卡消费` 只列出本轮实际采用并写入正文的卡名，由引擎按名扣除。时间窗口由现有回合时间真源派生，不建立持久化平行状态；它只帮助模型判断范围和发展方向，不授权复制输入索引或历法措辞。
- 主故事、故事连续性、天赋成长和条件式事件卡生成四个逻辑调用各自拥有独立缓存归属，同一主体同一调用保持稳定；事件卡池只保存按世界、人生阶段、规范化时间步长和玩家意图生成的只读卡片，不保存玩家已发生事实。

## 最大边界

Prompt 提供事实和职责，不拥有业务状态，也不替代本地协议校验。指定系统 Prompt、数据层示例、02 与 03 样品分别是主故事固定规则、动态字段、连续性压缩和天赋成长的接入基线；动态数据示例只说明字段形状，主故事资产不携带故事示例矩阵。样例中的世界、人物与故事不进入当前运行事实；不在对应样品中的 AI 可见字段不接入，也不从其他来源补回。旧版数值联动世界模拟不恢复为运行时状态源；当前事件卡只保留名称、正负与权重，不能成为第二个世界状态源。
