# 开发日志镜像机制

## 目标

在本地开发服务器实际发生 AI 调用后，为每个调用保留一份不改变正文的发送/接收文本文件，便于直接审阅 Prompt 输入、模型返回和剧情重复证据。

## 结果

- 镜像根目录固定为项目 docs/logs。
- 子目录由现有 AI 调用类型标识决定，发送和接收文件分别以对应的中文前缀开头。
- 每次实际发送和每次实际接收分别新建一个 UTF-8 .txt 文件；正文等于日志调用中的原始消息文本，不加标题、元数据、解释、分隔符或内容过滤。
- 文件名尾部使用北京时间 24 小时制时间戳；时间精度不足以区分同一秒时保留毫秒。
- 自动清理只作用于 docs/logs 镜像文件，文件超过三天后删除；数据库、诊断 JSONL、回合归档和其他 docs 内容不受影响。
- 该机制只在本地开发服务器路径启用；部署或生产运行不创建、更新或清理镜像文件。

## 边界

- SQLite 日志是调用记录、元数据和调试查询投影的真源；逐存档逐轮的 narrative-round archive 仍负责原始交换归档；文件镜像只是开发审阅副本，不回读、不双写业务状态，也不改变数据库 Schema。
- 镜像只写发送/接收消息正文；认证头、凭据、请求元数据和内部诊断不混入正文文件。调试页对旧代理记录使用安全投影，因此“完整发送/返回内容”指完整的非认证消息正文。
- 镜像写入失败不阻塞 AI 调用或数据库日志提交；失败只进入现有开发诊断路径。

## 验收

- 以真实开发调用确认调用类型分组、发送/接收成对落盘、正文逐字相等、时间戳为北京时间、超过三天清理和生产路径关闭。
