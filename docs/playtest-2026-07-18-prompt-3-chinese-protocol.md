## 1. 验收结论

- 主叙事固定 Prompt 已组件化，Prompt 版本为 `3.0.0`。
- AI 可见信封、字段、枚举、系统名和可写字段名统一为中文；英文旧协议不能进入成功路径。
- 内部 TypeScript、运行 ID 和持久化字段保持稳定，由唯一严格转译层衔接。
- 用户输入按 `全局信息 -> 记忆 -> 本轮引导` 三条消息装配；只改变本轮状态时，前两层保持字节级稳定。
- 世界与角色对象只发送中文投影视图，不发送内部 `config`、属性对象或隐藏校准字段。
- 到期因果只进入本轮提示，不提前消费；完整叙事提交通过后才确认触发并持久化。
- 字数偏离只记录建议，不触发重写或截断；实际通过样本约 496 字，完整保留。

## 3. 实际模型切片

固定条件：

- Provider：本机已配置 DeepSeek 代理
- Model：`deepseek-v4-flash`
- Temperature：`0.7`
- Seed：`417`
- 输出额度：`4096`
- 输入：潮汐群岛旧渡口营救阿禾，同一世界、人物、记忆、到期承诺和本轮阻力
- 对比：完整 Prompt；移除 `scene-and-causality` 与 `style-example` 的切片 Prompt

结果：

| 维度 | 完整 Prompt | 移除现场因果与示例 |
|---|---|---|
| 第二人称 | 稳定使用“你” | 使用“你” |
| 主线 | 营救、堵漏、巡船逼近、父亲线索连续推进 | 场景仍成立，但对白拆成独立短段 |
| 人物声音 | 阿禾、林舟有具体动作、对白与选择 | 人物有反应，但段落被切成 9 段 |
| 可见后果 | 小船搁浅、林舟引开追兵、旧缆绳/遗物形成下一步 | 巡船发现、缆绳卡死，后果较单一 |
| 协议 | 初稿漏回合数据；一次完整格式修复后通过 | 初稿字段类型错误；修复后仍违反三段契约 |
| 最终门禁 | 通过 | 不通过 |

完整 Prompt 的最终可提交样本为三段、约 496 字。字数超过 200 偏好，但现场、人物回应、行动阻力、后果和下一步线索完整，因此按 `PD-009` 保留全文。

## 4. 迭代记录

1. 初版中文协议只列部分枚举，模型把数值写成“高/上升”、把数组写成字符串，并自造“营救行动、局部、信任加深”等值。
2. 增加由同一协议权威派生的完整中文形状示例、全枚举/类型说明和仅修复时核对表后，字段与枚举错误消失。
3. 模型会把 JSON 语法双引号排版成中文弯引号；新增的结构修复只转换语法标点，不补写、不截断、不提取局部对象。
4. 固定模型首稿仍可能在三段正文后停止。一次格式修复能够得到完整可提交结果；额外常驻提交提醒未降低该样本的首稿漏协议率，已按切片结果移除。
5. “延迟因果”改为“新延迟因果”，避免把正在兑现的旧承诺再次登记为未来事项。
6. L1 摘要调用失败原本会把完整原文登记为成功覆盖；现改为不建立摘要节点、不增加成功统计，完整原始事件保留等待重试，并补入压缩回归与硬截断审计。

## 5. 真实玩家路径

测试流程：欢迎页 → 已保存世界 → 世界配置 → 角色创建 → 命格抽取 → 命格选择 → 属性分配 → 命书核对 → 核心叙事 → 存档恢复。

- 命格抽取按十条批量持续生成，约五秒内得到 5 条有效候选；选择 3 条后正常进入属性分配。
- 核心模拟运行界面保持顶部信息栏与叙事区两部分，没有恢复额外标题栏或独立底部按钮栏。
- 首次首轮调用在完整格式修复后仍缺少中文标签信封，页面未推进回合并显示“重新尝试”；玩家重试后成功提交。
- 成功首轮与第二轮均为三段第二人称现场叙事；正文包含动作、环境、人物回应和下一步悬念，未显示 `[正文]`、`[回合数据]` 或任何结构化字段。
- 第二轮直接成功；自动存档显示第 2 轮，从欢迎页继续后完整恢复两轮正文、时间和角色状态。
- 欢迎页存档面板的打开、关闭与恢复入口按真实可见状态验证；关闭后保持 `/welcome`，未发生导航穿透。
- 浏览器控制台没有新增应用错误。保留一条首轮协议拒绝记录和命格无效批次警告，均有明确恢复路径且未写入不完整状态。

## 6. 已知边界

- `deepseek-v4-flash` 固定样本的首稿可能需要一次协议修复，存在额外延迟；当前不以牺牲正文质量、拆成第二个常驻 AI 调用或接受不完整状态来换取速度。
- 实际浏览器中出现过一次“格式修复后仍失败、玩家重试成功”；这说明严格拒绝与恢复链正常，但模型协议首轮成功率仍不是 100%，后续评估应继续统计真实失败率。
- 后续模型或 Provider 评估应复用同一输入、配置、版本、成功门禁和质量维度，不得只比较 Token 或字数。
