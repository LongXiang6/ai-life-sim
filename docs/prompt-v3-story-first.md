# 主故事 V3：故事优先协议（草案）

> 设计判据：**随机人生 > 因果审计；角色 > 规则；正文 > 账本。**
> 这是文档草案，不改运行时。

## 1. 为什么 V2 还不够

V2 虽然删了示例和流水线，但仍保留 `事件结果` 的四项因果账本。它等于要求模型每轮交一份：

```text
事件：发生了什么
成因：为什么发生
结果：位置/关系怎么变
影响：留下了什么
```

这不是“记录事实”，而是在要求模型**解释因果**。模型会把注意力放在填满四项、让因果自洽、让每条都有影响上，人生就变成案例报告。精密设计越多，模型越执着规则，随机性和人物感越弱。

## 2. V3-A：最小协议（推荐）

只保留游戏真正需要的状态，不保留因果账本：

```json
{
  "正文": "",
  "属性": {"心智": 0, "体魄": 0, "魅力": 0, "财富": 0},
  "命运分支": false,
  "结局": false,
  "角色死亡": false
}
```

可选元数据，不参与叙事因果：

```json
{
  "事件卡消费": ["本轮实际采用的卡名"],
  "天赋表现线索": [{"引用": "命格-1", "可观察结果": "实际留下的结果"}]
}
```

删除：

- `时间定位`：没有游戏状态消费者。
- `事件结果`：四项因果账本，过度设计的主源。
- `自然寿命变化`：精密因果机制；自然寿命固定，死亡由 `角色死亡` 表达。
- `天赋表现线索` 的 `实际使用`、`突破契机`：只留“引用 + 可观察结果”，成长判断交给成长 AI，不让主故事写因果。
- `属性` 的全量必填：只写发生持续变化的项，未变省略。

保留：

- `正文`：唯一的故事载体。
- `属性`：角色状态，游戏必需。
- `命运分支`、`结局`、`角色死亡`：玩家可见的流程状态。
- `事件卡消费`、`天赋表现线索`：可选一行元数据；如果连卡池/天赋成长也不要，整块删除。

## 3. V3-B：折中方案

如果担心完全失去跨轮记忆，可以把四项压成一句**可选**的：

```json
"本轮事实": "一句话，只写已经发生的关键变化，不解释因果。"
```

它只做记忆锚点，不要求成因、结果、影响。下一轮历史优先用它，没有就用正文。它比四项账本轻得多，但仍保留一点“事实”框架；如果连这句都不想要，用 V3-A。

## 4. 历史与记忆

- 历史直接用正文，不再有 `事件结果` 账本。
- `timeline-memory.ts` 已经支持“没有事件结果时回退正文”，所以这不是大改造。
- 长期记忆继续用现有压缩摘要；近期用完整正文。记忆像人一样会模糊，这是随机人生模拟器可以接受的代价。
- 不再要求“每轮必须发生几件事”“每件事必须有因果影响”；模型可以写一段平淡的日子，也可以写一件大事。

## 5. Prompt 骨架（约 900 字）

```text
# 角色
你是一个人生模拟器。角色是中心：他是谁、此刻想要什么、怕失去什么、与谁有关系、手上有什么。世界是条件，不是任务清单。事件是角色选择与世界反应共同留下的结果。

# 输入
世界、玩家信息、历史输出、本次行动是已有条件。历史是已经发生的人生，只承接人物、关系、资源和未解决方向，不复述旧场景。玩家行动是尝试，不是命令；按年龄、能力、资源、关系和世界规则回应，可以成功、失败、延迟、转化或产生意外。未知不补。

# 写法
按本次信息.篇幅偏好写正文；按叙事称呼和文风偏好表达。写这一段时间里真正发生在角色身上的事：日常、关系、选择、代价、变化。允许概括、跳跃、留白；不要写成提纲、规则解释、设定说明或事件清单。正文像人生小说的一章，不是因果报告。

# 输出
只返回一个 JSON 对象：
{
  "正文": "",
  "属性": {"心智": 0, "体魄": 0, "魅力": 0, "财富": 0},
  "命运分支": false,
  "结局": false,
  "角色死亡": false
}
- 属性只写发生持续变化的项，填结算后的当前值；没变可省略。
- 命运分支：本轮自然形成的 2-4 个未决方向；没有真实分岔填 false。有分支时结局填 false。
- 结局：人生不可逆终态时填四个汉字，否则 false。
- 角色死亡：明确死亡时填 {"死因类型":"story|condition|trauma|life-ending","死因":"..."}，否则 false；死亡时必须有结局，且命运分支为 false。
- 事件卡消费（可选）：本轮实际采用的卡名数组；没有省略。
- 天赋表现线索（可选）：只写实际使用并留下可观察结果的命格引用和结果；没有省略。
```

批量生成时，只在末尾加一句：

```text
批量时顶层返回“故事批次”数组，最多 10 轮；遇到命运分支、结局或人生阶段结束时停止；每项完整，不写摘要。
```

## 6. 影响

- 当前骨架 746 字（非空白 680 字）；加上批量说明约 800 字。固定 Prompt 从 V2 的 2,232 字降到约 800-1,000 字。
- 每轮输出少一份四项账本，模型少一层“必须解释因果”的压力。
- 历史投影变短，但连续性更依赖正文和压缩摘要；可能出现更多模糊和重复，这是取舍。
- 删除 `事件结果` 需要同步改 Schema、parser、`NarrativeChunk`、`timeline-memory`、`recent-story-context`、连续性上下文和相关测试；不能只改 Prompt。

## 7. 验证

- A/B：同一角色、同一世界、同一行动，各跑 10 轮。
- 观察：正文是否更像人生、更少规则解释；重复开头/重复事件是否可接受；属性/分支/死亡是否仍正确；连续性是否明显断裂。
- 如果 V3-A 断裂过多，再上 V3-B 的 `本轮事实`，不要直接退回四项账本。
