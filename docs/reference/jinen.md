# AI 界面增强技能

用于让 AI 编码助手在做前端页面时少产出模板化、廉价感强的 UI。本文只保留可执行选型规则，不记录 star 数、营销描述或不稳定项目状态。

## 使用原则

1. 先判断项目现有技术栈和设计系统，优先复用已有组件、token、动画库。
2. 不因“更好看”擅自引入新依赖；新增依赖需确认。
3. 动画服务于状态反馈、层级变化和任务完成，不为炫技堆叠特效。
4. 面向后台、CRM、SaaS 工具时，优先信息密度、对齐、扫描效率和低干扰交互。
5. 面向官网、作品集、活动页、游戏时，可使用更强的视觉资产、动效和叙事布局。
6. 交付前检查桌面和移动端：横向溢出、遮挡、字号、对比度、焦点态、控制台错误。

|---|---|---|---|---|
| UI-UX-Pro-Max | https://github.com/nextlevelbuilder/ui-ux-pro-max-skill | 给 AI 提供基础设计规则、布局、配色、间距、响应式和可访问性约束 | 已有严格项目设计规范，或工具无法读取本地规则文件 | 当作规则参考，不当作组件库；和项目现有规范冲突时以项目为准 |
| React Bits | https://github.com/DavidHDev/react-bits | React 项目需要现成动画组件，如文字特效、按钮动效、背景动效、卡片交互 | 非 React 项目，或需要统一严肃后台风格 | 只引入少量亮点组件；统一颜色、圆角、间距和动效时长 |
| Magic UI | https://github.com/magicuidesign/magicui | React + shadcn/ui 项目需要微交互、Bento、边框光束、跑马灯、入场动画 | 非 shadcn 项目，或不能接受新增 Motion/动画依赖 | 适合局部增强；避免把营销页特效搬进工作台界面 |

## 场景组合

### 从零开始的新项目

- 基础规则：UI-UX-Pro-Max 思路
- 动画能力：Motion 或项目已有动画方案
- 目标：先建立配色、间距、字号、断点、组件状态，再做动效

### React + shadcn 项目

- 微交互：Magic UI
- 局部亮点：React Bits
- 约束：每页最多保留 1 个主视觉动效，其余只做轻量反馈

### 非 React 项目

- 动画：Motion 或原生 CSS/Web Animations API
- 图表：只在合适语境下使用 roughViz
- 约束：不要为了某个动画组件强行迁移框架

### 严肃工具型产品

- 优先：信息架构、表格密度、状态清晰、键盘/焦点可用
- 可用：轻量 hover、loading、展开收起、错误/成功反馈
- 避免：大面积渐变、粒子背景、强视差、持续循环动效、装饰性卡片堆叠

### 品牌/营销/作品展示

- 优先：首屏视觉资产、品牌识别、节奏感、可读文案
- 可用：Magic UI、React Bits、Motion 组合
- 避免：无内容支撑的特效堆砌、暗色模糊背景、看不清产品本体的图片

## 落地流程

1. 读取项目现有 UI 规范、组件库、token、路由页面和依赖。
2. 判断页面类型：工具型、营销型、游戏型、作品型、数据型。
3. 先修布局骨架：信息层级、对齐、间距、响应式、空/加载/错误状态。
4. 再加动效：只增强关键状态变化，不影响性能和可访问性。
5. 若需外部库，列出依赖、用途、替代方案和影响，等确认后再引入。
6. 验证桌面与移动端截图或 DOM 指标，确认无溢出、遮挡、低对比和控制台错误。

## 禁止项

- 不要默认生成紫色渐变背景、三列等宽卡片、玻璃拟态堆叠和无意义 hero。
- 不要把 landing page 的动效套到后台、表单、配置页、编辑器或数据看板。
- 不要用动画掩盖信息结构问题。
- 不要复制组件库示例后不统一 token。
- 不要引入无人维护或与项目技术栈冲突的依赖。
- 不要使用小于 10px 的可见文字。
- 不要牺牲 reduced-motion、键盘焦点和基本可访问性。

## 验收清单

- 页面目标一眼可见，主操作明确。
- 布局在桌面和移动端无横向溢出。
- 文本、按钮、卡片、图表不互相遮挡。
- 颜色、圆角、阴影、间距来自项目 token 或统一变量。
- 动画可关闭或尊重 `prefers-reduced-motion`。
- 控制台无 error，关键交互可点击、可聚焦、可回退。
