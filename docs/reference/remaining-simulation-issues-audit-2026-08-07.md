# 收缩后剩余模拟问题审计（2026-08-07）

本文档是 `docs/reference` 下的审计记录，不是运行时权威，不定义或修改任何系统契约。当前机制仍以 `src/`、`src/mods/mod-engine/helpers/mvp-stages-config.default.json`、活动权威和测试为准。

## 范围与口径

- 审计快照：2026-08-07 当前工作树，项目版本 `5.7.5`。
- 唯一活动范围：当前阶段 `p8`，共 24 个活动成员，其中 15 个外部业务成员、9 个引擎成员。
- 收缩前的 [`simulation-system-audit-2026-08-06.md`](simulation-system-audit-2026-08-06.md) 与 [`runtime-numeric-constraints-audit-2026-08-06.md`](runtime-numeric-constraints-audit-2026-08-06.md) 仍保留 62 个成员的历史证据，不能作为当前活动成员事实。
- 本报告分别核对“源码存在、活动注册、实际执行、状态写入、下游消费”。只有五项形成闭环，才视为当前有效的剧情辅助系统。
- “无界”表示所属系统没有局部收敛或总量边界，不表示应恢复整局回合上限。当前没有“单次人生最多 1000 回合”的规则。
- 项目禁止丢弃原始剧情事实。因此，本报告所说的容量治理方向是完整归档、分页、分段和限制派生 Prompt 读取范围，不是删除、截断或覆盖原始数据。
- 本次只审计和记录，不修改源码、Prompt、配置、Schema、玩家数据或运行行为。

## 总体结论

1. **系统数量已经明显收缩，但长期数据面仍未同步收缩。** 同一轮故事可能同时进入完整正文、历史账本、分层摘要、记忆索引、相关性全量快照、因果和伏笔记录。最大风险已经从“系统太多”转为“少量核心系统重复保存并重复读取大量事实”。
2. **最高风险是 `subsystem-relevance` 的全量状态快照。** 每次记录相关性时，它为每个被收集的活动成员保存完整 `SubSystemState`，`stateHistory` 与 `changeRecords` 都没有清理或归档边界。这不是必要业务真源，而是对其他系统状态的重复持久化。
3. **主叙事事实链有效，但长期 Prompt 成本仍会增长。** `orchestrator.narrativeHistory`、历史账本、L1/L2/L3 摘要、记忆索引和关系记忆均会随人生增长；压缩保留原始正文是正确的，但压缩 AI 和检索仍可能遍历越来越多的派生历史。
4. **当前仍有三项明显空壳或断链系统。** `fortune-encounter` 会卡在第一个已接受或过期候选；`anomaly-phenomena` 没有当前生产写入链；`cultivation` 读取不到角色状态契约中的 `talentTags`，且现有 AI 写入策略也不会提交其变更。
5. **`combat-power` 不是空壳，但存在叙事失真。** 开放力量框架会按时间自动增加进度并动态追加阶位，理论上无界；晋升不要求故事已经发生训练、战斗、突破或获得证据。
6. **剧情结构和伏笔有实际作用，但会反向约束故事。** 剧情结构按规范年数强制进入升级、高潮和收尾循环；伏笔系统会把全部到期活跃伏笔重新注入 Prompt，而源码声明的“最多 10 条、超时归档”并未实现。
7. **正常回合仍登记一条前台叙事和四条后台 AI 分析。** 四条后台分别承担角色状态/成长、基础属性、历史事件/因果/记忆/剧情结构/伏笔、区域/知识技术。实际业务写入集中在少数所有者，AI 调用数与剧情收益并不等比例增长。

## 运行链判定标准

| 层次 | 本报告中的含义 | 不能据此推出的结论 |
|---|---|---|
| 源码存在 | 项目中仍有类、方法、Store 或公共 API | 不代表当前 `p8` 已启用 |
| 活动注册 | ID 位于当前 `p8` 并由注册器绑定 | 不代表本轮会执行或产生状态 |
| 实际执行 | 回合、创建、切换或明确 API 会调用其方法 | 不代表状态会被故事事实更新 |
| 状态写入 | 本地规则、受限 AI 或公开调用能够提交状态 | 不代表下一轮剧情会读取 |
| 下游消费 | Prompt、历史、记忆、终态、地图或其他业务所有者读取结果 | 只有写入与消费闭合后，才是有效剧情辅助 |

## 剩余数值与容量膨胀

### 高优先级

| 风险 | 所有者与数据 | 当前增长方式 | 已有边界 | 对运行和剧情的影响 |
|---|---|---|---|---|
| 重复全量状态快照 | `subsystem-relevance.stateHistory`、`changeRecords` | 每次 `recordState()` 为每个活动成员追加完整 `SubSystemState`；变化记录继续追加 | 只在读取时看最近 3 轮，没有源数据清理、归档或分段 | 存档同时保存业务真源和其完整副本；长局体积与序列化成本接近“回合数 × 活动状态总量” |
| 完整正文双重长期保留 | `orchestrator.narrativeHistory`、进程内 `acceptedNarrativeRecords` | 每次接纳正文追加完整文本；accepted 记录在当前人生内随有效正文保留 | 新人生或载入时清理；压缩不会删除正文 | 完整正文保留符合数据完整性要求，但进程内对象、存档、重复率计算和后续投影成本持续增长 |
| 历史账本六类 append-only | `events`、`transitions`、`evidence`、`causalEdges`、`candidateAudits`、`migrationMetadata` | 每次事实或状态变化追加新记录 | 查询 API 有分页；源数组没有总量边界 | 事实源应完整保留，但索引重建、存档和全量候选读取成本持续增长 |
| 可用候选全量进入事件识别 | `historical-ledger-runtime.ts` | 以 500 条分页循环读取全部 `available` 候选，再组装后台输入 | 单页 500 不是总上限；候选未终结就一直保留 | 长期候选不被接受、拒绝或过期时，后台 Prompt 会直接随候选总数增长 |
| 摘要节点和压缩历史全量增长 | `summary-compressor.compressedSummaries` | 按边界追加 L1/L2/L3；生成新摘要时 `existingHistoryForPrompt()` 遍历全部既有摘要 | 按层级去重同一边界；不删除低层或旧节点 | 长期连贯性有效，但压缩调用自身输入也会越来越大，可能把“为了降上下文”变成新的上下文来源 |
| 记忆索引和关系记忆增长 | `memory-lifecycle.searchIndex`、`relationshipMemories` | 每个摘要边界建立索引；每轮结构化关系更新追加记录 | 同一摘要边界可替换；同轮完全相同关系更新去重；没有总量边界 | 检索会保留全部 HIGH 条目和实体命中项，没有条数上限；人物多、长期 HIGH 多时会放大主 Prompt |

### 中优先级

| 风险 | 所有者与数据 | 当前增长方式 | 已有边界 | 对运行和剧情的影响 |
|---|---|---|---|---|
| 因果记录永久保留 | `causal-delay.causalEvents` | 登记后永久保留；解决只改状态；未解决可重复设置新的到期日 | 每轮最多呈现 2 条；延迟按 30/90/180/365 天默认值 | `maxTriggerPerRound=2` 只限制单轮吞吐，不限制总量；积压会造成同类承诺长期排队和重复提示 |
| 伏笔容量契约未实现 | `foreshadowing.active/resolved/unresolved` | `addActive()` 直接 `push`；解决后移入 `resolved` | 优先级钳制 1..10；注释声明活跃最多 10 条，但代码无检查 | 活跃伏笔会全部评分并可能注入；`unresolved` 和 `totalUnresolved` 基本没有写入链，超时归档形同空壳 |
| 开放力量阶位无界 | `combat-power.framework.ranks`、`rankIndex` | 时间进度超过阈值时，为开放框架追加 `开放进阶N` | 固定框架有限；进度和子阶段局部有界 | 长寿命、大时间步长可自动产生无限新阶位；叙事可能把时间流逝误写为真实修炼成果 |
| 角色健康条件历史增长 | `character-base.status.health.conditions` | 同一 `conditionId` 替换，不同 ID 追加；resolved 条目仍保留 | 生命、体力、精神、气运和道德均有钳制 | 长人生中的轻微伤病会持续留在角色完整状态，进入分析 AI 输入并增加状态噪声 |
| 成长集合和记录增长 | `growth-system.skills/abilities/records` | 新技能、新能力和每次变更都追加；技能使用次数继续累加 | 经验不超过 `potentialCap`，潜力 0..100；展示只投影部分项目 | 完整状态仍永久保存；`useCount` 可达 `Number.MAX_SAFE_INTEGER`，大量近义技能会削弱角色能力表达 |
| 技术应用永久增长 | `culture-tech.domains[].applications` | 宏观 AI 遇到新名称就追加；趋势会到期，但应用不会结束或合并 | 成熟度、扩散度和趋势强度均为 0..100 | 状态可长期积累近义应用；虽然主 Prompt 排除完整状态，宏观分析输入仍会增长 |

### 低优先级或有意单调

| 数据 | 当前行为 | 判断 |
|---|---|---|
| `time.totalDays`、`orchestrator.totalRounds` | 每轮单调增加，无整局硬上限 | **有意单调。** 不能用固定总回合数解决容量问题；只需防安全整数溢出并治理派生读取成本 |
| `character-base.status.ageDays/maximumLifespanDays` | 可校验到 `Number.MAX_SAFE_INTEGER`；寿命来自角色配置，年龄由规范时间派生 | **业务上可极大。** 风险是极端时间尺度，不是应增加整局终止规则 |
| 世界上下文、区域节点、边、跨界出口、迁移历史 | 输入或玩家操作驱动增长；单次世界初始化区域数为 1..30 | **条件性增长。** 单世界初始规模受控，但多世界和长期迁移没有总容量边界 |
| `plot-structure.phaseHistory` | 每次阶段切换追加 | **低容量、高语义风险。** 数组增长较慢，主要问题是固定戏剧循环而非存储体积 |
| `anomaly-phenomena.zones` | 手动创建或扩散时可增长 | **潜在无界但当前休眠。** 当前更主要的问题是没有生产写入链 |

|---|---|---|
| 角色状态 | 普通基础属性 `-10..10`，超凡属性 `-100000..100000` | 防止属性公式越界；不代表普通叙事应接近硬上限 |
| 角色状态 | 气运、道德 `-100..100`；体力、精神 `0..100` | 用于生成当前状态引导，已经不会像旧独立道德系统那样无限漂移 |
| 角色状态 | 本轮气运/道德单次 AI 变化 `-20..20` | 限制单轮后台分析的跳变幅度 |
| 知识与技术 | 成熟度、扩散度、趋势强度 `0..100` | 表示知识领域与传播强度；集合数量仍需与数值边界分开审计 |
| 异常现象 | 全局不稳定度 `0..100` | 只在存在异常区域时推进；当前通常保持空态 |
| 命格 | 创建期生成、选择和固定，进入新人生时重建 | 明确属于创建生命周期，不随每轮无限追加 |
| 叙事解析 | 只保存当前 `lastResult` | 每轮替换，不形成自身历史膨胀 |

## 空壳、断链与残留契约

| 优先级 | 系统或契约 | 断链证据 | 实际后果 |
|---|---|---|---|
| 高 | `fortune-encounter` | 新候选要求 `activeEncounter` 为 `null`；自动过期和手动接受都只改状态，不清空对象；当前 AI 写入也不允许接受或终结 | 每个上下文通常只会看到第一个候选，此后长期显示冷却/累计但不再产生新机缘 |
| 高 | `anomaly-phenomena` | 有 create/spread/close 和危险检查 API，但系统指令及宏观 AI 均不允许写入，也未发现主叙事或事件识别调用 | 正常故事链不会产生异常区域；活动注册主要增加空状态与维护面 |
| 高 | `cultivation` | 从 `character-base.data.talentTags` 读取天赋，但当前角色状态契约没有该字段；`validated-write` 又只允许手动来源实际提交 | `trainingBonus` 通常固定为 1，系统大多只是复制战力阶位并计算无人消费的突破提示 |
| 中 | `combat-power` 和 `cultivation` 的字段注册 | 字段注册表声明 `validated-write`，当前 `shouldApplyMvpCommit()` 对非手动来源只允许 `character-base`、`growth-system` 或宏观两系统 | 存在“契约看似可写、生产链实际不可写”的残留，增加维护者误判概率 |
| 中 | `simulation-scope-policy` 的 background 能力 | 提供 `canRunBackgroundWorldSubsystem()`，但未发现后台世界模拟调度消费者 | background 与 frozen 的产品差异没有形成实际模拟效果 |
| 低 | `context-transition` 自动故事切换 | 有完整公开入口和历史记录，但主叙事不会根据正文自行调用 | 不是空壳；只是必须由玩家或显式流程触发，不能当作自动旅行系统 |

## 剧情辅助质量

### 高价值闭环

| 组合 | 实际贡献 | 剩余问题 |
|---|---|---|
| `time` + `character-base` | 把时间跨度转为年龄、生命阶段、健康、寿命风险、节日和当前行动约束 | 极端寿命和时间跨度会放大所有长期数据；不是增加回合上限的理由 |
| `spatial-graph` + `world-init` | 用区域而非详细坐标表达世界形态、当前位置和环境社会概况 | 多上下文、区域和迁移历史仍无总容量；区域更新依赖宏观 AI 的事实判断 |
| `historical-event-ledger` | 为人物、事件、死亡、因果和技术变化提供可验证事实 | 候选未终结时后台 Prompt 会不断膨胀 |
| `summary-compressor` + `memory-lifecycle` | 把长期故事投影为按实际时间排序的时间轴，并支持人物和区域召回 | 搜索索引、关系记忆、全部 HIGH 命中和压缩历史本身会逐步增加输入 |
| `causal-delay` | 让承诺、恩怨、债务和选择在未来回合真正兑现 | 可无限续期，已解决记录也不归档到独立冷存储 |
| `growth-system` | 将学习、练习和稳定能力变成可追踪事实 | 近义技能、能力和完整变更记录可能造成角色描述碎片化 |

### 有帮助但容易降低质量

| 系统 | 正向作用 | 质量风险 |
|---|---|---|
| `plot-structure` | 提供铺垫、升级、高潮、回落和收尾的节奏提示 | 铺垫超过 8 年、冲突升级超过 15 年会强制转移；后续阶段按最短年限自动循环，生活叙事可能被模板化 |
| `foreshadowing` | 让已经建立的长期线索得到回收 | 活跃项无执行上限，旧伏笔越多，Prompt 越像待办清单；回收压力可能压过当轮人物行动 |
| `culture-tech` | 提供时代知识成熟度和真实技术应用 | 主 Prompt 不读取完整状态，价值主要经宏观 AI 间接体现；后台成本可能高于可见收益 |
| `combat-power` | 给超自然世界一个统一力量标签 | 自动按时间晋升会把没有发生的训练和突破包装成角色事实，并影响角色影响范围 |

### 当前低价值或无效

| 系统 | 结论 |
|---|---|
| `fortune-encounter` | 候选生命周期不完整，只有首次候选可能出现，奖励和后续循环不成立 |
| `anomaly-phenomena` | 正常故事链无法创建状态，危险检查也没有消费者 |
| `cultivation` | 天赋来源断链、写入受阻、突破不约束战力；与战力系统形成低价值重复投影 |
| `simulation-scope-policy` 的 background 部分 | 没有后台模拟调度，不能提供“离开后世界继续演化”的剧情事实 |

## AI 调用与职责集中度

正常回合的逻辑调用结构如下：

| 调用 | 当前主要职责 | 可写或提交的所有者 |
|---|---|---|
| 前台主叙事 | 生成完整正文和可选分支 | 不直接写业务状态 |
| 数据分析 | 健康、气运、道德、死亡、技能和能力 | `character-base`、`growth-system` |
| 基础属性分析 | 四项基础属性的稳定变化 | `character-base` |
| 事件识别 | 历史事件、候选、因果处置、关系记忆、剧情信号和伏笔 | 历史账本、`causal-delay`、`memory-lifecycle`、`plot-structure`、`foreshadowing` |
| 宏观影响 | 区域概况、知识成熟、技术应用和思想趋势 | `spatial-graph`、`culture-tech` |

审计判断：

- 四路后台调用不是空转，但写入价值高度集中。角色状态被拆成两次 AI；事件识别承载最多职责；宏观影响只有两个可写系统。
- `fortune-encounter`、`anomaly-phenomena`、`cultivation`、`combat-power` 不会因为出现在宏观“玩家影响力证据”中就自动获得写入闭环。
- `test:prompt-wiring` 的当前固定夹具结果为 `fixed=2497 global=199 memory=84 round=263 total=548`。该结果证明接线和当前夹具体积，不是长人生 Prompt 上限；候选、HIGH 记忆和伏笔增长后仍会增加实际输入。

## 风险优先级

| 顺序 | 问题 | 优先理由 |
|---:|---|---|
| 1 | `subsystem-relevance` 重复保存完整状态 | 没有新增业务事实，却复制所有活动所有者的数据，是最纯粹的容量放大 |
| 2 | 历史候选、记忆命中、伏笔和压缩历史的全量 Prompt 读取 | 会直接增加 AI 输入、费用、延迟和噪声，且可能降低剧情聚焦度 |
| 3 | `fortune-encounter`、`anomaly-phenomena`、`cultivation` 空壳/断链 | 维护成本明确，当前剧情收益接近零或为负 |
| 4 | `combat-power` 时间驱动开放晋升 | 会持续制造没有故事证据的角色成长，并可能无限追加阶位 |
| 5 | `plot-structure` 固定年限强制戏剧循环 | 直接影响正文走向，可能让生活、成长和长期平稳阶段失真 |
| 6 | 核心事实、摘要、索引、因果和关系记录的长期存储架构 | 都有真实价值，适合做无损归档和派生读取治理，不适合简单删除或固定条数裁剪 |
