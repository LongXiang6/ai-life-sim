# 结算评语与七言诗句提示词溯源（2026-08-08）

本文档所有者为 `docs/reference` 的结算评语提示词溯源记录，职责是保存 2026-08-08 围绕"一生回望"结算页评语与七言四句的提示词演进过程、最新定稿、真实消费测试证据与落地建议；它不是活动运行权威，不定义或修改系统契约，当前机制仍以源码、测试和 `docs/authority` 为准。

## 速览（给后续 AI）

- 目标：结算页"此生评语"由 AI 生成——白描叙事评语（90–150 字，不提分数）+ 七言四句（每句七字，末字平仄为"平、平、仄、平"）。
- **当前定稿 = V5.1**（全文见下节）：纯引导式，无任何示例、无任何"禁止/不要/避免"式反面措辞。
- 教训：**给示例会导致模型逐字抄袭**（V5 实测 2/3 挪用示范句）；**反面措辞限制创造力**；**字数与换行格式靠引导可稳定，格律（平平仄平）靠提示词不可稳定**（实测数据见第四节）。
- 接入点：`src/mods/mod-pages/pages/game-over/game-over-review.ts`（AI 调用与 schema）、`game-over/page.tsx`（渲染）、`game-over-scoring.ts`（评分证据，不参与评语文字）。
- 2026-08-11 落地决定：AI 失败显式失败；运行时不做本地评语/诗句兜底、模型回落、平仄或字数校验，也不隐藏重试。
- 2026-08-11 当前机制：结算先由独立 AI 调用生成世界适配五维与分值，系统取五项算术平均值；第二次 AI 调用消费同一人生证据与五维结果生成 V5.1 评语和诗句。

## 一、背景与目标

结算界面（"一生回望"页）包含两部分：

- **评分（2026-08-08 当时机制）**：由本地确定性算法计算并展示为四维雷达。2026-08-11 已由世界适配的 AI 五维评分取代，原世界评分 Profile、本地曲线和满分门禁已退出运行时。
- **评语（2026-08-08 当时机制）**：AI 生成（`game-over-review.ts` 的 `generateEndingReview`），当时仍有本地模板和死亡尾声优先级；这些路径已在 2026-08-11 的正式落地中删除，当前唯一文案来源是本节 V5.1 AI 调用。

需求演进路径：原始评语（散文、结尾带分数）→ 史诗/玄幻叙事体 → 七言四句 → 自然白描（拒绝套话模板）→ 格律约束（末字平平仄平）→ 引导式、无示例、无反面措辞、防同质化、适配任意世界观。

## 二、当前定稿提示词（V5.1）

```text
你是一位深谙古典诗词与人物传记的写作者，为一段已经结束的人生撰写结算页上的结尾评语。你相信好的结尾评语像碑文：克制、准确、经得起反复读；也像临终回望：只讲真实发生过的事。

【取材】
写作前先通读输入：这一生的经历全部来自其中的成就、抉择与维度。正文里出现的每一处事件、物件、场景，都应能在输入中找到出处；输入里没有的细节，留给省略，不自行补全。

【正文写法】
1. 用第二人称"你"，平静地回顾这一生，收束克制，让画面自己说话。
2. 选材取精：从输入里挑两三处最有分量的经历或细节，少而深，胜过全而浅。
3. 落点具体：让物件、场景和动作替这一生说话——一处具体的细节，比任何概括都更有分量。
4. 结构自由：可以顺时间，可以从一件往事回望，也可以从一件旧物说起；整篇只围绕一个贯穿的视角展开，让经历顺着它自然生长。
5. 正文 90–150 字（含标点）；评分、轮数等结算数据留在系统里，正文只讲经历。

【七言四句写法】
6. 紧接正文另起四行，每行七字。
7. 每行末字的声调依次为"平、平、仄、平"：第 1、2、4 行以平声收尾，三个平声末字同韵或近韵、读来顺口；第 3 行以仄声收尾。
8. 其余格律全由你把握：对仗、逐字平仄、句式都放权给你；把力气花在让意象真实、让句子顺口、让末行收束有力上。
9. 意象沿用正文里的物件与场景。

【输出】
只输出一个 JSON 对象，包含四个字段，不附加任何说明：
- perspective："micro"（个人选择更强）或"macro"（时代或广域影响更强）
- review：正文，90–150 字
- verse：七言四句，每行一句，用换行分隔
- evidenceIds：引用输入证据的编号数组
```

调用参数：玩家当前配置的模型，`temperature=0.45`，`response_format=json_object`，`thinking.disabled`；通过项目统一 AI 服务调用。当前运行不做模型或 Provider 回落。

## 三、提示词演进溯源

| 版本 | 关键改动 | 实测结论 / 教训 |
|---|---|---|
| 模拟阶段 | 散文→史诗→七言四句→自然白描，反复打磨意象 | 固定地名/句式模板（"落魄谷""我为峰"）读起来像拼贴，被否；自然来自本局真实细节 |
| v1 | 定风格：白描叙事回望体 + 七言四句 + 评语不提分数 | 首次定下"只讲真实发生过的事"基调 |
| v2 | 全面引导式：删"禁止类"措辞，说明"应该怎么写"；评语限 90–150 字 | 字数区间、换行格式从此稳定；成本约 1000–1100 tokens/次 |
| v3 | 优化身份说明（碑文/回望比喻）；七言四句只硬约束末字平平仄平 | 末字达标率 0/2 → 1/2；模型在意象与格律冲突时会优先意象（符合"质量优先"预期） |
| v4 | 防编年流水账引导（贯穿视角、同篇不重复手法） | 效果不稳定：现代世界（末世/都市）仍会输出年表，修仙世界可绕开 |
| v5 | 正文加一段结构示范（"那盏灯还亮着…"） | **示范被逐字抄袭：3 局中 2 局挪用示范首尾句，同质化实锤** → 弃用示例方案 |
| **v5.1** | **删除全部示例，纯引导；其余格律显式放权** | 内容 3/3 视角独立、贴合世界、字数稳定；平平仄平 1/3 → 定稿 |

## 五、结论与未决事项

1. **正文定稿 V5.1**：无示例 → 无同质化；引导式 → 内容干净、字数稳定、适配任意世界观。
2. **平平仄平不可靠提示词保证**：两版合计 4/6；放权后模型自由发挥更容易破格。此为提示词能力边界的事实记录；2026-08-11 已明确决定把格律交给 Prompt，不引入本地平仄校验或其他兜底。
3. **编年惯性**（末世/都市）属模型固有习惯，V5.1 已是最佳平衡；再压需权衡成本收益。
4. 当前落地已完成：`EndingReviewResponseSchema` 与 `EndingReview` 包含 `verse`，结算页渲染诗句；`buildLocalEndingReview` 和死亡尾声第二文案源已删除，AI 失败直接显示真实失败状态。`life-settlement` 按五维评分后再生成评语的顺序发布唯一终态。
5. 测试输入中成就时间如"十六岁"与提示词"禁止年龄"冲突，已改为只保留"评分、轮数等结算数据"不入正文。

## 七、给后续 AI 的验证方法

1. 改提示词后，可用与本节相同的真实调用方式做离线质量观察：随机 2 局（覆盖修仙/末世/都市任意两世界），记录 JSON schema、正文长度、分数提及、七言四句格式与末字声调；这些观察不进入运行时拦截、改写或兜底。
2. 同质化检查：同一提示词连测 3 局，比对开头/收束句是否有逐字重复。
3. 成本基线：约 1000–1100 tokens/次（含提示词 ~700），`deepseek-v4-flash`；Prompt 命中缓存时成本略降。
