## 1. 文档结论与边界

本文件是用户已选定的模拟系统精简、重组和接入目标。P0-P5 已完成多世界上下文、历史因果、NPC/关系、空间资源、成长评价和生命周期；P6 人口/聚落/工作/物品/经济、P7 社会文明与生态、P8 世界观插件已完成重写并进入现行回合清单。当前运行真源仍以 `mvp-stages-config.default.json` 和活动权威为准。

第 1—13 节定义完整重写目标和阶段顺序；每个阶段的实施输入、执行记录与验收证据归入阶段文件或任务溯源，避免主蓝图随执行历史无限增长。

核心结论：

1. 多世界不等于复制多套完整引擎。项目仍保留一个回合编排权威和一个规范时间权威，各世界通过上下文、局部历法、时间倍率和模拟范围接入。
2. 地图能力必须保留，但旧 `world-map` 同时承担模板生成、区域、资源、人口、势力、外交和演变，不能作为单例系统原样恢复。
3. P6-P8 已接入但不全部每回合运行。重写后的系统分为全局常驻、当前上下文实例、后台低频、休眠和世界观插件五类。
4. 任意世界观适配依靠显式能力组合和作用域契约，不依靠目录名、固定世界类型或散落的世界观条件分支。

## 2. 多世界目标架构

### 2.1 上下文层级

```text
Campaign
├─ 全局连续状态
│  ├─ 主角身份与基础连续属性
│  ├─ 跨世界记忆、因果与物品身份
│  └─ 旅行状态与全局回合序列
├─ WorldContextRegistry
│  ├─ 世界 / 宇宙 / 位面
│  ├─ 星系 / 星球 / 大陆
│  └─ 区域 / 聚落 / 场景
└─ CurrentContext
   ├─ 当前能力画像
   ├─ 当前空间位置
   ├─ 当前世界实例系统
   └─ 可达的上下文切换出口
```

`WorldContext` 是统一概念，不强制每个世界都拥有星球、国家、地图或物理距离。现实城市、修仙位面、飞船舱室、梦境、网络空间和纯叙事场景都可作为不同种类的上下文节点。

### 2.2 模拟范围

| 模式 | 作用 | 目标执行策略 |
|---|---|---|
| `active` | 玩家当前所在上下文 | 完整运行已启用能力、生成叙事并允许合法状态提交 |
| `background` | 与当前故事仍有因果联系的上下文 | 低频聚合模拟，只生成可追踪事件和必要状态差异 |
| `dormant` | 已访问但暂时无活动因果的上下文 | 冻结详细系统，只保存离开时快照和恢复所需元数据 |
| `closed` | 尚未开放或已永久关闭的上下文 | 不进入运行和 Prompt，仅保留必要索引或结局事实 |

从 `dormant` 恢复时应根据离开时间、世界规则和已确认因果生成一次可解释的追赶结果，不逐回合重放所有细节，也不静默丢失原有事实。

### 2.3 时间权威

- 保留唯一全局 `TimeSystem`，继续拥有规范回合序列、`daysPassed` 和 `totalDays`。
- 每个上下文可声明本地历法、时间显示单位、时间流速和暂停规则，但不能建立第二个竞争的回合提交权威。
- 跨世界移动由切换系统把全局经过时间换算为当地时间，并记录换算证据。
- 不同世界时间流速影响局部模拟推进，不允许直接篡改全局已发生回合。

## 4. 原未启用系统与当前处置

本节保留重写开始时的来源节点，表中“当前作用”是当时职责；“目标处置”已同步 P0-P5 的实际完成结果。旧 ID 只用于解释迁移来源，不表示仍有运行入口、兼容载荷或第二状态所有者。目标阶段见第 6 节，最终拥有系统见第 13 节。

处理类型：

- **保留重写**：职责有价值，但必须按新契约重写后再接入。
- **拆分重组**：当前系统跨越多个权威，不能作为一个系统原样恢复。
- **实例化**：每个世界或上下文拥有独立状态，通过统一契约创建和休眠。
- **混合作用域**：实体身份可跨世界连续，当地效果和位置按上下文计算。
- **世界观插件**：默认关闭，仅由能力画像明确启用。
- **替换旧实现**：保留产品能力，淘汰当前单例或中央大桶实现。

## 8. 必须删除或废弃的旧前提

| 旧前提 | 处理方式 | 原因 |
|---|---|---|
| 单一全局 `WorldConfig` 代表整个存档唯一世界 | 废弃为当前上下文投影；完整数据进入上下文注册表 | 无法表示多世界并存和不同能力组合 |
| 单例 `WorldMapState` | 删除或迁移为按 `contextId` 分区的空间图状态 | 切换世界后会覆盖旧世界位置和区域 |
| 裸 `regionId`、`npcId`、`itemId` | 迁移为全局唯一 ID 或带命名空间引用 | 不同世界会产生 ID 碰撞和错误关联 |
| `planeIndex` 同时表示位面、地图层或空间等级 | 替换为显式 `contextId`、`parentContextId`、`contextKind` 和空间边 | 复用字段无法稳定表达星球、位面、梦境和场景 |
| 地图系统同时拥有资源、人口、势力、外交和 UI | 拆分权威，只保留空间契约和投影输入 | 大桶无法独立休眠、替换或按世界能力关闭 |
| 每回合完整运行全部已访问世界 | 改用模拟范围策略 | 成本随世界数量线性增长，并会制造大量与玩家无关的 AI 和状态变化 |
| 每个世界各自拥有 `TimeSystem` 和回合提交 | 禁止 | 会产生竞争时间线、重复年龄推进和非原子提交 |
| 地图 UI 直接依赖修仙位面、国家或星球等具体 MOD 类型 | 删除深层依赖，改读统一投影 DTO | 同一 UI 无法适配任意世界观，模拟层也会被展示层反向绑定 |
| `adaptation-manager-system.ts` 继续放在 `subsystems/` 并被当作正式模拟系统 | 迁移到叙事引擎 AI 投影层的内部服务目录；保持编排器消费者和会话缓存，不注册运行 ID、不进入玩家系统清单 | 它有真实消费者但没有独立模拟状态，文件位置和名称不应误导系统扫描与恢复计划 |

## 9. 实施决策与验收要求

本文件已经确认目标架构和处置方向，但每个阶段开始前仍必须冻结公开 API、持久化结构、AI 返回 Schema 和跨 MOD 契约；不得把目标批准误当成批量修改代码的授权。

### 9.1 叙事 AI 统一模拟指令

重写后的模拟系统应共享一套中文“系统指令”外壳，再由每个系统声明自己允许的操作和专属字段。该设计扩展现有 `SUBSYSTEM_FIELD_CONTRACTS` 单一真源，不新建第二份 Prompt 字段表、Schema 字段表或系统手写指南。

当前 AI 可见结构：

```text
"系统指令":
  - "系统": "通用关系系统"
    "目标对象": "已存在的稳定关系编号"
    "目标上下文": "当前上下文编号"
    "操作": "调整"
    "说明": "本轮共同脱险后信任增加"
    "变更":
      "好感变化": 5
      "信任变化": 3
    "依据事件":
      - 本轮已接受事件编号
```

该外壳已在 P2 冻结为唯一成功协议；每个系统的操作、中文字段和内部映射继续从登记契约派生。

#### 9.1.1 通用指令字段

| 通用字段 | 必需性 | 作用 | 约束 |
|---|---|---|---|
| `系统` | 必需 | 选择唯一拥有该状态的系统 | 只能使用本轮指南公开的中文系统名 |
| `目标对象` | 必需 | 指向角色、NPC、关系、组织、地点、物品、事件或上下文本身 | 必须引用输入中已有的稳定业务 ID；AI 不得自造未知 ID |
| `目标上下文` | 必需 | 限定变化发生的世界、星球、区域或场景 | 必须等于当前回合上下文；不得默认写入其他休眠世界 |
| `操作` | 必需 | 表示本条指令属于哪类标准操作 | 只能使用目标系统登记的操作类型 |
| `说明` | 必需 | 保存产生变化的叙事依据和可审计原因 | 不能代替结构化字段，也不能从说明文本反推未提交数值 |
| `变更` | 必需 | 承载当前操作允许的系统专属字段 | 字段名、类型、范围、枚举和组合关系由操作契约唯一派生；仅关系“解除”使用空对象 |
| `依据事件` | 必需，可为空数组 | 关联已经成立的事件、因果或意图记录 | 只能引用输入中存在或本轮同包合法创建的事件；没有依据时显式使用空数组 |

本地接收层在翻译后补充稳定指令 ID、回合 ID、请求 ID、提交状态和失败原因，用于防重、日志、回滚和存档追踪。这些内部字段不要求叙事 AI 自行生成。

#### 9.1.2 标准操作族

| 操作族 | 标准操作示例 | 适用系统 |
|---|---|---|
| 数值 | 增量、设值 | 属性、健康、寿命、运气、声望、资源等 |
| 实体 | 创建、更新、移除 | NPC、组织、聚落、物品、作品等 |
| 关系 | 建立、调整、解除 | 人际关系、组织关系、外交、商路和空间连接 |
| 状态 | 进入、推进、完成、失败、关闭 | 生命周期、意图、冲突、事件、任务和世界生命周期 |
| 事件因果 | 登记、触发、解决、作废 | 历史事件、延迟因果、预言、伏笔和奇遇 |
| 空间 | 移动、跨界、到达、离开 | 角色位置、NPC 迁移、物品转移和上下文切换 |

操作族只统一语法，不统一业务规则。例如“健康”可以接受生命值增量，但不能接受外交关系操作；“时间”即使拥有数值状态，也不得因此开放给 AI 直接设值。

#### 9.1.3 每个系统必须登记的字段契约

| 契约项 | 说明 |
|---|---|
| 中文系统名 | AI 协议中的唯一名称，严格映射内部系统 ID |
| AI 权限模式 | `只读`、`提议`、`受校验写入` 或 `事件输入` |
| 允许目标 | 当前角色、指定实体、指定上下文、全局状态或系统自有事件 |
| 作用域要求 | 全局、当前上下文、指定上下文或允许跨界 |
| 允许操作族 | 从标准操作族中选择，不允许系统自行发明同义操作 |
| 专属字段 | 中文名、内部名、类型、增量/绝对值语义、范围或枚举 |
| 组合约束 | 必填搭配、互斥字段、前置状态和跨字段一致性 |
| 应用所有者 | 负责预检、公式计算、实际写入、持久化和回滚的 owning system |
| 运行门禁 | 系统必须已注册、当前阶段启用、能力画像允许且本轮可写 |

不是每个系统都必须允许 AI 直接写入，但每个系统都必须显式登记权限模式：

- `time`、`orchestrator`、`simulation-scope-policy`、存档和持久化系统为 AI 只读。
- `context-transition` 只接受玩家意图或 AI 提议，必须由本地检查出口、权限、携带物和时间换算后执行。
- 健康、关系、声望、技能等可以接受受校验写入，但确定性公式和钳制仍由 owning system 计算。
- 历史、因果、预言和奇遇优先接受事件输入，不允许 AI 绕过事件账本直接伪造已经结算的结果。

#### 9.1.4 提交规则

1. Prompt 只注入当前运行、当前相关并且允许 AI 操作的系统契约。
2. 未知系统、未知字段、非法操作、错误实体、错误上下文、越权目标或跨字段矛盾，使本轮全部系统指令整包失效。
3. 本地代码必须先对整包执行权限、Schema、目标存在性、作用域和各 owning system 预检，再进行第一次写入。
4. 多系统变化作为同一个原子提交；任一系统应用失败时回滚本包已经发生的写入。
5. 系统指令失败不裁剪或改写已经合格的正文与摘要；条件任务继续按自己的必需数据规则保持 pending。
6. AI 负责从叙事中表达有意义的变化，系统负责确定性计算、范围限制、状态机合法性、持久化和最终事实。
7. 不因 Prompt 或 Schema 方便而限制故事事件、关系、记忆或因果的语义条数；技术批处理必须保留完整原包和覆盖证据。

每个阶段至少验收：

1. 单世界现有玩家路径无回归。
2. 创建、切换、休眠、恢复和存档还原具有确定证据。
3. 当前世界完整模拟，后台世界只按策略产生聚合结果。
4. 所有事件、关系、记忆、地点和物品引用能够定位到正确上下文与实体。
5. 禁用任一可选能力包或世界观插件后，基础叙事链仍然可运行。
6. 不通过字符数、固定条数、数组位置或容量上限静默删除故事、记忆、因果和世界事实。

## 10. 后续阶段仍需冻结的契约

P0-P5 已分别冻结并完成世界上下文、历史因果、NPC/关系、空间资源、成长评价和生命周期边界。P6-P8 开始前仍必须分别冻结其公开 API、持久化结构、AI 返回 Schema、跨 MOD 契约和迁移方案；不得把前序阶段授权扩大为批量恢复后续系统。

P0 实施保持了以下边界：

- 运行策略当前包含 50 个外部成员和 12 个引擎成员；P0-P8 均已进入同一现行清单，实际推进由能力画像、作用域和当前上下文决定。
- 当前九个主叙事可写系统为 `character-base`、`lifespan`、`health`、`luck`、`morality`、`growth-system`、`reputation`、`npc-system`、`relationship-system`，统一受七字段中文“系统指令”契约校验。
- P3-P5 没有新增第二套 AI 成功协议；地理、资源、成就和生命周期由本地规则或事件输入推进，成长、声望和健康纳入现行系统指令。
- P3-P5 状态只通过各 owning system 的封闭 `schemaVersion: 1` 快照进入预览回滚和存档，不读取已淘汰所有者载荷；死亡缺少专属历史事件或仍为 pending 时禁止正式持久化。

## 11. P0—P8 各阶段实际执行系统

本节使用中文名称说明接下来会做什么。内部系统 ID 只作为迁移与开发定位信息保留，不再承担阅读时的主名称；其中需要合并或内部化的旧 ID 不会继续成为最终独立系统，最终目标归属以第 13 节为准。每个阶段只处理表内范围，并继续运行已经通过前序阶段验收的基础能力。

### 11.1 P0 世界上下文基础

P0 是已经完成的第一阶段。它没有增加经济、政治、NPC 或修炼玩法，而是先让一个存档能够安全拥有多个世界、星球和场景，并在它们之间切换。

| 中文系统名称 | 内部系统 ID | 系统的详细作用 | P0 具体执行内容 | 叙事 AI 关系 |
|---|---|---|---|---|
| 世界上下文注册表 | `world-context-registry` | 保存世界、宇宙、位面、星球、区域和场景的层级关系，为每个上下文及其中实体提供全局唯一身份，并管理创建、开放、休眠和关闭状态。 | 建立存档级上下文目录、父子关系、当前上下文引用和全局实体命名空间。 | 只读；AI 可以描述世界事实，但不能直接创建、删除或切换运行上下文。 |
| 上下文能力画像 | `contextual-capability-profile` | 判断一个世界是否具有生命、地理、NPC、经济、政治、科技、超凡等能力，决定哪些模拟系统适用于该世界。 | 从世界配置和已确认事实派生能力组合，为后续阶段提供统一启停依据。 | 只读；AI 可提交世界语义候选，最终能力由本地规则确认。 |
| 空间关系图 | `spatial-graph` | 用统一图结构保存地点层级、邻接、距离、出口、可达性和实体当前位置，可表达城市、星球、位面、飞船或抽象场景。 | 建立每个上下文的空间根节点、位置引用和跨上下文出口，不生成具体地图画面。 | 事件输入；AI 只能提出空间事实，必须经过节点和可达性校验。 |
| 上下文切换系统 | `context-transition` | 负责角色在场景、地区、星球或世界之间移动，统一检查出口、资格、携带物、同行者、时间换算和到达结果。 | 建立切换预检、原子迁移、失败回滚、离开事件和到达事件流程。 | 提议；叙事可以提出移动结果，但本地验证通过后才真正切换。 |
| 模拟范围策略 | `simulation-scope-policy` | 决定哪个世界完整运行、哪个世界只做后台聚合、哪个世界休眠冻结、哪个世界完全关闭，避免访问世界越多性能越差。 | 建立当前完整模拟、后台聚合、休眠和关闭四种调度规则。 | 只读；AI 不能为了剧情方便唤醒或关闭世界。 |
| 世界初始化系统 | `world-init` | 负责创建新世界实例，包括世界基础事实、能力画像、空间根、当地历法和初始实体，而不是只创建唯一世界。 | 把旧单世界中央工厂重写为“每次创建一个世界上下文”的受控工厂。 | 提议；AI 可提供世界语义数据，完整结构、ID 和合法性由本地生成与校验。 |
| 世界实体系统 | `world-entity` | 保存具名国家、派系、家族、聚落和商路，使这些世界级实体能够被剧情、关系、经济和政治系统引用。 | 将现有单一实体集合改为按世界上下文分区，并允许跨世界实体保留全局身份。 | 事件输入；实体变化必须经过实体系统自己的创建和更新契约。 |
| 时间系统 | `time` | 推进规范回合时间，唯一负责本轮经过天数和累计天数，防止多个世界分别推进后出现重复年龄或冲突时间线。 | 保持一个全局时间权威，增加当地历法、显示方式和时间倍率的换算接口。 | 只读；AI 不得修改回合、日期或累计时间。 |
| 叙事编排系统 | `orchestrator` | 按固定顺序收集系统状态、组装提示词、调用叙事 AI、处理分支和因果、预检状态变更、原子提交并生成快照。 | 在每轮流程中加入当前上下文、运行系统组合和后台世界调度，但继续保持唯一提交所有者。 | 只读；AI 返回结果由编排系统接收，但 AI 不能控制执行顺序。 |
| 叙事协议解析系统 | `narrative-parser` | 解析“正文、摘要、可选数据、结束”中文协议，把 AI 输出转为可以严格校验的内部结果。 | 为未来上下文、目标对象和统一系统指令预留严格翻译边界，不在 P0 自动开放新可写系统。 | 消费 AI 输出；不直接写入任何模拟状态。 |
| 摘要压缩系统 | `summary-compressor` | 把长期故事压缩为有覆盖证明的多层摘要，同时保留原文或低层叶子，避免长局失忆和剧情事实丢失。 | 为摘要增加发生世界、时间范围和覆盖区间，使跨世界后仍能找到原始故事。 | AI 可参与语义压缩；无完整覆盖证明时不得提交摘要节点。 |
| 长期记忆引擎 | `memory-engine` | 从剧情和各系统状态中提取人物关系、状态、财富、地点与事件，形成可持续使用的结构化长期记忆。 | 让记忆记录全局实体 ID、发生世界、当地身份和跨世界可见范围。 | 消费叙事结果；记忆写入由记忆引擎校验和拥有。 |
| 子系统相关性系统 | `subsystem-relevance` | 判断本轮哪些系统与玩家当前处境相关，只把必要状态发送给 AI，减少无关信息和无关系统执行。 | 先按当前世界和能力画像筛选，再计算叙事相关性，禁止唤醒无关休眠世界。 | 只读；AI 不决定系统是否进入本轮运行。 |
| 记忆生命周期系统 | `memory-lifecycle` | 管理记忆的重要性、层级、事件闭合和提示词注入，决定哪些事实以原文、摘要或核心记忆形式出现。 | 区分全局记忆与当地记忆，并保护跨世界身份、因果和未完成事项。 | 只读使用 AI 语义结果；不允许 AI 删除记忆。 |
| 可解释遗忘系统 | `memory-forgetting` | 根据重要性、重复、因果完成状态和保护标记进行可审计遗忘或压缩，不按固定容量直接删除剧情事实。 | 增加上下文范围；世界休眠时只允许冻结或有覆盖证明的压缩。 | 只读；AI 可提供语义评价，但最终遗忘决策必须可追踪。 |
| 延迟因果系统 | `causal-delay` | 保存本轮已经成立但要在未来兑现的承诺、后果或事件，到期后交给叙事处理，只有成功提交后才确认兑现。 | 给每条延迟因果增加全局、当地或旅行中的作用域，并明确休眠世界如何推进。 | 事件输入；AI 可以登记新延迟事项，不能直接把未兑现事项标成完成。 |
| 剧情结构系统 | `plot-structure` | 管理剧情阶段、张力和结构信号，使每轮故事具有推进、转折和收束，而不是完全随机生成。 | 区分全局主线和当地支线的结构视图，但继续由一个叙事编排器统一使用。 | 只读约束 AI 写作；不拥有玩家行动或模拟状态。 |
| 伏笔系统 | `foreshadowing` | 保存伏笔的建立、触发条件、相关实体、解决状态和回收提示，防止跨世界后在错误地点无条件触发。 | 为伏笔增加世界、实体和可触发范围，并与切换和休眠规则连接。 | 事件输入；AI 可建立或回收伏笔，系统校验作用域和状态。 |
| 核心记忆系统 | `core-memory` | 保存不能遗忘的关键人生事件、核心关系和重要伏笔，为长局叙事提供稳定身份与情感连续性。 | 使用全局实体 ID 保存关键记忆，同时保留原发生世界和当地身份。 | 只读向 AI 提供上下文；新增核心记忆必须有已接受事件依据。 |
| 角色基础系统 | `character-base` | 保存体魄、心智、悟性和魅力四项基础属性，并聚合命格、伤病、衰减等其他系统提供的修正。 | 保持主角身份全局连续，把世界、种族和状态影响改为带来源的上下文修正。 | 受校验写入；只允许当前字段契约中的四项属性变化。 |
| 命格系统 | `destiny-pattern` | 管理命格候选、已选命格、命格效果、运行进度和生成失败状态，为角色提供跨局或长期叙事规则。 | 区分全局命格身份与只在特定世界生效的当地效果。 | 创建阶段可由 AI 生成候选；主叙事当前只读。 |
| 寿命系统 | `lifespan` | 保存最大寿命、突破和寿命变化，不负责当前年龄、时间推进或死亡叙事。 | 将角色寿命状态与当地种族规则、世界规则和时间倍率连接。 | 受校验写入；AI 只能提交明确的最大寿命或寿命增减。 |
| 气运系统 | `luck` | 保存角色气运并为疾病、死亡、事件权重和衰老提供修正，但不直接生成事件。 | 区分角色基础气运与当前世界的当地气运规则，防止跨世界公式互相污染。 | 受校验写入；只允许合法范围内的气运状态变化。 |
| 道德系统 | `morality` | 保存角色行为的道德变化，为剧情留下连续记录，但不再用关键词自动判断善恶。 | 暂时保留全局道德值，同时为以后拆分“个人行为记录”和“当地文化评价”预留边界。 | 受校验写入；AI 只能在重大行为时提交道德增减。 |

P0 完成后的直接结果：现有单世界玩法继续可用；同一存档可以安全创建第二个世界或星球，角色可以通过受控流程切换，离开的世界能够后台运行或休眠，记忆、因果、时间和实体不会互相串世界。P0 不恢复旧世界地图，不加入 NPC、经济、政治或超凡玩法。

### 11.2 P1 历史与因果

P1 让世界发生的事情成为长期、可追踪的事实。后续 NPC、政治、经济和灾害都必须以事件账本和因果关系为依据。

| 中文系统或组件名称 | 内部标识 | 系统的详细作用 | P1 具体执行内容 | 叙事 AI 关系 |
|---|---|---|---|---|
| 历史事件账本 | `historical-event-ledger` | 统一保存已经发生、正在进行、被阻止、已解决或已作废的世界事件，以及参与实体、发生地点、原因、结果和证据。 | 建立所有世界共用但按作用域分区的事件真源，为其他模拟系统提供历史依据。 | 登记为 `event-input`；AI 只提供已通过统一协议的语义结果，本地分配 ID、验证作用域并原子提交。 |
| 事件候选提供器 | `EventCandidateProvider`（内部组件） | 接收显式候选，记录 `available/accepted/rejected/expired` 生命周期和通用能力要求；接受前不视为已发生事实。 | 取代旧 `event-pool` 的独立系统、题材预设和事实 Store，由账本拥有候选审计。 | AI 或规则只能提供语义候选；本地对每个目标上下文校验能力并决定接受、拒绝或过期。 |
| 因果图组件 | `CausalGraphComponent`（内部组件） | 在已经存在的事件之间建立原因、条件、阻止、解决或传播关系。 | 取代旧 `causal-simulation` 的正文正则、随机延迟和重复队列，因果边由账本统一保存。 | 不从正文猜测因果；端点、跨世界作用域和证据全部由本地预检。 |
| 延迟因果系统 | `causal-delay` | 管理玩家或剧情已经形成、但要在未来某个条件下兑现的具体承诺和后果。 | 接入历史事件账本；到期后生成待叙事事实，完整回合提交成功后才标记兑现。 | 受控事件输入；不能由 AI 提前宣布尚未满足条件的事项完成。 |
| 叙事编排系统 | `orchestrator` | 把到期事件、当前因果和相关历史装配进本轮叙事，并负责最终原子提交。 | 增加历史事件预检、消费者引用和跨系统快照/回滚顺序。 | 本地编排与提交所有者；不是 AI 可写系统，也不自造历史事实。 |
| 伏笔系统 | `foreshadowing` | 把伏笔与具体历史事件和因果条件连接，确认何时可以回收。 | 伏笔建立、触发和解决都留下对应事件证据。 | AI 可提议建立或回收，系统校验条件。 |
| 剧情结构系统 | `plot-structure` | 根据已经发生的历史和未解决因果调整剧情阶段与张力。 | 使用事件状态而不是正文关键词判断推进、转折和收束。 | 只读约束 AI 叙事结构。 |

P1 完成后的直接结果：玩家离开一个世界后，该世界发生过的战争、承诺、灾害、人物死亡或重大转折不会只存在于一段正文中；系统能够知道事情为什么发生、是否解决、会影响哪个世界以及什么时候继续兑现。
