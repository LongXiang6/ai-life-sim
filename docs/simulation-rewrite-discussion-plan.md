## 〇、背景

前期蓝图暴露了 28 项缺陷，根源在于以"年"为最小时间粒度的设计迫使各子系统分散处理时间缩放，导致了零循环、截断、概率紊乱、数据路径断裂等致命问题。

结论：**不应该在旧架构上修修补补。** 先清空模拟代码，再以"日"为最小整数粒度重写时间引擎，然后按优先级逐系统恢复。

## 二、时间引擎重写方案（全部已确认）

| 原则 | 说明 |
|------|------|
| ✅ 整数日 | 唯一最小粒度为"日"。所有时间计算用整数。 |
| ✅ 一年 365 天 | 固定不变。 |
| ✅ 一个月为真实分布 | 1月31天、2月28天、3月31天、4月30天、5月31天、6月30天、7月31天、8月31天、9月30天、10月31天、11月30天、12月31天。当前 MVP 固定 365 天，不实现闰年。 |
| ✅ 无需时辰/小时 | "日"就是最小单位，不再向下细分。 |
| ✅ 单一权威源 | TimeSystem 是唯一有权管理时间的模块。 |
| ✅ 叙事步长可切换 | 时间引擎底层最小单位仍是"日"；开局默认一次叙事推进 1 年，但玩家可切换为按日、按月、按季度、按年推进。 |
| ✅ 消除浮点数 | 不再出现 `1/365`、`0.00274` 等浮点数。 |
| ✅ 消除年累加器 | 不再需要 `_simYearAccumulator`、`consumeSimulationYears` 等。 |

TimeSystem 需要提供：

- `totalDays: number` —— 当前游戏总天数（整数）
- `dateToString(totalDays)` —— 日 → 年月日文本
- `getYear(totalDays)` / `getMonth(totalDays)` / `getDay(totalDays)`
- `getSeason(totalDays)` —— 当前季节（春 3-5月 / 夏 6-8月 / 秋 9-11月 / 冬 12-2月）
- `advance(days: number)` —— 推进指定天数
- `daysPassed: number` —— 本轮推进了多少天（供子系统读取）
- `timeStep` 换算能力 —— 日=1天，月=当前月份真实天数，季=连续3个真实月份天数之和，年=365天；叙事轮次只负责选择步长，子系统只接收换算后的整数天数。
- 切换 `timeStep` 只影响下一次叙事推进，不得修改当前 `round`、`daysPassed` 或 `totalDays`。

纪元时间线属于拓展功能，先清空转为注释，后续再执行。

## 三、MOD 架构升级

### 3.1 当前 MOD 结构

共 21 个 MOD。除 `mod-religion`、`mod-diplomacy`、`mod-fate-prophecy` 外，均有 `_internal/` 目录。

### 3.2 `_internal/` 目录

**作用：** MOD 公私有边界。

- `index.ts` —— 公共大门，只导出其他 MOD 可以安全引用的类型和函数
- `_internal/` —— 内部机房，放 MOD 自己的实现细节和生命周期逻辑
- 当前大部分 MOD 的 `_internal/control.ts` 为空占位（仅 `mod-engine` 有实际代码），目的是保持结构统一

**决策：** ✅ 保留现有 `_internal/` 结构。

### 3.3 抽象基类

**作用：** 像驾照考试机构一样，定义所有子系统必须遵守的统一方法签名和参数类型。

- `abstract` 方法标记了子系统必须实现的方法
- AI 新建子系统时只需看基类就知道要写什么、输入什么、返回什么
- 基类还提供共享工具方法（如值域限制），各子系统不需要重复实现

**决策：** ✅ 引入轻量抽象基类。

### 3.4 标准化方向

| 目标 | 做法 |
|------|------|
| 模板化 | 每个子系统遵守统一的方法签名模板 |
| 数据契约化 | 跨子系统通信走 foundation 层定义的类型接口 |
| AI 减少决策负担 | 抽象基类定义全部必实现方法 |
| 自检自动化 | manifest 自校验 |

**✅ foundation 层的跨域数据契约现在设计——这是 MOD 架构升级的第一步。**

## 四、页面流程（已确认）

```
启动页（新游戏 / 载入存档 / 设置 / 文档）
  └─ 新游戏
       ├─ 世界选择（列表 / 自定义入口）
       └─ 世界自定义（四个字段）
            力量体系 · 世界观本质 · 力量上限 · 空间形态
            文明阶段：注释掉，最后实现
            └─ 角色设定
                 名称 · 性别 · 种族 · 寿命 · 背景信息
                 ├─ 命格抽取 → 命格选取（完整保留）
                 ├─ 属性分配（保留）
                 └─ 身世总览（保留）
                      └─ 进入核心模拟界面
                           推进按钮（点不了或点击后无反应）
                           结算界面（空壳 → 返回启动页）
```

清空后目标：能启动 → 能创建世界和角色 → 模拟界面打开 → **零红错、零崩溃**。若为迁移期临时保留抛错桩，最终 MVP 正常玩法路径不得持续触发这些错误日志。

## 五附、执行顺序 v2 —— 五段式（2026-07-04 追加决策，取代上表六梯队的固定顺序）
