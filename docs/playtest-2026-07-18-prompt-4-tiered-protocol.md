## 1. 生效契约

1. 固定 System Prompt 使用纯文本组件顺序，不再把规则序列化为 JSON 外壳。
2. 上半部分只保留基础写作与事实约束；下半部分只有一个带 `⟪说明⟫` 的完整标准示例。
3. 正式输出顺序为 `⟦正文⟧ -> ⟦摘要⟧ -> 可选 ⟦数据⟧ -> ⟦结束⟧`，标记必须独占一行。
4. 普通轮以完整三段正文、摘要和结束标记为最低成功。数据缺失或非法时保留正文与摘要，整包拒绝数据，不重写故事。
5. 当前命运意图和玩家强制命运分支保留条件必填门禁；缺少相应完整数据时进行一次针对性修复。
6. 数据字段无内容时省略，禁止空数组、空对象、空字符串和 `null`；省略不等于确认无变化。
7. 摘要始终进入 digest 账本；只有 AI 有效提交的事件才携带权重与实体，本地不伪造默认语义。
8. 流式 UI 只接收正文增量，不显示摘要、数据、协议标记或修复内容。

## 2. 确定性结果

| Case | 结果 |
|---|---|
| 带注释完整标准示例经字符串感知扫描、JSON 解析和中文 Schema 转译 | 通过 |
| 普通轮仅正文、摘要和结束标记 | 通过，不生成结构化写入 |
| 普通轮数据区为空数组、未知字段或畸形 JSON | 正文与摘要通过，数据整包拒绝 |
| 当前命运意图缺少完整语义核心或意图判定 | 不通过，进入一次修复 |
| 玩家强制分支缺少高重要度、不可逆语义与分支选项 | 不通过，进入一次修复 |
| 英文旧协议或旧 `[正文]/[回合数据]` 标签 | 不进入成功路径 |
| 混合合法/非法状态变更 | 整包拒绝并保持正文、摘要完整 |
| 摘要存在但没有带权事件 | digest 正常记录，不伪造权重或实体 |
| 流式原始输出包含摘要和数据 | UI 只获得正文增量 |

## 3. Prompt 密度

- Prompt 3.0 固定 System 快照：约 `2943` 字符。
- Prompt 4.0 最终固定 System 快照：约 `2809` 字符。
- 在新增独立摘要、全部字段示例、字段旁说明、两类“类型”消歧和空值防照抄说明后，固定 Prompt 仍减少约 `4.6%`。
- 删除了 JSON 规则外壳、第二份文风示例、重复字段清单和常驻空数组指令。

## 4. 结构化提交边界

- 摘要不属于可选数据包；即使数据非法也必须保留并进入压缩账本。
- 数据包存在时，未知字段、非法系统、非法枚举或任一状态写入失败都会使数据整包失效。
- 本地只消费明确提交且校验成功的字段，不从正文补属性、关系、权重、伏笔、因果或意图结果。
- 无有效语义核心时，情节系统使用可识别的生活层中立降级；到期因果和待回收伏笔保持待处理。

## 5. DeepSeek 官方模型真实调用

固定条件：官方 `deepseek` Provider、`deepseek-v4-flash`、Prompt `4.0.0`、潮汐群岛场景、三层中文消息、服务端凭据、最多一次协议修复且不写游戏存档。此前在用户明确测试路由前执行的 `managed` / `grok-4.5` 调用只保留为托管通道历史，不计入本节最终本地验收。

| Case | 结果 |
|---|---|
| 空值误填切片 | `9193ms`；三段正文与摘要首稿通过；模型照抄了零变化、空数组和 `命运分支:false`，数据整包拒绝，正文与摘要保持完整且不重写 |
| 提示词修正 | 明确数据区不是字段清单，零变化、无项列表和无分支必须省略；解析器仍严格整包判定，不删除非法项、不部分提交 |
| 协议波动切片 | `8814ms`；模型返回四段正文但漏掉摘要与结束标记，证明 DeepSeek 首稿协议率并非 100%；该结果应进入既有一次格式修复，不能宣称成功 |
| 生产链最终复测 | `9964ms`；首稿直接返回完整三段正文、摘要、结束标记并省略无内容数据区；未触发修复；正文约 `667` 字，只产生软提示而不重写 |

最终复测正文包含黄昏修船坞、守卫封锁、登船解缆、底舱暗记、父亲遗留图纸和追船逼近。按玩家体验量表检查：

| 维度 | 结果 |
|---|---|
| 第二人称代入 | 通过；全程以“你”的感知和行动推进 |
| 现场与人物声音 | 通过；有船坞、跳板、缆绳、底舱烛火、林舟对话和追船桅灯 |
| 行动、阻力、后果 | 通过；登船、解缆、调整吃水、穿过暗流和北岸追击形成连续因果 |
| 娱乐性与继续游玩意愿 | 通过；父亲暗记、烧焦图纸、废弃灯塔仍亮和追船逼近形成明确悬念 |
| 字数策略 | 通过；正文略高于参考区间仍保留完整原文，没有因字数触发重写 |

本节只验证模型输出、协议解析和质量门禁，不向运行存档提交状态；命运意图和状态写入仍由 orchestrator 的既有条件门禁、预检与回滚负责。

## 6. 浏览器证据边界

- `npm run test:creation-first-narrative:browser` 正确报告当前项目未安装 Playwright，因此没有把不可用夹具描述为浏览器通过。
- 应用内浏览器中的既有 `localhost:3000/welcome` 可正常恢复并显示现有存档；没有推进、删除或覆盖玩家存档。
- 为隔离存档尝试的新来源会停留在 OPFS 恢复等待态，不作为应用主路径失败，也不以该环境替代真实创建流程结论。
- 创建到首轮的零依赖状态/调用契约继续由 `npm run test:creation-first-narrative` 验证；完整可见终态浏览器证据需在项目已有 Playwright 运行时或安全的空存档浏览器环境中补充。

## 7. 当前结论

确定性协议、DeepSeek 官方模型的生产链首稿和叙事质量已达到本次用户确认的目标。真实调用证明可选数据失败不会拖正文重写，最终生产链样本能够在首稿省略无内容数据并完成正文、摘要和结束标记；同时保留一次协议波动记录，不把单样本结果描述为 100% 首稿率。当前仍不把缺少隔离 Playwright 环境的结果宣称为完整浏览器端到端全绿。后续本地实测只使用 DeepSeek 官方 Provider，并继续以协议通过率、首次响应延迟、文笔、代入感、因果推进和继续游玩意愿为主，速度或 Token 改善不得替代叙事质量。
