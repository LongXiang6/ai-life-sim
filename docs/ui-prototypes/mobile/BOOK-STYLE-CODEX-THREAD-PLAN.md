## 1. 这轮真正要解决的问题

这轮不是再做一套暖白、冷蓝或深色主题，而是先确定一套可以贯穿整个产品的排版语言：让界面像一本正在被阅读、填写和推进的命书，同时仍然是一套清楚、可操作的移动端产品。

欢迎页可复用的是以下语法，不是它的具体颜色：

- 宋体承担叙事、章名和关键动作，无衬线体承担页码、状态、注释和参数。
- 文字本身就是主要入口，按钮不依赖大色块、胶囊和投影才成立。
- 通过章标、书脊、页码、路径、脚注、边注和细线建立层级。
- 留白用于控制阅读节奏，重点来自字号、字重、位置与行长，而不是卡片底色。
- 页面首先像一个完整的阅读版面，其次才出现控件集合。

欢迎页右侧曲线是欢迎页的专属构图，不要求复制到其他页面。其他界面要继承它的排版逻辑，而不是复制其装饰图形。

## 2. 共同边界

### 2.1 必须保留

- 每个页面现有的字段、操作、条件、状态含义和前后流程。
- 命格抽取的 P1 云紫宽环与十二命印抽取机制。
- 神话传承 U1、U2、U3 三套候选机制；本轮不得替用户淘汰其中任何一套。
- 375px、390px 和 768px 下的信息完整性、可操作性和语义一致性。
- 所有旧轮次与现有 `final.html`。新任务只能新增候选，不能覆盖最终稿。

### 2.2 可以竞争

- 内容先后顺序、分区方式、主次关系、导航位置和操作收束方式。
- 卡片是否继续存在，以及哪些信息应改为正文、目录、边注、脚注、章末动作或书签。
- 单页、对开、手稿、长卷等版式如何随页面任务变化。
- 页面在保持同一视觉语法的前提下，形成自己的结构，而不是十页套同一个模板。

“以现有布局为起点”不等于“锁死现有布局”。候选必须说明每一处结构变化解决了什么问题；不得为了显得不同而删除信息或制造无意义的装饰。

### 2.3 本轮暂不评判

- 最终品牌色、深浅主题、渐变、材质和大面积背景。
- 最终字体授权与跨平台字体文件。
- 真实应用组件改造。

候选先使用克制的中性色和最多一个语义强调色，颜色只服务状态辨识，不作为方案卖点。

## 4. 第一阶段：四条母版方向并行赛

四个线程使用同一组代表页面：世界选择、命格抽取、核心模拟、设置。它们分别覆盖目录型选择、仪式型交互、长文本阅读和高密度表单，只有四类页面都成立，方向才有资格进入下一轮。

### B01 · 章节书页 / Chapter Folio

**设计命题**：每个页面是一章，用户通过章名、节标题、页码和章末动作完成任务。界面应像被精心编排的单页书册，而不是卡片面板。

**重点探索**：

- 主标题、导语、正文、参数、注释和动作的稳定文字层级。
- 以章、节、页码、细线和留白替代大多数容器。
- 主操作如何成为“章末下一页”，次操作如何成为脚注或页尾目录。
- 高密度设置如何仍然像书页，而不牺牲扫描效率。

**任务目录**：`book-style-tournament/b01-chapter-folio/`

### B02 · 对开书册 / Facing Spread

**设计命题**：把叙事或解释放在一侧，把选择、状态或操作放在另一侧，形成“阅读页 + 行动页”的关系。768px 可显式对开，375/390px 应转换为连续的正反页，而不是压成两列。

**重点探索**：

- 信息与操作如何形成互相解释的两页关系。
- 移动端从“对开”降级为“先读后做”时，阅读顺序是否自然。
- 页面切换、展开和选择能否被表达为翻页、书签或换页，而不依赖拟真翻页特效。
- 核心模拟的正文与 HUD/状态如何互不争抢。

**任务目录**：`book-style-tournament/b02-facing-spread/`

### B03 · 批注手稿 / Marginalia

**设计命题**：主内容像手稿正文，规则、状态、数值、解释和次级操作以边注、脚注、夹注出现。重点不是仿旧纸，而是建立正文与注释的双层阅读关系。

**重点探索**：

- 主任务始终占据视觉中心，辅助信息退到边注但仍可快速扫描。
- 表单标签、当前值、错误提示和说明如何成为自然批注。
- 选中、锁定、消耗、风险等状态如何不用大面积底色也能清楚表达。
- 375px 下边注如何内联或折入脚注，不造成拥挤和横向滚动。

**任务目录**：`book-style-tournament/b03-marginalia/`

### B04 · 章回长卷 / Serial Scroll

**设计命题**：页面是一段持续展开的章回或长卷，通过回目、段落、纪年、分隔符和卷末动作组织流程，适合核心模拟，也必须证明能承载选择和设置。

**重点探索**：

- 连续滚动中的章节定位、进度感和返回路径。
- 重复条目如何像谱牒、年表或条目正文，而不是卡片信息流。
- 长文本、动态状态和操作控件如何在同一阅读轴上出现。
- 固定底栏是否必要；若保留，如何不破坏长卷沉浸感。

**任务目录**：`book-style-tournament/b04-serial-scroll/`

## 5. 第一阶段候选的共同验收

每个 B01–B04 线程都必须：

1. 从四个对应 `final.html` 逐项建立内容与交互清单，不得凭截图猜字段。
2. 四页使用同一套排版语法，但不能只是换标题后复用同一布局。
3. 提供可点击的主要交互、选中态、展开态、禁用态或设置切换；静态海报不算完成。
4. 在 `README.md` 写清设计命题、排版规则、页面差异和主动放弃的做法。
5. 在 `evaluation.md` 按本文件评分表自评，并明确最弱的一页与原因。
6. 用浏览器检查 375px、390px、768px，无横向溢出、无文字遮挡、无控制台错误。
7. 运行 `npm run check:ui`、`npm run gate-check:quick` 和 `git diff --check`；若存在无关基线失败，记录差异，不得宣称全绿。

第一阶段评分：

| 维度 | 权重 | 判断问题 |
|---|---:|---|
| 与欢迎页排版语言同源 | 25% | 不看颜色，仍能认出是同一产品吗？ |
| 文字层级与书本沉浸感 | 25% | 文字、章标、页码、边注与留白是否真正主导界面？ |
| 工作流清晰度 | 20% | 用户是否清楚下一步、当前状态和可操作位置？ |
| 跨页面一致性 | 15% | 四种任务场景能否共用规则又保留页面个性？ |
| 移动交互与响应式 | 10% | 375/390/768 是否都完整、紧凑且可操作？ |
| 超越“只换主题” | 5% | 是否产生了可解释的排版与信息组织变化？ |

颜色偏好不得计入评分。B01–B04 完成后，由 B05 把四个代表界面分别转成四选一同屏评审；用户按页面选择、按页面指定融合，或只要求某个弱页再迭代。没有完成逐页决定，不进入第二阶段。

B10 不得把某个代表页的完整布局强行复制给其他页面。规范应定义共用语法、页面差异与可复用部件，不定义十张相同模板。

## 8. 第二阶段：界面 02–11 独立三选一

第二阶段的每个页面线程读取 B10 规范，但可以重排自己的页面。每个线程必须给出三个边界清楚的候选：

- **A · 保守转译**：尽量沿用当前信息架构，把卡片/控件翻译成胜出排版语言。
- **B · 编辑重排**：主动调整章节、阅读顺序和操作收束，追求最清楚的书页结构。
- **C · 沉浸实验**：针对该页任务使用更强的书本交互，但必须保留全部机制并可实际操作。

这三个标签是风险梯度，不是固定布局。线程可以认为 A、B 或 C 中任何一个更优秀，并给出临时推荐；最终晋级只由用户决定。
