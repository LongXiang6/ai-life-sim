本轮边界

目标
迭代创建流程属性分配（06）界面：沿用命格抽取 / 命格选取已定版的暖纸墨语言（.page/.paper/.runningHead 框架、米纸底、卡片语言），仅在上层布局分向——候选 A 预算置顶（基础点数吸顶常驻，四项属性列表为主体）；候选 B 属性卡片（预算卡片 + 每项属性独立卡片）；候选 C 运行时结构（忠实照抄运行时三段布局：基础点数 → 四项基础属性 → 重置/平均分配）。结构与数值口径全部照抄运行时 attribute-alloc 页面。
保持不变
业务契约：runningHead（06 / 08）、标题「属性分配」+ 副句「塑造这段人生的先天起点。」、基础点数（15 点预算，命格加成不占预算，0 是普通人基准）、四项基础属性（体魄 💪 / 心智 🧠 / 悟性 ✨ / 魅力 💫，步进器与 15 格倾向轴）、重置与平均分配、底部返回（返回命格选择）与确认（07 确认属性 / 尚余 X 点 · 下一步核对命运）、未使用点数对话框（继续分配 / 确认并继续）。运行时 AttributeAlloc.module.css 无动画，候选不加动画。候选不含 localStorage/sessionStorage/fetch。
比较维度
布局直觉（预算与属性的主次关系、滚动时剩余点数是否始终可见）、操作效率（分配 15 点最短路径）、数值可读性（基础值 / 有效值 / 命格加成的层级）、精简协调性（与命格抽取 / 命格选取定版语言的连贯统一）。

本轮决策

已选择 C
入选
候选 C（运行时结构）。用户确认「C」。要点：忠实照抄运行时三段布局（基础点数 → 四项基础属性 → 重置/平均分配），仅替换为暖纸墨语言；档位语义照抄 attr-tiers.ts。
淘汰
候选 A（预算置顶）：预算吸顶条浮于滚动正文之上，与标题/内容形成双层级视觉割裂，先不采纳；候选 B（属性卡片）：预算卡 + 四属性卡共五卡垂直堆叠，同屏信息密度低于列表，滚动路径最长，先不采纳。
下一轮继承
以候选 C（运行时结构）为基线开始第二轮迭代；候选不含任何运行时状态与持久化。
