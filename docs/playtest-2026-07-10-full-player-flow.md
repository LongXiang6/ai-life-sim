## 第二阶段重点测试：时间推进、叙事质量、沉浸式 UI

### 目标口径

1. 月推进使用自然月序列：例如 `2001年1月 -> 2001年2月`；季节由月份推导，1 月属于冬季，不应出现“春季一月”。
2. 季推进表示从当前日期连续推进 3 个真实月份；叙事应体现阶段变化和一个关键节点，而不是三个月流水账。
3. 年推进表示推进完整年份；叙事应有年度跨度和阶段性后果。
4. 推进交互应位于最新故事正文尾部，作为纯文字沉浸式热区，随故事滚动；不应表现为独立固定底栏或胶囊按钮。

### 静态对照发现

1. `TimeSystem` 已采用 365 天真实公历。月推进按实际月天数前进；季推进从当前月连续推进 3 个月；年推进到下一年 1 月 1 日。
2. 月档标题格式当前为“纪年 · X月”，季档为“纪年 · 春/夏/秋/冬”，日档包含季节、月份与日期。
3. 叙事提示已区分月/季/年：月档要求本月代表事件，季档要求季节变化与关键节点，年档使用年度跨度。
4. UI 问题 P1：当前 `NarrativeTimeline` 把推进区放在滚动容器外的 `advanceDock`，形成固定底栏；废弃项目把推进区放在事件列表之后，真正属于故事尾部。需要浏览器确认后修复。
### 浏览器实测发现

1. UI P1 确认：桌面 1280x720 下，推进文字固定占据视口底部 `y=662-720`；故事滚动容器截止于 `y=662`。推进区不是故事正文尾部，而是滚动区外固定底栏。
2. 时间/叙事 P1：现有 2001 年叙事写“春雨连绵”，但切换月档后当前日期显示 `2001年 · 正月`，真实公历 1 月应属冬季，叙事与日历不一致。
3. 时间 P0：从 `2001年 · 正月 / 1岁` 选择月推进一次，生成中的下一条仍显示 `2001年 · 正月`，角色年龄却直接变为 `2岁`。说明年龄仍受旧的回合/年制逻辑驱动，月档没有按真实天数计算年龄；月/季推进当前不可视为正确可用。
4. 时间 P0 根因修正：第一次月推进完成后实际跳到 `2002年 · 正月 / 2岁`。第二次月推进才正确到 `2002年 · 杏月 / 2岁`。说明月引擎本身按月推进正常，但切换档位时错误消费了切换前按年生成的旧预生成结果；时间档切换的预生成失效/校验存在缺口。
5. 时间显示 P1：当前现代世界月份显示为“正月、杏月”等传统月名。用户期望直观自然月 `1月、2月`，现代世界不应默认使用诗意月别称。
6. 叙事质量 P1：2002 年正月与杏月连续两条都围绕“扶书架站立、摔倒、走向母亲、说出单字”展开，场景和动作高度重复；月档虽有季节环境变化，但缺乏对上一月已发生事件的去重与发展承接。
### 时间档切换结论修正

- 前述“切月消费旧年档预生成”的判断经调用链复核后撤销。`OrchestratorSystem.advanceTimeForCurrentStep()` 会在粗粒度切到细粒度时调用 `alignToNextPeriod`：2001 年年叙事已经覆盖完整 2001 年，因此切月后的首个合法未叙事节点是 `2002年1月`，不能回到 2001 年 2 月重写已覆盖时间。
- 下一次月推进正确到 `2002年2月`，年龄保持 2 岁，证明真实月推进与年龄计算正常。
- 当前问题是 UI 只在菜单底部用一段小字解释“进入未叙事周期”，玩家点击后仍容易误判为跳年。需要把月份改成数字月，并在时间档切换后的第一次推进中保持明确、一致的标题语义。
### 月份与季节显示口径修正

- 用户明确期望月档完整显示“年份 + 季节 + 数字月份”，例如 `2001年 · 春季 · 1月`，而不是仅显示月份。
- 项目当前历法权威定义为 1-3 月春季、4-6 月夏季、7-9 月秋季、10-12 月冬季。前文“1 月应属冬季”的判断不符合项目历法，现撤销。
- 格式调整为：月档 `纪年 · X季 · N月`，季档 `纪年 · X季`，日档 `纪年 · X季 · N月N日`。
7. 季推进：从 2002 年 2 月连续推进三个月，最终显示 `2002年 · 夏季 / 2岁`，时间语义正确。
8. 季叙事质量仍失败：夏季条目再次重复“扶墙走向母亲、说出单字、旧录音机/磁带”，与前两个月核心动作高度相似。已将“最近两轮主要场景、动作、对话结论、成长里程碑禁止换皮复演”提升为主叙事 L0 硬约束。
9. 年推进：最终正确到 `2003年 / 3岁`，引入连锁书店竞争和是否上幼儿园的分支，剧情方向有推进。
10. 叙事 P0：2003 年同一回合内，三段正文出现两套近乎同义的重复版本，共 6 段，然后才显示分支。违反“正文必须且只分三段”，需定位草稿/终稿拼接或解析重复。
